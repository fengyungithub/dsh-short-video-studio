# 48fps 补帧 A/B 质量检查（RIFE ×2）

> 日期：2026-10-27 ｜ 环境：ComfyUI 0.42.1 + `FrameInterpolate` + `rife_v4.25.safetensors`（A800 80GB）
> 上游设计：[`../fps-interpolation.md`](../fps-interpolation.md)、[`integration.md`](integration.md)
> 产物（gitignore，本地）：`e2e-out/ab-48fps/`、`e2e-out/fps-test/`

## 0. 结论速览

| 片段 | 类型 | 48fps 结论 | 关键证据 |
|---|---|---|---|
| **S1** | 快动作 / 大幅运动（260 帧 / 10.8s） | **可用** | 中间帧 PSNR 32–36 dB，肉眼无双影；保留帧与源一致（41–42 dB） |
| **S2** | 慢镜 / 人像（124 帧 / 5.2s） | **可用（最干净）** | 中间帧 PSNR 39–41 dB，几乎无感 |
| **S3** | **含硬切**（1.9s → 2.1s 场景切换） | **不可用** | 切点处出现交叉淡化鬼影帧：中间帧 PSNR **13.9 dB**、meanabs **29.4** |
| **S4** | **烧录字幕**（144 帧 / 6.0s） | **有条件可用** | 字幕仍可读，但中间帧文字边缘变软（PSNR 32.8–34.9）；小字/密集字风险高 |

**一句话**：**逐镜补 48fps 可用**（镜头内无硬切、无密集小字）；**含硬切/转场的镜头不可用**；**成片绝不能补**。保留帧不会被重画（PSNR 41–42 dB 的差异只来自重编码，dev 图只在边缘有细线）。

## 1. 方法

1. 取 4 个 768×1344、24fps 的片段（S1/S2 来自 `canvas/session-002884e3…/`；S3 取一段**内部含硬切**的片段；S4 由 S2 素材用 ffmpeg 烧上两行字幕，模拟成片字幕）。
2. 每个片段跑 `node scripts/experiment-48fps.mjs <src> 2`（RIFE ×2 → 48fps；该脚本不含 D2 补齐，产物 247f/5.146s，比源短 20.8ms——这是补帧链路本身的帧数规则，正式管线由 `video_interpolate` 的 D2 补齐修掉）。
3. 用 ffmpeg 在相同时间点抽帧：源帧 `src`、48fps 的**保留帧**（偶数帧，应≈源）、48fps 的**中间帧**（奇数帧，模型生成）。
4. 计算指标（`e2e-out/ab-48fps/metrics.json`）：
   - `psnr_src_vs_retained`：48fps 保留帧 vs 源帧（应接近无损，差异来自重编码）；
   - `psnr_mid_vs_src_n` / `…_n1`：中间帧 vs 前后两张源帧；
   - `mid_vs_midpoint_meanabs`：中间帧与「两源帧线性中点」的平均绝对差（越小越像时间中点）。
5. 人工看 `side`（左右对比）/`triple`（源·保留·中间）/`dev`（差异图）/`detail`（1:1 裁切）四类图。

## 2. 指标（`metrics.json` 摘要）

| 片段 | t | 保留帧 PSNR | 中间帧 PSNR | 中间帧 vs 时域中点 meanabs |
|---|---|---|---|---|
| S1 | 1.42s | 41.26 | 32.24 | 2.11 |
| S1 | 5.00s | 41.82 | 34.81 | 1.72 |
| S1 | 8.75s | 42.23 | 36.30 | 1.49 |
| S2 | 1.33s | 42.25 | 39.04 | 1.39 |
| S2 | 2.83s | 42.46 | 41.46 | 1.26 |
| S3 | 2.08s | 41.78 | **13.90** | **29.40** |
| S3 | 3.10s | 41.37 | 40.47 | 1.62 |
| S4 | 1.50s | 41.39 | 32.79 | 2.08 |
| S4 | 4.00s | 41.86 | 34.90 | 1.70 |

读法：**保留帧 ≈ 源**（41–42 dB 已是 H.264 重编码的量级）；**中间帧 32–41 dB** 属于自然插值；**13.9 dB 就是崩了**（两场混合）。

## 3. 逐片段结论

### S1 · 快动作 —— 可用

- `triple` 三格（源 / 保留 / 中间）几乎一致；`dev` 差异图只剩人物轮廓与衣物边缘细线（重编码残差），**没有整块拖影**。
- 中间帧 32–36 dB：运动越大越低，但肉眼没有双影/重影。
- 结论：**运动镜头可以补 48fps**，观感更顺且不糊。

### S2 · 慢镜人像 —— 可用（最干净）

- 中间帧 39–41 dB，`dev` 图几乎全黑；头发、五官边缘无拉丝。
- 结论：慢镜补帧最安全。

### S3 · 含硬切 —— 不可用（恰好证明「成片不能补」）

- 源片 1.9s 还是人物特写、2.1s 已经切到山水楼阁；**切点被插值成一张交叉淡化帧**（人物半透明叠在山水上）。
- 中间帧 PSNR 13.9 dB / meanabs 29.4，是全部样本里唯一的灾难值。
- 这正是文档 §2.6「硬切鬼影」的实证：模型没有场景检测，两场之间会生成形变帧。
- 结论：**逐镜补**（镜头内部不含切点）；成片、含转场的镜头、拼接产物一律不补。

### S4 · 烧录字幕 —— 有条件可用

- 字幕「我等了你三年 / 48FPS 补帧字幕测试 0123」在源帧与保留帧都锐利；**中间帧文字边缘变软**（`detail` 1:1 裁切可见，PSNR 32.8–34.9）。
- 文字仍可读，但字号越小、笔画越密，软化越明显；48fps 下这种软化是逐帧交替的，可能表现为轻微「字在呼吸」。
- 结论：字幕镜**先 A/B 再决定**；密集小字/大量文字的镜头建议跳过补帧，或把字幕留到补帧后叠加（需要字幕层，当前管线没有）。

## 4. 对管线的建议

1. **默认逐镜开 48fps**：`video_interpolate(video_node=…, target_fps=48)`，`quality` 档、×2；D2 补齐已内置（产物帧数 = 源 × 2、时长不变）。
2. **成片/含硬切镜头不补**：切点会出鬼影；转场镜和拼接产物保持 24fps，或先拆再补。
3. **字幕镜有条件**：抽中间帧核对字幕清晰度，不过就跳过该镜。
4. **体积**：768×1344 的 48fps 产物与 24fps 源持平（实测 2.00 MB vs 2.00 MB，同 CRF 重编码）；120fps 母版 +37%。
5. **不要用 48fps 掩盖画质问题**：保留帧没有被重画（PSNR 41–42），补帧只加时间信息，不会提高清晰度。

## 5. 复现

```bash
# 1) 补帧（脚本会等队列空闲）
node scripts/experiment-48fps.mjs <源mp4> 2

# 2) 抽帧（ffmpeg 不在 PATH，用绝对路径）
FF=/Users/seiue/Workspace/short-video/tools/ffmpeg/ffmpeg
$FF -ss 1.42 -i <48fps产物>.mp4 -frames:v 1 out.png

# 3) 正式管线（含 D2 补齐）：
node scripts/e2e-interpolate.mjs        # 24→48 与 24→60 两例
```
