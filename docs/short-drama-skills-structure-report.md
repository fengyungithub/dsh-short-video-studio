## 0. 结论速览

1. **三层结构的方向是对的，坏在三处接缝**：剧本层（WRI）→ 系列治理层（PROD）→ 单集拍摄层（SSG）。问题不在"要不要拆/合"，而在：**上层写了下层的产物**、**层间契约没有单一载体**、**初始化与路由没有仲裁人**。
2. **最贵的结构问题是 writer 的"双层制作包"**：WRI 的 `/export` 产出「分集制作包」（含分镜稿、12 镜、18–25 句对白），PROD 又产出「集制作包」（6 节、8 列、17–18 镜、句数≤镜数）。同名不同物、口径互斥、前者无人读取。真实项目已发生：WRI 包 15 镜 / 24 句 / 3 场 / 1.5–2 分钟 → PROD 重排成 **25 镜 / 105.8s**，靠人工往 state 里补了 skill 未定义的 `episodeSecondsException`。
3. **第二个洞是声线资产没有归位**：系列路径跳过 SSG 的 STEP 3.5，预填表也没有「声线方案」⇒ 80 集对白剧会静默走 `text-only`，而 SSG 自己规定「有对白时门控必须作答，不许 AI 默认」。
4. **第三个洞是规则复制**：PROD 复述 SSG 的调用序列，两套 `groupOrder`（9 vs 10，缺 `voice auditions`）、两处 `canvas_set_state`、PROD 全文零次 `canvas_get_state`；另有「插件不能生成 BGM」「无 TTS 所以音色无解」两处过期断言。
5. **命名不是根因，但有一个真 bug**：技能目录只把 `description` 前 500 字给模型看，SSG 的描述有 1068–1150 字，「片型 / 连续短剧」落在第 **559–636** 字 ⇒ 模型在目录里**看不到它承接短剧单集生产**。⇒ 先改描述（6 文件 / 10 处），比改名有效；改名（含 `short-drama-generator`）作为可选项，等结构定稿后再做。

**推荐路线**：方案 1「三层收敛 + 一份契约 + 门分层」（约 4–6 个工作日），保留三个 skill id；命名走 A（只改描述），可选叠加 A′（`short-drama-series-production` → `short-drama-series-producer`）。不建议现在全量改成 `short-drama-*` 族名，也不建议合并成一个大 skill。

## 2. 职责分层：应该是什么，现在偏在哪

### 2.1 三层 + 一份契约（目标模型）

```
L0 剧本层     WRI   写「故事与台词」：场次、逐字对白、钩子、卡点、合规
                      产物：creative-plan / characters / episode-directory / episodes/epNNN.md
                      权威：文件
              │
              │  ① 剧本（文件）
              ▼
L1 系列治理层 PROD  管「拍什么、花多少、到哪了」：圣经、目录、资产台账、声线台账、
                      集制作包、状态、成本、跨集一致性、交付治理
                      产物：series/bible.md / production-state.json / 集制作包
                      权威：文件 + 主会话画布
              │
              │  ② 集制作包（唯一交接物：6 节 + 8 列镜头意图 + 资产清单 + 生产参数预填）
              ▼
L2 单集拍摄层 SSG   管「怎么拍」：卡片 → 七列镜头表 → 分镜 → 提示词库 → 逐镜 → 拼接 → 终检
                      产物：画布节点
                      权威：画布
              │
              ▼
L3 生成能力   插件能力注册表（图片 / 视频 AV / 音频 / 超分 / 拼接）
```

**一句话优先级**：L1 管「拍什么」，L2 管「怎么拍」；L2 的实测硬约束（一镜一说话人、≤15s、≤3 重要角色、续接链、G-ref、门 3）**不可被 L1 覆盖**。

### 2.2 现状职责矩阵（谁写 / 谁读 / 谁批）

| 产物 | 唯一写入者（现状） | 读取者（现状） | 人工门 | 问题 |
|---|---|---|---|---|
| `episodes/epNNN.md` | WRI | PROD | WRI 各阶段 + G-B | ✔ |
| `export/episodes-production/*`（「分集制作包」） | WRI | **无人读** | `/export` 抽查 | **死产物，且与 PROD 的包同名** |
| 集制作包 `series/episodes/epNNN/package.md` | PROD | SSG **只声明读 ⑥** | **无** | 交接物没有批准门；③④⑤ 读取点未声明 |
| `series/production-state.json` | PROD | PROD | — | 无 schema、字段超出草案（真实项目已出现） |
| `.drama-state.json` | WRI（仅 `/start`） | 无人读 | — | 只有一个写入点，进度不可信 |
| 画布 `settings`（7 字段） | **PROD 与 SSG 都写** | SSG 读；**PROD 零次读** | — | 双写、后写者胜、无校验 |
| 画布 `groupOrder` | 双方各写一套 | 画布渲染 | — | 9 vs 10 组，缺 `voice auditions` |
| 角色卡 / 场景卡 / 道具卡 | SSG（PROD 只在阶段 C 触发） | 双方 `asset_list` | 卡片锁定 / G-A | 单片要 5 张锁定卡 |
| 声线 `voice:` | SSG STEP 3.5 | SSG STEP 7 | 试镜听核 | **PROD 无槽位、预填无此项** |

### 2.3 五个结构性错位

1. **WRI 越界到拍摄层**：它规定 12 镜、18–25 句对白、3–5 场次、分镜稿与景别运镜。这些是 L2 的实测资产，写在上游就会被下游覆盖；覆盖规则一漏，行为就不可复现。
2. **PROD 越界复述 L2 规则**：§8.3 与 runbook 抄了 SSG 的调用序列（`canvas_write_prompt_bank`、`comfy_generate_video(...)`、转场、门 3），还自带一份 9 组 groupOrder。规则一改就要人工同步两处，且已经漂移。
3. **SSG 越界承担路由**：STEP 0 的片型门 + 三级查剧本 + 委托入口，是为系列路径打的补丁，代价是**单片主路径被系列关卡污染**（开门先问片型，再问 11 项）。
4. **声线在两层之间"掉了"**：SSG 有完整管线，PROD 没有槽位也没有步骤，于是系列路径既不问也不做。
5. **契约被劈成两半**：8→7 列映射、节拍→Hook 映射、⑥ 预填表全在 PROD 的 references；SSG 正文只声明读 ⑥。交接靠散文互指，没有 schema、没有版本号、没有校验。

## 3. 完整工作流程（现状）

### 3.1 单片路径（SSG 独立使用）

```
创意
 → STEP 0 规格（门0 片型 → 复用范围 → 11 项生产规格 = 最多 13 张卡）
 → STEP 1 项目简报 ────────────── 卡①
 → STEP 2 故事大纲 ────────────── 卡②
 → STEP 3 角色卡（每角色 single + three 两版） ├ AI 自检 → 锁定卡
 → STEP 3.5 声线试镜（audition/existing/text-only） ├ 听核卡 → 入库 voice:
 → STEP 4 场景卡 / STEP 4.5 道具卡 ──────────────── 锁定卡
 → STEP 5 七列镜头表 ──────────── 门 1
 → STEP 5.5 十一项自检 ─────────── 门 2（+ 分镜模式卡）
 → STEP 6 文本分镜（铅笔图 opt-in） ─ 分镜批准卡
 → STEP 7 渲染参数卡 → 逐镜 prompt bank → 逐镜 r2v（continuity_from）
        └ 门 3：AI 逐镜自检 + 人工 per-shot / batch
        └ 跨场景转场镜（i2v 双端锚定）
 → STEP 8 拼接 → 超分（opt）→ 终检 → 交付卡
```

**门数（实测计数）**：batch **28** 张（区间 19–31），per-shot **38** 张（26–43）；其中 STEP 0 就占 13 张，且全部发生在任何产物之前。

### 3.2 连续短剧路径（PROD 总控 + WRI 剧本 + SSG 单集）

```
主会话（1 个，不渲片段）
  A 立项与圣经   WRI 选题/方案/人物/目录 → series/bible.md + production-state.json ── G-S
  B 剧本流水     WRI /episode 1-10（每批 5–10 集）────────────────────────────── G-B
  C 资产锁定     角色双版 + 状态卡 + 场景卡 + 道具卡 +（声线：缺失）──────────── G-A + 集中入库
  D 样片集 EP01  单集 SOP + 三档实测 + 一致性基线 + 原生/超分对照 ────────────── G-SAMPLE
  F 收尾         整季交付清单 + 成本复盘 ───────────────────────────────────── G-F
        │
        │  每集：series/episodes/epNNN/package.md（6 节 + 8 列 + 资产 + 预填）
        ▼
每集会话（新会话，一集一会话）
  1 读 production-state.json（stage / doneShots / 资产台账）
  2 读 episodes/epNNN.md + 分集目录 + series/bible.md（按需）
  3 asset_list → asset_to_canvas（本集角色/状态/场景/道具）
  4 建集制作包（文件 + 该集画布节点）        ← 无人工批准门（问题 C11）
  5 委托 SSG，从 STEP 3 起（十项参数用 ⑥ 预填）
      3 卡片（缺卡才建）→ 5 七列镜头表（门1）→ 5.5 自检（门2）
      → 6 分镜（批准）→ 7 逐镜（门3 batch）→ 8 拼接/终检/交付
  6 回写 state + 主会话 ledger
```

**门数（实测计数）**：单集 batch **6** 张（runbook 清单读法只有 3 张——文档自身两套读法），per-shot **24** 张；EP01 从立项到样片批准 **17** 张（+ 一集量产 6 ⇒ 23）。

**注意三个"断点"**：
- `reviewMode` 写在 PROD §1/§8.2，但每集 SOP 没有 `canvas_set_state` 这一步；SSG 读不到就按 per-shot ⇒ **6 门变 24 门**。
- `groupOrder` 在每集会话缺 `voice auditions`；一旦走试镜，声线节点会漂到画布末尾，不报错。
- 集制作包**没有人工批准门**，70 min/集的成本在包生成后直接开跑。

### 3.3 双路径对照

| 维度 | 单片 | 连续短剧单集 |
|---|---|---|
| 参数来源 | STEP 0 现场问（13 张卡） | 集制作包 ⑥ 预填（不问） |
| 简报/大纲 | 完整写 | 只写「本集简报」（五项无 state 字段的配置无处落） |
| 资产 | 每项目现场建 | 资产库物化，缺卡才建 |
| 镜头表输入 | 大纲 + 分镜 | 8 列镜头意图（映射不完整） |
| 声线 | STEP 3.5 做 | **不做、不问、不记录** |
| 审查节奏默认 | per-shot | batch |
| 交付 | 单条成片 + 终检 | 集交付包 + 配乐点单 + 成本台账 |
| 人工门 | 28（batch） | 6（batch）/ 24（per-shot） |

### 3.4 真实项目旁证：冲突已经发生

`.dsh-assets/绛珠泪-交付包/`（运行时不入库，仅作证据）：

- WRI 侧 `06-分集制作包/ep001-*.md`：**15 个镜头 / 24 句对白 / 3 场 / 1.5–2 分钟**。
- PROD 侧 `series/episodes/ep001/package.md` 开头写着：源剧本逐字沿用，**按「一镜一说话人」重排为 25 镜 / 105.8s**。
- `series/bible.md` 把规格改成「90s 标准（17–20 镜）｜**EP01 例外 105.8s**（源剧本 24 句）」。
- `production-state.json` 出现 skill 草案里没有的字段：`episodeSecondsException`、`imageTier`、`characterCardVariant`、`reviewMode`、`source`、`bible`；`episodes` 键实际写成 `ep001`，而草案写 `ep01`。

⇒ 这不是"理论冲突"，而是**人工在给缺失的契约打补丁**。结构优化必须把这些补丁收编成正式机制（例外字段 / 编号规范 / 口径覆盖表）。

## 4. 人工参与环节：现状与目标

### 4.1 五类人工参与（按"为什么必须人"分）

| 类型 | 含义 | 例子 | 能否自动化 |
|---|---|---|---|
| **D 决策** | 成本 / 创意分叉，AI 无权默认 | 片型、风格、画幅、时长、档位、字幕、声线方案、交付画质、故事/镜头表/分镜批准 | 不能，但可合并、可给默认 |
| **A 资产验收** | AI 已跑完自检，人看结论 | 角色卡 / 场景卡 / 道具卡锁定、门 2、G-A | 可降级为 exception-only（只在不过时打断） |
| **L 听核** | AI 听不了音 | 试镜听核、门 3 音频项、转场幻听、交付听核 | 不能，但可批量 |
| **O 操作** | 必须点按钮 / 上传 | 卡片与声线入库、上传干声、手动裁图、飞书群聊审批卡 | 不能，但可批量清单 |
| **E 异常** | 只在出事时打断 | G-ref 门禁、同镜 3 次失败、铅笔图失败、意图冲突、换规格 | 已是 exception-only |

### 4.2 门清单（分组摘要）

| 组 | 门 | 为什么必须人 | 频次 |
|---|---|---|---|
| 项目规格 | 片型、复用范围、风格、画幅、时长、音频模式、**声线方案**、字幕、视频档位、角色卡版本、图片档位、交付画质、审查节奏 | 成本 ×10 量级 / 破坏性 | 每项目 1 次（现状 13 张） |
| 创作 | 简报、大纲、剧本批次（G-B）、单集剧本确认、`/review` | 创意方向 | 每项目 / 每批 |
| 资产 | 角色卡锁定 ×N、场景卡 ×N、道具卡 ×K、G-A、试镜听核 ×角色 | 视觉锚点 + 听核 | 每项目 1 轮（现状单片 5 张 / 系列 1 张） |
| 单集方案 | 门 1 镜头表、门 2 自检、分镜模式、分镜批准、渲染参数 | 拍摄计划 | 每集（现状 4–5 张） |
| 成片 | 门 3（per-shot / batch）、交付批准、G-E、G-SAMPLE | 听核 + 成本 | 每集 / 每部 |
| 操作 | 入库、上传、通读目录、导出抽查、每 5 集抽查、飞书审批 | 插件契约规定由人做 | 批量 |

### 4.3 触达次数（1 次 = 1 张 `ask_user_question`）

| 场景 | 主数字 | 区间 | 备注 |
|---|---|---|---|
| 单片 45s / 10 镜 / batch | **28** | 19–31 | per-shot 38（26–43） |
| 一集 90s / 18 镜 / batch | **6** | 3–8 | runbook 读法只有 3 |
| 一集 90s / 18 镜 / per-shot | **24** | 21–26 | 门 3 每镜一张 |
| EP01 样片集 | **17** | 14–19 | + 一集量产 6 ⇒ 23 |

- 飞书**群聊**每次 ask 前会先弹审批卡，上述数字 **×2**；私聊不乘。
- 入库/上传/通读/抽查是纯人工操作，未计入：单片 8–9 次点击，系列一次集中 30–50 次。
- 结论：**门数不跟镜头数走，跟"第一次做这个项目"走**。真正随镜数增长的只有门 3，所以优化重点在"一次性规格 + 一次性资产"，不在门 3。

### 4.4 重复、叠门与缺口

| # | 现象 | 证据 | 影响 |
|---|---|---|---|
| 1 | 13 张规格卡堆在任何产物之前 | `SSG:194/224/226-269` | 开场连点 13 次才见到简报 |
| 2 | 档位 / 审查节奏 / 交付画质被问 2–3 次 | `SSG:247/264/257` vs `SSG:688-696` vs `SSG:926` | 第二、三次几乎必选"沿用" |

## 5. 结构问题清单

> 严重度：**P0** = 每集必踩 / 直接返工；**P1** = 经常踩 / 需人工纠偏；**P2** = 低成本修正。完整证据见附件。

### P0

**P0-1 · 双层制作包 + 三层数量口径，没有覆盖规则**

**P0-2 · 交接契约没有单一载体**

**P0-3 · 声线资产未归位**
系列路径跳过 STEP 3.5、预填表无声线方案、资产台账无 voices 槽位；PROD 还断言"跨集音色无保证 + 无 TTS ⇒ 只能后期配音"。

影响：静默覆盖、每集门数翻 4 倍、声线组漂到画布末尾。

## 6. 优化方案

### 6.1 三个方案对比

| | 方案 0 · 文档修复 | **方案 1 · 三层收敛 + 契约（推荐）** | 方案 2 · 拆出"集生产引擎" | 方案 3 · 合并成一个 skill |
|---|---|---|---|---|
| 做法 | 只改描述 / README / 3 处过期断言 | 保留三 skill；单源规则、唯一交接物 + schema、单一声明者、门分层、声线归位、编号统一 | 新增薄 skill `short-drama-episode`，SSG 回到纯单片；PROD 委托它 | 三合一 |
| 解决 | 路由 | **路由 + 契约 + 门 + 声线 + 可维护性** | 方案 1 的全部 + 受众彻底分离 | 无 |
| 成本 | 0.5 天 / 6 文件 | **4–6 天 / 3 skill + schema + 1 脚本** | 方案 1 + 拆 STEP 3–8 调用链（1–2 周） | 最慢 |
| 风险 | 契约问题全留 | 中（改动集中在文本，可灰度） | 高（拆调用链会动续接/门控） | 高（1200+ 行、单片用户被系列关卡绑架） |
| 结论 | 作为 P0 先做 | **推荐** | 二期可选 | 否决 |

> 为什么不再"加一层总控"：PROD 已经是总控；再叠一层只会增加交接次数。问题不是层数，是接缝。

### 6.2 方案 1 的七个改动（按依赖顺序）

1. **规则单源**：L2 拍摄规则只在 SSG 定义；PROD 删掉可照抄的调用序列，只保留「注入点 + 系列层校验 + 门编号」。WRI 只写剧本（场次 + 逐字对白 + 钩子 + 卡点），**删掉 12 镜 / 18–25 句 / 分镜稿 / 制作包导出**这类拍摄层产物（或标注"非生产输入"）。
2. **唯一交接物 + schema**：集制作包 = 文件 + 画布节点（逐字一致），前置 YAML/JSON 块；新增 `schemas/episode-package.schema.json`（仓库已有 `schemas/workflow-manifest.schema.json` 先例）。必填项至少补：`voicePlan`、`storyboardMode`、`groupOrderVersion`、`assets.voices[]`、`scenes[].lightBaseline`、`dialogue[].voiceRef/sfx`、`contract.version`。
3. **单一声明者（按模式定唯一写入者）**：委托模式下 `canvas_set_state` / `groupOrder` / 集制作包 / `production-state.json` 由 PROD 独占；单片模式下由 SSG 独占。SSG 在委托模式只读、校验、缺值告警不重写。每集 SOP 补一步 `canvas_set_state`。
4. **门分层**：项目规格（1 张）→ 资产总览（1 张）→ 每集 **3 张卡**（方案：包 + 镜头表 + 分镜 + 渲染参数；片段：门 3 batch + 听核；交付：终检 + 成本 + 台账）→ 异常 only。合并"门 1 + 门 2 + 分镜模式 + 分镜批准 + 渲染参数"为方案卡；单片同理（P2）。
5. **声线归位**：声线 = 角色资产。PROD 阶段 C 一次性试镜 / 复用 → 入库 `voice:` → 写 `assets.voices[]`；集制作包 ⑥ 加 `voicePlan=existing`；SSG 的 STEP 3.5 在委托模式下改为"读台账校验"，单片模式保留原流程。PROD §11.6 改写成"可用 `voice:` 参考音频统一；无 TTS 只限制生成新音色"。
6. **编号 / 路径 / 状态统一**：`EP{三位补零}`；`state.episodes["ep001"]`；`series/episodes/ep001/package.md`；状态文件建议改名 `series/state.json`（避开与外部 `shortdrama-memory` 的同名 `production-state.json`）；加 `contract.version` 与 gate 结构（`{id,status,at,by}`）。
7. **路由与描述**：三个 description 的前 500 字重写到能自解释分工与交接（SSG 写"连续短剧只做单集，系列层转 PROD"；PROD 写"制片总控，不拍片"；WRI 写"只出文本，两类包不同"）；加显式排除句（Hub 版 / `shortdrama-*` / `film-assets`）；修 README 的「3D 动画短片」旧标签。

| **A（推荐）** | 三个 id 都不动，只改描述与文档标签 | 0 目录 / 0 代码 / 6 文件；路由问题靠描述解决 |
