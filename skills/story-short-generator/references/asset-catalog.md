# 资产目录（角色卡 / 场景卡 / 道具卡 / 风格锚点 / 片段 / 文本）

> 本 Skill 的**资产定义**集中在这里。SKILL.md 的 STEP 3 / 4 / 4.5 只写执行步骤与门控，形态规范以本文件为准。
> 结构借鉴同语料的 `film-assets` skill（角色 / 道具 / 环境三大类 + 子类型 + 生成要求表），并按本 Skill 的**视频生产**用途收窄——**凡是要进 `ref_nodes` 的资产，形态必须匹配该次渲染的档位**（见 §6）：`fast` 档一律单视图单主体，`balanced` / `quality` 档角色卡可以是三视图横排。

## 1. 资产总表

| 资产 | 画布 carrier | 画布分组 | 库内 `type` | 形态规范 | 可否作 `ref_nodes` | 对应步骤 |
|---|---|---|---|---|---|---|
| **角色卡** | image | `character cards` | `character` | **双版本**：单视图正面全身 + 三视图横排（视频引用版本由 STEP 0 用户选择；`fast` 只能单视图）；纯色背景、零文字 | ✅ | STEP 3 |
| **场景卡** | image | `scene cards` | `scene` | 单视图环境、无人物、零文字（**不随档位改形态**） | ✅ | STEP 4 |
| **道具卡** | image | `prop cards` | **无 `prop` 类型**（见 §5） | 单件道具、单视图、纯色背景、零文字（**不随档位改形态**） | ✅ | STEP 4.5 |
| 风格锚点 | image | 任意 | `style` | 单张风格帧、零文字 | ⚠️ 实验性，未实测 | 可选 |
| 片段 | video | `shot clips` | `clip` | — | ❌ 视频不可作参考图 | STEP 7 |
| 文本 / 表格 | text / table | 各对应组 | `text` | — | ❌ | 各步 |

**库内 type 由插件定义**（`ASSET_TYPES = ['character','scene','style','clip','text']`），本 Skill 不新增类型。`kind` 由 type 推导：`character|scene|style → image`、`clip → video`、`text → text`。

## 2. 角色卡

**用途**：锁定角色身份（脸、发型、身材、服装、签名道具），是 r2v 镜头的身份锚点。

**子类型（每个角色固定出两版；视频引用按当次 `tier` 选）**：

| 版本 | 形态 | 说明 |
|---|---|---|
| `single` | **单视图正面全身** | 一图一人；**所有档位合法**，`fast` 档必须用它（该档多主体参考图必出副本 / 画面污染） |
| `three` | **三视图横排**（正面 / 侧面 / 背面全身，1×3） | 三格等宽、每格一人全身，**靠纯底留白分隔，不画分隔线、不写标注**；`balanced` / `quality` 默认引用（实测只出 1 个角色） |

- **视频引用规则**：由 STEP 0 用户选择决定（`state.characterCardVariant`）——项目档位 `fast` 只能 `single`；`balanced` / `quality` 可选 `single` 或 `three`。每镜按 `ref_variant` 显式传（**工具不按 tier 自动选**）；某镜临时降到 `fast` 时该镜强制 `single`。非 fast 档若自检出现参考图形态类污染（多角色副本 / 版面被投影 / 环境材质被替换）→ 传 `ref_variant='single'` 重渲。
- **配对元数据**：两版用 `params.character` / `params.cardVariant` / `params.pairedNodeId` 互配（`comfy_generate_image` 的 `character` / `card_variant` / `paired_node_id` 参数写入）。
- **两版共享同一份角色设定**（脸 / 发型 / 身材 / 服饰色 / 签名道具 / 不可改特征）与同一套风格锁；自检必须并排核对两版是同一角色。

同一角色的**不同着装 / 形态状态分别建一对卡**（如「不穿宇航服 / 穿宇航服」「常态 / 变身态」），每对仍是 `single` + `three`，标题用「统一角色名 + 状态 + 版本后缀」。

> `film-assets` 有 三视图 / 四视图 / 八视图 / 表情包 / 姿势组图 / 角色卡 等子类型。本 Skill **只采纳「三视图横排」作为原始素材**（单视图由它裁出来），且要求它**零文字、无分隔线、无头特写混排**；四视图 / 表情包 / 姿势组图 / 多格设定图**仍不要用**（多主体在 `fast` 档必崩；非 `fast` 档也未测这些形态）。要更多角度时**逐张单独生成**，分别占 `ref_nodes` 槽位。

**生成要求**

| 要求 | 说明 |
|---|---|
| 形态 | **先出 `three` 三视图横排**（正 / 侧 / 背，1×3），再用 `image_crop` 裁正面格当 `single` 单视图；平视平角（相机与腰部至胸部齐平），禁止俯拍仰拍；比例正常，不拉伸不压缩；**每格全身含脚**（裁出来的单视图会继承这个构图） |
| 文字 | **图内零文字**——不画角色名、不画视图标注、不画道具标签、不加水印、**不画格与格之间的分隔线** |
| 背景 | 浅灰或纯白纯色；三视图卡**恰好三格**、同一角色、三格姿态不重复、无第四格 / 额外身体 / 剪影 |
| 风格 | 所选风格文件的**风格锁后缀 + 负向约束**必须追加 |
| 光线 | 柔和均匀（`pixar-3d` 影棚光；`cinematic-live-action` 自然光 + 真实光比）；三视图三格光位一致 |
| 清晰度 | 目标审阅尺寸下脸、服装、姿势细节可读 |
| 一致性 | **两版按构造一致**：单视图 = 三视图正面格 1:1 裁切（`image_crop`，不重绘）；记录 seed 以便同 seed 微调三格；自检只查**裁切边界**（没带进旁格内容、没裁掉人物） |
| 比例 | **不继承影片比例**，三视图显式传 `width`/`height`（32 对齐）：**16:9 横版** `fast` 1024×576 · `balanced` 1344×768 · `quality` 2048×1152；**单视图 = 正面格**（三视图宽的 1/3）：`fast` 341×576 · `balanced` 448×768 · `quality` 682×1152，由 `image_crop` 自动得出，**不要手填旧 2:3 尺寸** |
| 非人形角色 | 形态一律按「实测 prompt 铁律：形态正向构造」写**正向解剖清单**，禁止否定堆叠 |
| 批量 | 同类资产一次性批量生成 |

**自检（自检点 1）**：① **三视图本体**——恰好三格 / 同一角色 / 正侧背可辨 / 三格不重复 / 每格全身含脚 / 无第四格 / 无分隔线 / 零文字；② **裁出的单视图**——正面 / 单主体 / 全身含脚 / 纯底 / **左右边缘无相邻格残留** / 零文字；③ **裁切边界**正确（没带进旁格、没裁掉人物）；与节点描述逐项一致；符合所选风格锁。三视图不过就重出三视图再重裁，单视图不过只调裁切矩形。不过不许弹「锁定」选项卡。

**命名与入库**：标题写「角色名 + 状态」，定位与不可改特征写进**节点标题与描述**（不进图内）。跨会话复用：**单片**由用户在画布点「入库」；**剧集**在 G-A 资产总览批准后由 AI 调 `asset_ingest`。id 形如 `character:luna`。

## 3. 场景卡

**用途**：锁定环境（布局、光态、地标、氛围），是 r2v 镜头的环境锚点。

**形态**：**单视图环境**（一个机位视角）。需要多角度时**逐张单独生成**，不要拼成多格场景卡。**场景卡不随视频档位改形态**——三视图横排的档位默认只适用于角色卡（多角度场景卡在非 `fast` 档无实测依据）。

**生成要求**

| 要求 | 说明 |
|---|---|
| 形态 | 单视图环境；机位与视角写进节点描述 |
| 内容 | **只展示环境**——无人物、无人群、无剪影、无手、无脸、无角色客串 |
| 文字 | **图内零文字** |
| 地标 | 写明**连续性地标**（同场景跨镜必须保持屏幕位置的固定物体，如门框 / 中岛 / 邮筒）及其画面相对位置——供镜头表 `固定地标` 列直接引用 |
| 光态 | 写明主光 / 补光 / 轮廓光方向与色温（日景 / 夜景各一版） |
| 风格 | 所选风格锁后缀必须追加 |
| 比例 | **跟随画布 `aspectRatio`**（与影片同比例，便于直接当镜头参考；**不要**给它套角色卡的 2:3 竖版） |

**自检（自检点 2）**：零文字 / 无人物与剪影 / 与节点描述一致 / `固定地标` 真实存在且位置可读未被遮挡 / 符合所选风格锁。

**命名与入库**：标题「场景名 + 光态」；地标名与位置写节点描述。id 形如 `scene:bridge`。

## 4. 道具卡

**用途**：锁定**签名道具**（反复出现、承担叙事功能的物件）的形状 / 比例 / 材质 / 配色，避免逐镜只靠文字描述导致漂移。

**形态**：**单件道具、单视图、纯色背景**。

> ⚠️ `film-assets` 的道具模块默认是「摄影机位环绕多视图」（三视图 / 四视图）。**本 Skill 一律收编为单视图单件，且不随视频档位改形态**——理由同上：多主体参考图在 `fast` 档必崩，而道具的多视图在非 `fast` 档也**无实测依据**。真需要多角度时逐张单独生成、分别占槽位。

**生成要求**

| 要求 | 说明 |
|---|---|
| 形态 | 单件道具、单视图；透视与光影写进节点描述 |
| 内容 | 只画道具本身——无人物、无手、无脸、无人群、无剪影、无场景环境 |
| 文字 | **图内零文字** |
| 特征 | 形状 / 比例 / 材质 / 配色 / 磨损特征逐项写进节点描述 |
| 风格 | 所选风格锁后缀必须追加 |
| 背景 | 纯色（默认纯白） |
| 比例 | **1:1 方形**（显式传 `width`/`height`，如 `balanced` 1344×1344）——单件道具居中，方形最省画面 |

**自检（自检点 3）**：单件单视图 / 零文字 / 无人物与手 / 与节点描述一致 / 符合所选风格锁。

**是否建卡**：**可选**。只在道具是叙事关键且**反复出现**时才建卡并进 `ref_nodes`（每张卡占一个参考槽位）；单次出现的小道具写进镜头描述即可。**单镜 `ref_nodes` 数量 >2 的形态未实测**——加了道具卡就优先在 `balanced` / `quality` 档生成。

## 5. 已知限制：资产库没有 `prop` 类型

插件资产库的 `type` 只有 `character` / `scene` / `style` / `clip` / `text`（`lib/assets.js`）。所以：

- 道具卡**入库时只能选这三选一**：`character` / `scene` / `style`，**推荐 `scene`**（道具属于"环境中的物件"），id 形如 `scene:prop-<name>`。
- **后果**：`asset_list(type=scene)` 拿到的资产**不一定是环境卡**。Agent 必须用**节点标题与描述**确认它的真实语义，不要盲信前缀。
- 若用户不接受语义混用，道具卡就**只在会话内以画布节点复用**，不入库。

## 6. 跨类公约

1. **风格锁**：所有图片类资产生成时都必须追加风格后缀（**按产物取用 A / B / C 段**，见 [style-selection.md](style-selection.md) 的取用表）。**铅笔分镜图除外**（始终纯黑白线稿）。
2. **图片档位**：所有图片类资产（角色卡 / 场景卡 / 道具卡 / 铅笔分镜图）都用 **STEP 0 选定的图片档位**生成，并**显式传 `tier=`**，**默认 `balanced`**。**尺寸口径分两条路**：**文生图**长边 `fast` 1024 / `balanced` 1344 / `quality` 2048（× 画布比例，32 对齐）；**参考图改绘**（`image.image2image`）**没有固定长边**，输出尺寸**跟随第一张参考图**按该档「参考图预算」等比缩放（32 对齐），显式宽高不参与 ⇒ 想改绘出大图，参考图本身不能太小。`fast` **只用于抽卡试构图**，其产物**不得直接锁定**——锁定前必须用选定档位重出定稿；`balanced` 是默认，`quality` 按需。理由：卡片是全程复用的身份 / 环境锚点；`balanced` 1344 长边已够用，`quality` 只在高细节/大尺寸交付时选（同张卡约 7× 耗时）。
3. **角色卡固定两版；先三视图、裁出单视图；引用版本由 STEP 0 用户选择**：每个角色出一张三视图横排（16:9），再用 `image_crop(panel=0, panels=3)` 裁正面格当单视图（**同源像素，身份按构造一致**）；**视频引用哪一版由用户选择**（`state.characterCardVariant`；`fast` 只能单视图，`balanced` / `quality` 可选单视图或三视图）；**采样尺寸**由**图片档位**推导（长边 1024 / 1344 / 2048）——两者独立，不要互相顶替。单视图分辨率约为整张 1/3，别再按旧 2:3 尺寸生成。
4. **参考图形态与门禁**：所有要进 `ref_nodes` 的资产（角色卡 / 场景卡 / 道具卡）都受 [reference-image-contract.md](reference-image-contract.md) 约束——先按 **STEP 0 的 `state.characterCardVariant`** 选角色卡版本（每镜 `fast` 强制 single），再按档位判定门禁：`fast` 档必须通过 G-ref（单主体 / 单视图 / 零文字 / 无拼图）；`balanced` / `quality` 档无门禁，三视图卡可直接使用；非 fast 档若出现参考图形态类污染，先换同角色单视图卡重渲。项目档位非 `fast` 但某镜临时降到 `fast` 时，该镜按 `fast` 规则处理（升档或换单视图卡）。
5. **入库由用户人工完成**：AI **不调用任何入库动作**，只在锁定卡片时提示用户"想跨会话复用就点该卡的入库按钮"；双版本角色卡两版分别入库，标题带版本后缀。
6. **重做纪律**：卡片重做后，下游（镜头表 `绑定` / `固定地标` 引用、分镜、已渲片段）必须改用**最新批准的卡片**；旧卡在画布上标记废弃。**改角色设定只能改三视图**，改完必须**重新裁单视图**（复用同一 nodeId 重裁）并保持 `pairedNodeId` 双向有效。详见 SKILL.md「重生成与最新资产纪律」。
7. **同一角色的状态卡**：续接**不继承身份**——续接沿用上一镜画面与声音，**不保证沿用服装 / 妆容**；认人永远看参考卡。
