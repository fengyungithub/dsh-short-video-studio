# 视觉风格选型与风格锁机制

本 Skill 内置 **6 套视觉风格**，STEP 0 选定一套，全流程统一使用。

- **选型指引**：本文件
- **每套的完整规则 + 风格锁后缀**：`references/styles/<id>.md`（**只读选定的那一份**，不要一次把 6 份全读进来）

## 2. 怎么选

1. 用户已明确说了风格 → 直接映射到最近的 id，不要再多问一轮。
2. 用户只给了题材 → 按上表"适用题材"列推荐，把推荐项放选项卡最前。
3. 用户完全没概念 → 只列 2–3 个差异明显的候选（不要 6 个全列），每个用一句画面描述说清差别。

## 3. 风格锁机制

**风格锁 = 风格锁后缀（英文关键词串）+ 负向风格约束**，两者都在选定风格的 `references/styles/<id>.md` 里，**由该文件单独提供，SKILL.md 不再全局写死**（旧版把"不要写实真人摄影"写死在全局，加了真人风格后必然自相矛盾）。

**追加位置**：每次生成的 **prompt 尾部**——角色卡 / 场景卡 / 道具卡 / 视频片段通用。

**后缀按产物取用（实测结论：污染是双向的）**：

- **锁 A · 渲染基调** —— **所有产物通用**。⚠️ A 段里**既不能有角色词**（服饰 / 皮肤 / 头发 / 身段），**也不能有场景物件词**（建筑 / 树木 / 云海 / 光束）。
- **锁 B · 角色与表演** —— **只有角色卡与视频片段**才带
- **锁 C · 环境与氛围** —— **只有场景卡与视频片段**才带（当前仅 `guofeng-xianxia` 拆出了 C 段；其余风格的环境词并入了 A，见下方「待办」）

**两向污染的实测证据**：

- **角色词污染空场景**：`anime-cel` / `ink-wash-oriental` / `comic-halftone` 的场景卡里分别冒出了动漫男性 / 白衣女子 / 肌肉男 —— 违反「场景卡只展示环境」。
- **环境词污染纯底角色卡**：`guofeng-xianxia` 的角色卡在带了环境段后，**纯灰底上长出了松树、石台、法器炉与丁达尔光束**。

⇒ **取用表**：

| 产物 | 用哪几段 |
|---|---|
| 角色卡 | A + B |
| 场景卡 | A + C（未拆 C 的风格：A 中不含角色词的版本） |
| 道具卡 | A |
| 视频片段 | A + B + C |
| 铅笔分镜图 | 都不用 |

> **待办（已知不一致）**：`guofeng-xianxia` 已按三段式落地；其余 6 套目前是两段式，其中 `pixar-3d` / `cinematic-live-action` / `anime-cel` 已把混在 A 里的头发 / 皮肤 / 表面纹理词移入 B，但**环境词仍留在 A**——它们的场景卡不受影响（环境词不会污染空场景），**但角色卡可能带进环境元素**。需要严格纯底角色卡时，按 `guofeng-xianxia` 的三段式改造。

- **视频片段**：后缀追加在 **H3 结构化 prompt 之后**。风格锁与负向意图由片型侧拼接，**不归 `h3-prompt-writing`**（该 skill 只管 H3 结构核心）。
- **铅笔分镜图**：**不追加**。铅笔图始终是纯黑白线稿，套风格后缀会毁掉它作为"审稿草图"的用途。

**负向要按风格取反，不能跨风格混用**：

| 风格 | 负向里**必须包含** | 负向里**绝不能出现** |
|---|---|---|
| `pixar-3d` | `NOT live-action photography` | 禁 `photorealistic` 类词（会与自身冲突） |
| `cinematic-live-action` | `NOT cartoon, NOT 3D render, NOT anime` | 禁 `NOT photorealistic photography`（自相矛盾） |
| `ghibli-2d` | `NOT 3D render, NOT photorealistic` | 禁 `halftone`（那是欧美漫画的） |
| `anime-cel` | `NOT photorealistic, NOT 3D render` | 禁 `watercolour bleed` |
| `ink-wash-oriental` | `NOT western painting, NOT photorealistic` | 禁 `neon` 相关正向词 |
| `comic-halftone` | `NOT photorealistic, NOT soft pastel` | 禁 `halftone`（那是自身特征） |

> 这份表是**逻辑一致性检查清单**（"A 风格不要的东西"绝不能出现在 A 自己的负向里）。每套风格文件里的后缀已按此写好。

## 4. 换风格纪律

**换风格是破坏性操作，与「换档重做」同级：**

- 已批准的**角色卡 / 场景卡 / 道具卡**全部失效（它们带着旧风格渲染）
- **所有已生成片段**失效，必须全片重出
- 因此：**换风格必须在动手前显式确认**，并告知用户代价；不要在用户随口一提时静默切换
- 换风格后重跑：STEP 3 → 4 → 4.5 → 5.5 自检 → STEP 7 逐镜

用户只是"想看看另一种风格长什么样"时，建议先出一张**角色卡抽卡**给他比，不要直接全片重做。

## 5. 风格文件格式（8 段，固定）

每份 `references/styles/<id>.md` 必须给全这 8 段：

1. **适用与不适用** —— 什么题材该用、什么题材该换
2. **视觉 DNA** —— 8 层：渲染风格 / 角色造型 / 比例语言 / 发丝毛发 / 皮肤材质 / 表演风格 / 动态风格 / 情绪尺度
3. **负向风格约束** —— 中文描述
4. **风格锁后缀** —— **英文关键词串**，可直接复制追加到 prompt 尾部（含 `NOT ...` 负向）
5. **分层适配** —— 角色卡 / 场景卡 / 道具卡 / 视频片段各自怎么套；铅笔图显式排除
6. **与参考图契约的关系** —— 说明本风格不改变形态规则（角色卡固定双版本（单视图 + 三视图）；视频引用版本由 STEP 0 用户选择，`fast` 只能单视图）与「零文字 / 不拼图」硬规则，以及 `fast` 档的 G-ref 门禁
7. **已知风险与未实测项** —— 诚实标注，不要编造实测结论
8. **实测状态** —— 日期 / 档位 / 抽卡结论 / 耗时

## 6. 风格锚点资产（可选，实验性）

跨会话复用时可以把一张满意的风格帧入库为 `style` 类型资产（插件支持 `style:<name>`），后续以 `asset_to_canvas` 物化回画布，并用 `comfy_render(capability='image.image2image', ref_nodes=[风格锚点])` 做风格迁移式改绘。

⚠️ **未实测**：把风格锚点直接塞进视频的 `ref_nodes` 是否安全（多一张参考图会不会像多主体参考图那样泄漏）。**默认只用 prompt 后缀做风格锁**，风格锚点当作 `image2image` 的改绘参考用。

| `cinematic-live-action` | ✅ balanced 场景卡 + 角色卡 | 照片级夜巷 / 白底单视图全身，风格精准 |
| `ghibli-2d` | ✅ balanced 场景卡 + 角色卡 | 手绘线稿 + 水彩天空 / 柔线平涂角色，风格精准 |
| `anime-cel` | ✅ 场景卡复测通过 | 首轮场景卡**人物侵入空场景**；拆 A/B 后**复测通过**（纯空街、零人物）。2:3 竖版角色卡合规且保真良好 |
| `ink-wash-oriental` | ✅ 场景卡复测通过；角色卡 ⚠️ | 拆 A/B 后场景卡复测通过（零人物）。角色卡合规但**风格保真偏弱**；已把锁 B 的 `white-outline drapery` 修为 `dark ink-outline drapery`（原措辞会产生剪纸式白边），**待复测** |
| `comic-halftone` | ✅ 场景卡复测通过 | 首轮场景卡**人物侵入**；拆 A/B 后复测通过（零人物）。2:3 竖版角色卡合规、保真良好 |
| `guofeng-xianxia` | ✅ balanced 场景卡 + 角色卡 | 三轮迭代后通过；后又按用户反馈把角色推向**写实真人级**、场景推向**透亮清晰**（收 bloom / 收紧雾与灰调），复测通过。**过程中确立了「污染是双向的」结论** |

> **抽卡验证口径**：每套生成 1 张**场景卡**（balanced）+ 1 张**角色卡**（balanced），判定风格可辨认与"场景卡无人物"。**视频层结果见 §8。**
>
> **本轮验证的实际产出**：3 套风格以"场景卡不通过"暴露了后缀设计的缺陷（表演条款污染空场景），直接导致后缀拆成 A/B（后扩展为 A/B/C）。这正是抽卡验证该起的作用。

## 8. 视频层验证（2026-10-08 · 6 套各一条 5s `fast` 镜头）

口径：每套 1 条 `fast` 档镜头（`type=r2v` · **单视图角色卡**作 `ref_nodes` · seed `424242` · `length=124`），逐条抽中帧检视。**本表是视频层结果的唯一集中记录**；各风格文件 §8 记的是图片层。

> 本节记录的是**当时**的口径（`fast` 档必须用单视图卡）。现行规则见 [reference-image-contract.md](reference-image-contract.md) §1「双版本 + STEP 0 用户选择」：输出双版本（单视图 + 三视图）；视频引用版本由用户选择——`fast` 只能单视图，`balanced`·`quality` 可选单视图或三视图。

| 风格 | 结果 | 观察到的问题 |
|---|---|---|
| `pixar-3d` | 未测 | — |
| `cinematic-live-action` | ⚠️ | 画面出现**横向条纹伪影**；脸部仍偏插画，未到照片级 |
| `ghibli-2d` | ✅ | 水彩天空 + 草地野花 + 平涂人物，保真最好之一；脸比参考卡略年轻 |
| `anime-cel` | ✅ | 赛璐璐 + 硬边阴影稳定；脸有中性化漂移 |
| `ink-wash-oriental` | ❌ → 已修 | **自发产生竖排书法题款（乱码）**，违反零文字硬规则；已补负向，**待复测**。风格偏写实柔光，辨识度最弱 |
| `comic-halftone` | ✅ | 网点稳定**无摩尔纹**；但脸严重年轻化 / 少年漫化，与参考卡年龄漂移 |
| `guofeng-xianxia` | ⚠️ | 仙侠氛围到位；但脸退化成 Q 感，与「写实真人」目标冲突 |

**两条跨风格结论（比单风格结果更重要）**：

1. **6/6 都是单人、零副本** ⇒ 反过来验证了「`fast` 档 + **单视图**卡作 `ref_nodes`」是安全的 —— 门禁 G-ref 的前提成立（`fast` 档出事的是**多主体**参考图，不是单视图）。
2. ⚠️ **`fast` 档不能用来验收风格**：4 步采样下**人脸与细节保真严重不足**——4 套风格的脸都出现年轻化 / 中性化 / Q 化漂移，写实风格还出现条纹伪影。**风格验收至少跑 `balanced`**；`fast` 只用于验证链路是否跑通。这与「`fast` 是调试档」的定位一致。
