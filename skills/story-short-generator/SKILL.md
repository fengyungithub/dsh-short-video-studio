# 故事短片生成器（dsh-short-video-studio 适配版）

当用户想把一句话创意做成完整的故事优先短片时使用本 Skill。流程从创意开发到最终交付，所有主要产物都必须按生产顺序落到画布，并在高成本或关键创意节点用选项卡让用户确认。

核心规则：**先故事、再资产；接到创意后立刻用选项卡确认生产规格（含视觉风格、视频档位、图片档位、字幕开关、片段审查节奏、逐镜自检门与「声线方案」；有对白时门控必须作答：audition / existing / text-only 三选一）；产物按顺序上画布；所有需要用户确认的地方必须用选项卡；角色卡锁定后先做声线试镜（STEP 3.5）、再场景/道具卡；固定顺序为：七列标准镜头表 → 镜头表自检门 → 单文本分镜文档（可视化模式再加铅笔图）→ 逐镜 prompt 分档库 → 逐镜视频生成（门 3 的人工确认按 `reviewMode` 逐镜或批量）→ 交付复查；成片必须清除所有分镜痕迹。**

参考图硬规则（图内零文字 / 不拼图）由插件工具契约统一定义；入库规则是「单片用户点入库；系列 G-A 批准后 AI 可 asset_ingest」，本文不复述，全流程严格遵守。**角色卡固定出两版（先生成三视图横排，再用 `image_crop` 裁正面格当单视图——同源像素、身份按构造一致）**：视频引用哪一版由 STEP 0 用户选择——`fast` 只能单视图（多主体必出副本或污染画面），`balanced` / `quality` 可选单视图或三视图；非 fast 档成片自检若出现参考图形态类污染，**先传 `ref_variant=single` 重渲本镜**。门禁 G-ref 按**每次调用实际传入的 `tier`** 判定 —— 完整规则与实测证据见「参考图形态与档位」节。

**提示词分档持久化（prompt bank，全档位共用 quality）**：每镜一份画布文本节点，`fast` / `balanced` / `quality` 三段都写**同一份完整 quality 提示词**；视频生成传 `prompt_node`，换档只变采样、不换 prompt。详见「提示词分档持久化」节与 STEP 7。

**形状策略：正片镜头一律 r2v，i2v 只保留在两处（刻意保留，别顺手删）**

- **正片镜头 = `type='r2v'`（参考绑定）**：每镜传 `ref_nodes`（角色卡 + 场景卡）——**身份与环境永远由参考卡保证**；镜头之间的连续性用**链式续接**表达：**连续镜头传 `continuity_from`（接上一镜），独立镜头不传（起链）**。
- **i2v（首末帧串联）只用于**：① **跨场景转场镜**——双端锚定（前一场景尾镜末帧 + 下一场景首镜首帧），收尾**精确落回**下一镜首帧；② **锚点式重渲**——只改中段、要保住已批准的下游首帧时的例外路径（见「重渲与续接链」）。
- **i2v 也有支持续接的实现**（r2v / i2v 两边成对，用 `comfy_list_workflows` 查）：两处 i2v 用途都能**额外**选择"同时继承上一镜尾部"。实测行为契约：**续接的 i2v 里 `first_frame_node` 会被丢弃**（钉住的 head 已决定开头约 22 帧），**`last_frame_node` 保留**——所以转场镜的正确姿势是"续接前一场景尾镜 + 末帧锚定下一场景首镜"，首帧锚点传了也会被忽略。

续接的传参、链的硬约束与规划要求见 STEP 5 的 `续接` 列、STEP 5.5 第 9/10 项与 STEP 7「续接策略」。

## 视觉风格（7 套，STEP 0 选定）

本 Skill 内置 **7 套视觉风格**。全部角色卡、场景卡、道具卡、单镜头视频片段与成片必须**统一使用 STEP 0 选定的那一套**：

| id | 中文名 | 适用题材 |
|---|---|---|
| `pixar-3d` | 皮克斯感 3D 卡通（**默认**） | 合家欢、童话、成长故事 |
| `cinematic-live-action` | 电影真人写实 | 现代剧情、悬疑、犯罪、纪实感 |
| `ghibli-2d` | 吉卜力 2D 手绘 | 治愈、自然、成长、奇幻冒险 |
| `anime-cel` | 日式二次元赛璐璐 | 校园、青春、轻小说改编 |
| `ink-wash-oriental` | 水墨东方古风 | 古装、仙侠、武侠、历史 |
| `comic-halftone` | 欧美漫画半调 | 超英、暗黑奇幻、西部、动作 |
| `guofeng-xianxia` | 国风仙侠 3D | 仙侠、修真、玄幻、古风奇幻 |

**执行规则**

- 选型指引、默认值与完整对比表见 `references/style-selection.md`；**选定后立刻读取 `references/styles/<id>.md`**（只读这一份，不要一次把 7 份全读进来）。
- 每个风格文件都给出**风格锁后缀**（英文关键词串）与**负向风格约束**；两者都**追加到每次生成的 prompt 尾部**（角色卡 / 场景卡 / 道具卡 / 视频片段通用），确保跨镜风格一致。
- **后缀按产物取用（实测：污染是双向的）**：**锁 A · 渲染基调**（**既无角色词、也无场景物件词**）所有产物通用；**锁 B · 角色与表演**只有**角色卡与视频**带；**锁 C · 环境与氛围**只有**场景卡与视频**带（三段式目前只有 `guofeng-xianxia`，其余见各自文件的分段说明）。⇒ **场景卡与道具卡不得带 B**——角色词会把人物拉进空场景（实测：`anime-cel` / `ink-wash-oriental` / `comic-halftone` 的场景卡都出现了角色）；**角色卡不得带环境段**——环境词会让纯底卡长出松树、石台与光束（`guofeng-xianxia` 实测）。
- **负向风格约束由所选风格文件提供，本 Skill 不再全局写死**（例如 `pixar-3d` 禁写实真人摄影，而 `cinematic-live-action` 反过来禁卡通与 3D 渲染）。
- **铅笔分镜图不受风格锁影响**：它始终是纯黑白线稿（见 STEP 6）。
- **换风格 = 破坏性操作**：已批准的角色卡 / 场景卡 / 道具卡与**全部片段**都会失效，必须重出；与「换档重做」同级，须显式确认后再动。

## 参考图形态与档位（实测，STEP 0 / 3 / 4 / 4.5 / 5.5 / 7 引用）

### 1. 角色卡双版本（每个角色先出三视图、再裁正面格当单视图；STEP 3 出卡前必读）

**现行规则（2026-10 起）：每个角色固定出两版，不再只按档位出一版。** 做法是「先出三视图 → 裁正面格当单视图」——两版是同一批像素（裁切不重绘），所以角色设定（脸 / 发型 / 身材 / 服饰色 / 签名道具 / 不可改特征）与风格锁只需写一份；节点元数据用 `character` / `cardVariant` / `pairedNodeId` 配对。

| 版本 | 形态 | 画幅 | 用途 |
|---|---|---|---|
| `single` | **正面格全身**（一图一人、纯底、零文字，由三视图裁出） | 三视图宽的 1/3（≈0.59；`quality` 682×1152） | **所有档位都合法**；`fast` 档必须用它（多主体参考图在 fast 档必出副本 / 污染）；非 fast 档出问题时的兜底 |
| `three` | **三视图横排**（正面 / 侧面 / 背面全身，1×3，纯底、零文字） | 16:9 横版 | `balanced` / `quality` 档可选（推荐；实测只出 1 个角色、画面干净） |

**视频引用哪一版 = STEP 0 用户选择（`state.characterCardVariant`），不是 AI 按 tier 自动选版**：

| 条件 | 可选版本 | STEP 7 传参 |
|---|---|---|
| 项目视频档位 `fast` | **只能 `single`** | `ref_variant='single'` |
| 项目档位 `balanced` / `quality`，用户选单视图 | `single` | `ref_variant='single'` |
| 项目档位 `balanced` / `quality`，用户选三视图 | `three` | `ref_variant='three'` |
| 项目档位非 `fast`，但**本镜临时降到 `fast`** | 该镜强制 `single` | `ref_variant='single'`（不改项目选择） |

> **`ref_variant` 必须显式传 `single` / `three`**（工具不再有 `auto`，不会按 tier 自动换版）。带 `character` / `cardVariant` / `pairedNodeId` 的卡会被换成同角色对应版本；找不到配对会 warning 并按原卡使用。跨会话资产 id 需要两版都有 `character` / `cardVariant` 元数据，或先 `asset_to_canvas` 物化两版再传节点 id。

- **这条只管角色卡。场景卡与道具卡仍是单视图**——多视图对这两类资产在非 `fast` 档**无实测依据**，不随档位放开（见 STEP 4 / 4.5）。
- **单视图在所有档位都合法、且一直最稳**：所以「先 `fast` 走通全片再升档」时，fast 用单视图；升到 balanced / quality 后按 STEP 0 的选择用 single 或 three。
- **非 fast 档的回退规则**：`balanced` / `quality` 生成后，自检若发现**参考图形态类**问题——多出角色副本、参考图的版面 / 文字 / 分格结构被印进画面、环境被参考图内容替换——先用 **`ref_variant='single'`**（或把 ref_nodes 换成同角色**单视图卡**）+ 同一份 prompt（优先同 seed）重渲；仍不过再走 prompt / 时长等失败阶梯。**不要用 prompt 声明「只出现一只」来压**（实测无效）。
- 反过来（项目选的是 three、该镜临时降到 `fast`）时，G-ref 门禁立即生效：该镜**必须** `ref_variant='single'`（或直接传 single 卡）。
- STEP 0 的「角色卡引用版本」选项卡**必须按视频档位收窄选项**：fast 只给单视图；balanced / quality 给单视图 + 三视图（推荐）。三视图先出、单视图从它裁出来（所以两版一定同源），**这个选择只决定视频引用哪一版**。

### 1.1 双版本的一致性要求（按构造，不靠"两次生成碰运气"）

- **单视图是三视图正面格的 1:1 裁切**（`image_crop`，不重绘、不采样）⇒ "两版是同一个角色"这件事**按构造成立**：不需要同 seed，也不需要并排比对像不像。
- 要查的换成**裁切边界**：正面格没把相邻格（侧面 / 背面）的头发、衣袖、裙摆或分隔灰带带进来，也没把正面人物裁掉一部分（贴边到脚 / 手）。带脏了就调 `panel` 或显式矩形重裁，**不要重出三视图**。
- 反过来：**三视图不过自检，单视图一定跟着废**（单视图不能单独修）——三视图本体是三格 / 全身含脚 / 零文字 / 无分隔线的**唯一关口**。
- 复用资产库卡片时先看 `cardVariant` / 标题后缀：库里可能只有单版（历史资产）。只有单版时：单视图可用于任何档位；只有三视图时，fast 档不合规（走 G-ref 四出路），非 fast 档照常可用。

### 2. 参考图形态的档位风险（实测矩阵）

| 档位 | 多主体参考图（三视图 / 一图两身体 / 角色卡 / 设定图） | 实测表现 |
|---|---|---|
| `fast` | ❌ **必出问题** | 泄漏样式不固定：多出人（一图两身体 → 3 个、角色卡 → 5 个）、内容被投影成背景墙纸、环境被换掉材质 |
| `balanced` | ✅ 实测干净 | 角色卡 / 一图两身体 / 综合设定图，均只出 1 个角色 |
| `quality` | ✅ 实测干净 | 三视图（3 个身体）只出 1 个角色，首/中/末帧全干净 |

### 3. 门禁 G-ref（仅 `fast` 档；渲染前强制）

判定键是**每次调用实际传入的 `tier`**，**不是 STEP 0 那一次选择**——本流程允许「先 fast 走通全片再升档」与「本镜临时改档」，只按 STEP 0 判会漏。

`tier=fast` 时，每一个将要进 `ref_nodes` 的图片节点必须**同时**满足：**单主体、单视图、零文字、无拼图**。判定方式：用当前模型自身视觉读图核对（当前模型不支持图片输入时回退 `describe_image`）。任一不满足 → **不渲染**，出选项卡：

1. **升到 `balanced` / `quality` 按原图渲染**（推荐——多视图参考图在 balanced/quality 实测干净）
2. 换成单视图卡（新建或复用）后重渲
3. 用户手动裁图上传单视图
4. 放弃该参考图（纯文本生成）

**门禁落点**：STEP 3 / 4 / 4.5 复用库内资产前 → STEP 5.5 第 11 项（规划期预检）→ STEP 7「渲染前的门」组装 `ref_nodes` 前 → 门 3 自检留痕（fast 档镜须写明 G-ref 已过）。

**完整证据、实验矩阵与结论强度见 `references/reference-image-contract.md`。**

## 提示词分档持久化（prompt bank，全档位共用 quality 提示词）

**每镜一份画布文本节点**（group `shot prompts`，标题如「S01 提示词（分档）」），用 `canvas_write_prompt_bank` 写入三段提示词。**当前策略：三档使用同一份完整的 `quality` 提示词，逐字一致。**

| 段 | 写什么 |
|---|---|
| `## fast` | 与 quality 段**完全相同**的完整提示词 |
| `## balanced` | 同上 |
| `## quality` | 完整 quality 提示词（唯一源头） |

**硬规则**

- **只维护一份 quality 文案**：先把本镜的完整 quality prompt 写好，再原样复制到 `fast` / `balanced` / `quality` 三段；**不要**为 fast / balanced 另写精简版。
- **为什么三档同文**：这样换档只改变采样预算，不引入 prompt 差异；升档 / 降档 / 做档位对照时变量干净，也不会出现「fast 段和 quality 段不是同一镜头计划」。
- 生成时**传 `prompt_node`、不传 `prompt`**：工具按本次实际 `tier` 取段；因为三档同文，实际读到的都是同一份 quality 文本。缺段回退规则仍存在，但正常流程不会触发。
- **升档重渲直接复用同一个 `prompt_node` + 新 `tier`**（或同一视频 nodeId / 同标题且不传 prompt，工具会按标题 + 分组找回该镜提示词库），不要手抄旧 prompt。
- 工具生成后会把本次实际使用的 prompt **回写该档段**（幂等）。只传 `prompt` 也能用：视频工具会自动创建 / 更新提示词库节点并返回 `promptNodeId`（`persist_prompt:false` 可关闭）；后续升档用这个 id 即可。
- 镜头表 / 分镜修订导致本镜计划变化时：**先改 quality 源文本，再把同一份同步到 fast / balanced 两段**，然后重渲；不要只改一次调用的 prompt 而不落库。
- 提示词库是**过程产物**，不放进交付清单、不作为自动送达的交付物；节点正文可读、可人工编辑。
- **来源留痕（建议，非门禁）**：`canvas_write_prompt_bank(..., note="source-shot-table: <表格节点标题或 id> · source-storyboard: <分镜节点标题或 id> · prompt-version: vN")`。**必须写在 `note`（`## fast` 之前）**——`note` 在每次生成回写时原样保留；写进 `## quality` 段会被当成 prompt 原文发给模型。历史 / 复用提示词库没有 provenance 不阻断渲染。
- 如果以后要恢复「按档位不同密度」，把对应段改成不同文案即可；工具本身支持，但本 Skill 的当前策略是**全档同文**。
- **旧提示词库迁移**：如果画布上已有旧版三档不同文案的 `SXX 提示词（分档）`，先用 `canvas_get_prompt(nodeId, tier="quality")` 读 quality 段，再用 `canvas_write_prompt_bank(nodeId=…, prompts={fast: q, balanced: q, quality: q})` 把三档统一，然后才生成；不要直接沿用旧的三档不同文案。

## 实测 prompt 铁律：形态正向构造（STEP 3 / 5 / 7 引用）

以下铁律由插件 AV 视频模型实测沉淀（13+ 版否定堆叠失败后一次突破，之后全程稳定）。角色卡形态描述（STEP 3）、镜头表对白规划（STEP 5）、逐镜 prompt 组装与失败重试（STEP 7）都按此执行。**字幕写法的规范不在这里**，见下方「字幕与画面内文案：本节不定义写法」。

### 铁律一：角色形态用「正向生物构造描述」，不用否定堆叠

原理：模型对否定词执行力很弱。`NO front legs / NO arms / NO hands` 这类命令式否定会被理解成"有东西要避免"的暗示，反而按默认角色模板（四肢齐全的"可爱小生物"）补全缺失附肢；否定词堆得越多，越像在强调"可能长四肢"。正向构造描述给出"这个物种本来就只有这些零件"的完整解剖图景，模型跟随"长什么样"而非"不要长什么样"。

**成功写法六要素**（按顺序组织成一段）：

1. **整体形状词** — 先定义它是"一个什么形状的单一整体"：`its head and body are ONE seamless pear-shaped unit`。
2. **比喻锚点** — 调用模型已有的视觉原型：`like a smooth dark pebble with a face`（亦可 `like a small dark pearl with a tail`）。
3. **部位间关系** — 头身一体而非拼接：`no seam, no neck, no shoulder between head and body; the whole front surface is one continuous smooth curved skin`。
4. **唯一附肢清单** — 用"唯一"正向锁定数量与生长位置：`its only limbs are TWO short thick bent hind legs with small round toes growing from the lower rear of its body`。
5. **解剖总括句** — 结尾锁定总数：`Its anatomy is exactly: one pear-shaped head-body, two hind legs, one tail — that is all`。
6. **姿态即形态** — 让角色持续做该物种的自然行为（如连续游动巡游）；静止悬浮时模型容易把它"补全"成标准生物。

配套纪律：正文一次也不出现"它可能长前肢"类暗示；必须出现的否定词收敛到 prompt 末尾一行；成长阶段（形态 A/B/C）各阶段独立写清解剖清单，阶段切换 = 换状态卡 + 换描述，绝不在镜头内变形。

### 字幕与画面内文案：本节不定义写法（只有指针）

**写法、失败写法、容量 / 拆镜阈值、档位与实现口径，一律以 `h3-prompt-writing` 的「字幕与画面内文案（唯一权威版）」为准**——本节及本 skill 其它位置都**不复述、不简化、不另立策略**（简化版漏限定词 → 字幕整段不烧，是已实测缺陷）。

**要不要字幕是 STEP 0 的用户选择**（`burned-in` 要 / `none` 不要）：本流程**没有后期字幕轨**（不做 .srt 叠加、也不做后期烧录），所以「不要字幕」= 成片里彻底不出现字幕。选 `none` 时片型侧**不写任何字幕声明**（连下面的定稿句式也不用）、`<d>…</d>` 对白照写，只在逐镜 prompt 的负向尾句留 `no subtitle`——**「不写声明」是主机制，负向只是兜底**。这一项只管**字幕**，不管片内本来就该出现的招牌 / UI / 品牌文案（那是 `h3-prompt-writing` 的「画面内文案」，同源同法但是另一个开关）。

片型侧在本流程里只负责三件事（都在下面的步骤/门里）：

1. **数据**：镜头表 `字幕` 字段填本镜要渲进画面的字幕文本（即台词本身），`silent` 镜写 `none`，**项目字幕选 `none` 时全表写 `none`**；选 `burned-in` 时字幕文本与对白原文逐字一致（STEP 5.5 自检）。
2. **抽查**：门 3 自检对**有对白（含字幕）的镜**抽说话窗帧，核对字幕文字；**字幕选 `none` 时同一帧改为核对「画面里没有任何字幕 / 烧录文字」**。
3. **处置**：抽查不过 → 交用户选择 **重新生成本镜 / 升档重渲**（见门 3）；字幕已关闭却冒出字幕，同样算不过。

**自检速查**（角色 prompt 送出前过一遍）：

- 形态：整体形状词给了吗？比喻锚点有吗？唯一附肢清单列了吗？总括句锁定总数了吗？还有否定堆叠 / "可能长前肢"暗示要删吗？

> **链式能力取决于选中的实现**：有些实现**支持续接**（产物可作下游 `continuity_from` 的源，自己也能传 `continuity_from`），有些不支持（**不能作续接源**，下游接它会报「上一镜没有链式序号」）。r2v 与 i2v 两种形状都各自有支持续接的实现——**当前哪些可用用 `comfy_list_workflows` 查，不要凭 id 猜**。

## STEP 3：角色卡（先出三视图 → 裁正面格当单视图）

先 `asset_list(type=character)` 查库；命中复用就 `asset_to_canvas(id=资产 id)` 把卡片物化到画布（复用的卡也必须在画布可见）。**物化前先看 `cardVariant` / 标题后缀确认版本**：库里可能只有单版（历史资产）。

**新建角色一律"一张三视图 + 一次裁切"**，理由是一致性按构造成立：单视图不是第二次文生图，而是从三视图**正面格里 1:1 裁出来**的（`image_crop` 不重绘、不采样）。顺序固定：

1. `comfy_generate_image(..., card_variant="three")` 出三视图横排（16:9，1×3 正 / 侧 / 背）；**显式传 `width`/`height`、不继承影片比例**；
2. 跑下面的「角色卡 AI 自检」核三视图本体；
3. 自检过 → `image_crop(image_node=<三视图节点>, panel=0, panels=3, character=…, card_variant="single", paired_node_id=<三视图节点>)` 裁出正面格；
4. 核单视图（左右边缘无相邻格残留）→ 两版齐活，弹「锁定」选项卡。

两版尺寸（都按**图片档位**长边推导、32 对齐；三视图显式传，单视图由裁切自动得出，不要再手填）：

| 版本 | 形态 | `fast` | `balanced` | `quality` |
|---|---|---|---|---|
| `three` | 三视图横排（正 / 侧 / 背全身，1×3，16:9） | 1024×576 | 1344×768 | 2048×1152 |
| `single` | 正面格（= 三视图宽的 1/3，比例 ≈0.59） | 341×576 | 448×768 | 682×1152 |

- 三视图走 **16:9 横版**：三格等宽、每格一位角色全身（**头顶到脚底都在框内**），格与格之间靠纯底留白分隔——不画分隔线、不写任何标注。
- 单视图 = `image_crop(panel=0, panels=3)`：**零重绘**，所以"两版是两个人"这类问题在结构上消失；代价是分辨率约为整张的 1/3（`quality` 682×1152 ≈ 0.79MP，低于历史 2:3 独立单视图的 1344×2016），但人物占画面比例更大，作 `ref_nodes` 够用。**别再按旧表的 2:3 尺寸去生成单视图**。
- **形态不跟图片档位走**：图片档位只换采样尺寸；两版都出，不按项目视频档位只出一版。
- **旧资产兼容**：库里已有的 2:3 独立单视图卡继续合法可用（全档）；某角色只有单视图就不必回填三视图；只有三视图时先裁一版单视图即可（`fast` 档本来就不能用三视图）。
- 只在抽卡试构图时临时降到 `fast` 的产物**不得直接锁定**——锁定前用选定档位重出三视图并重裁。

生成调用示例（两次调用，第二次用第一次返回的节点 id 作 `image_node` / `paired_node_id`）：

```text
comfy_generate_image(prompt=<角色设定 + 正/侧/背三格 + 锁 A/B>, tier=<图片档位>,
                     width=…, height=…, character="Mia", card_variant="three",
                     title="Mia 角色卡·三视图", group="character cards")

image_crop(image_node=<上一步 nodeId>, panel=0, panels=3,
           character="Mia", card_variant="single", paired_node_id=<上一步 nodeId>,
           title="Mia 角色卡·单视图", group="character cards")
```

> **不要单独修单视图**：它是裁出来的。三视图不合格（三格不是同一人 / 少一格 / 有分隔线 / 脚被切 / 有文字）就重出三视图、再重裁。历史做法"两版各自文生图 + 同 seed + 文本锁"已废弃——同 seed 不保证跨画幅一致，实测会出现换发型 / 加配饰。

三视图本体（两版共用的唯一素材）的硬性要求：

- **画面内不得出现任何文字**（角色名 / 视图标注 / 道具标签 / 水印 / 分隔线一概不画）。
- **背景纯净**（浅灰或纯白），只有角色本人；**恰好三格**、三格同一角色、正 / 侧 / 背可辨、三格姿态不重复、每格一人**全身含脚**，无第四格 / 额外身体 / 剪影 / 镜像。
- 角色定位、签名道具、年龄段、身材、发型、服饰色、不可改特征、`speaks_on_screen` 等标注信息**只写在画布节点标题与描述里**，绝不画进图内。
- **同一角色的不同着装状态分别建一对状态卡**（如「不穿宇航服 / 穿宇航服」），每对仍是「三视图 → 裁正面」；标题用统一角色名 + 状态 + 版本后缀。
- **记录 seed**：生成后把 seed 写进节点描述，需要微调重出时复用同一 seed（保三格同人 + 减少抽样漂移）。
- **非人形 / 非常规解剖角色**（如「圆头无颈 + 两条后腿 + 一尾」的蝌蚪类生物）：形态一律按「实测 prompt 铁律一」写**正向构造清单**（整体形状词 → 比喻锚点 → 部位关系 → 唯一附肢 → 解剖总括句），卡 prompt、节点描述与后续镜头 prompt 共用同一份正向解剖描述；**禁止否定堆叠**——`NO front legs / NO arms / NO nubs` 类写法实测会让模型按"四肢齐全小生物"模板补全缺失附肢，否定堆得越多越糟。成长阶段（形态 A/B/C）各建一对独立状态卡，每张卡独立写清该阶段解剖清单；阶段切换只靠换状态卡 + 换描述，绝不在镜头内变形。
- **所选风格文件的风格锁后缀与负向约束必须带上**（见「视觉风格」节；角色卡用**锁 A + 锁 B**，后缀追加到每次生成的 prompt 尾部）。

### 角色卡 AI 自检（自检点 1：三视图本体 + 裁出的单视图，强制）

出「锁定」选项卡之前，AI 必须先用当前模型自身视觉读生成图自检（当前模型不支持图片输入时回退 `describe_image`），任一不过不许交人工：

1. **三视图本体**：恰好三格、同一角色；正面 / 侧面 / 背面可辨且三格姿态不重复（不是镜像复制）；每格一人全身**含脚**（脚被切 = 裁出来的单视图也跟着缺脚）；格与格之间靠纯底留白分隔，**没有分隔线 / 边框 / 投影**；无第四格 / 额外身体；零文字。
2. **裁出的单视图**：正面、单主体、全身含脚；**左右两侧没有相邻格的残留**（侧面格的头发 / 衣袖 / 裙摆越界，或分隔带的灰边）；零文字、纯底。
3. **裁切边界（取代旧的"跨版本并排比对"）**：单视图就是三视图里的同一批像素，所以要查的是**裁得对不对**——没带进旁格内容、也没把正面人物裁掉一部分。带脏 / 残缺就调 `panel` 或显式矩形重裁，**不重出三视图**。
4. **与角色设定标注一致**：对照节点标题与描述里的定位逐项核对画面；着装状态与目标状态卡一致；整体符合**所选风格锁**（见 `references/styles/<id>.md`）。
5. **失败处置**：三视图不过 → 复用同 seed 微调、或修订节点描述后**重出三视图并重裁单视图**；单视图不过（裁到旁格 / 构图被切）→ 只调裁切矩形重裁。**未过自检的卡不得弹「锁定」选项卡**。资产库物化复用的卡为历史已锁定版本，无需重检（但若明显缺腿缺脚 / 带旁格内容，必须向用户说明并按需重裁）。

自检通过后出选项卡：锁定角色设计（两版）并继续（推荐）/ 重新生成三视图（单视图会跟着重裁）/ 只调裁切矩形重裁单视图 / 调整具体视觉细节 / 增加另一张角色卡。

锁定后提示用户：想跨会话复用就在画布点该卡的「入库」按钮人工登记（AI 不自动入库；两版分别入库，标题带版本后缀）。同时警告：后续修改已锁定的角色设计会连带重做镜头表、分镜与已渲片段。

## STEP 3.5：声线（按模式）

- **单片**：读 `references/voice-audition.md`，按 3.5.1–3.5.5 执行（试镜 → 抽声线 → 听核 → 入库 → 声线清单）。
- **剧集单集**：不重跑试镜；从台账 `voices[]` 取 `voice:`（`assetMode=library` 时必须是 `voice:`，不能只用 canvas 节点）；缺 id 才回阶段 C 补，不在本集重抽。

## STEP 4：场景卡

先 `asset_list(type=scene)` 查库，命中就 `asset_to_canvas`，未命中才生成。**场景卡只展示环境，不出现人物、人群、剪影、手、脸或角色客串，画面内同样零文字。** 角色动作属于镜头表、分镜与视频片段。**场景卡用单视图**（一个环境视角；需要多个角度时逐张单独生成，不要拼成多格场景卡——多格在 `fast` 档会出副本或污染画面）。**场景卡不随视频档位改形态（始终单视图）**：三视图横排的档位默认**只适用于角色卡**（见「参考图形态与档位」§1），场景卡的多视图在非 `fast` 档无实测依据。**复用库内资产前同样要先核形态（G-ref）**：多角度场景卡在 `fast` 档不合规。**风格上用「锁 A · 渲染基调」+（该风格若拆出 C 段则再加「锁 C · 环境与氛围」），不带锁 B**——B 段的角色 / 表演条款会把人物拉进空场景（见「视觉风格」节）。

**新建场景卡一律用 STEP 0 的图片档位并显式传 `tier=`**（默认 `balanced`）；抽卡降档的产物必须在锁定前重出定稿。

包含：主环境总览；关键光态（日景 / 夜景）；情绪子空间；**连续性地标**（同场景跨镜头必须保持屏幕位置的固定物体，如厨房中岛、沙发、门框、树、邮筒）；环境中的重要道具。地标名与位置写在节点描述里，供镜头表的 `参考锚点` 列直接引用。

### 场景卡 AI 自检（自检点 2：生成后、交人工前，强制）

每张**新建**的场景卡生成后、出「锁定」选项卡之前，AI 必须先用当前模型自身视觉读生成图自检（当前模型不支持图片输入时回退 `describe_image`），任一不过不许交人工：

1. **参考图硬规则合规**：画面内零文字；只展示环境，无人物 / 人群 / 剪影 / 手 / 脸 / 角色客串。
2. **与场景设定一致**：主环境布局、关键光态（日景 / 夜景）、情绪子空间与节点描述一致；镜头表 `固定地标` 列要引用的地标真实存在、屏幕位置可读、未被杂物遮挡；整体符合**所选风格锁**。
3. **失败处置**：任一不过 → 复用同 seed 微调重出或修订节点描述后重出，重跑本自检；**未过自检的场景卡不得弹「锁定」选项卡**。资产库物化复用的卡无需重检。

自检通过后出选项卡：锁定场景设计并继续（推荐）/ 重新生成场景卡 / 增加另一个场景角度 / 调整光位或布局。同样提示人工入库。

## STEP 4.5：道具卡

签名道具（反复出现、承担叙事功能的物件）单独建卡，避免逐镜只靠文字描述导致形状 / 材质漂移。

先 `asset_list(type=scene)` 查库——**注意：资产库没有 `prop` 类型**，道具卡入库时只能归到 `character` / `scene` / `style`，**推荐 `scene`**（id 形如 `scene:prop-<name>`），所以库里拿到的 `scene:` 资产不一定是环境卡，**要用节点标题与描述确认**。命中就 `asset_to_canvas`（`fast` 档同样先核形态），未命中才 `comfy_generate_image` 新建。

每张道具卡的硬性要求：

- **单件道具、单视图、纯色背景、画面内零文字**。`film-assets` 那边道具卡默认是「摄影机位环绕多视图」；**本 Skill 一律收编为单视图单件**——多视图拼图在 `fast` 档会出副本或污染画面（见「参考图形态与档位」），且道具的多视图在非 `fast` 档**无实测依据**，**道具卡不随档位改形态**。确需多角度时**逐张单独生成**，分别放进不同 `ref_nodes` 槽位。
- 只画道具本身：不出现人物、手、脸、人群、剪影，也不带场景环境。
- 道具的形状、比例、材质、配色、磨损特征写进节点描述，供镜头表 `固定地标` / `绑定` 列引用。
- **所选风格文件的风格锁后缀必须带上**——道具卡**只加「锁 A · 渲染基调」，不带锁 B / 锁 C**。

**新建道具卡一律用 STEP 0 的图片档位并显式传 `tier=`**（默认 `balanced`）；抽卡降档的产物必须在锁定前重出定稿。

### 道具卡 AI 自检（自检点 3：生成后、交人工前，强制）

每张**新建**的道具卡生成后、出「锁定」选项卡之前，AI 必须先用当前模型自身视觉读生成图自检（当前模型不支持图片输入时回退 `describe_image`），任一不过不许交人工：

1. **参考图硬规则合规**：单件道具、单视图、纯色背景、零文字；无人物 / 手 / 脸 / 人群 / 剪影；无多视图拼图。
2. **与道具设定一致**：形状、比例、材质、配色与节点描述逐项一致；整体符合**所选风格锁**。
3. **失败处置**：任一不过 → 复用同 seed 微调重出，或修订节点描述后重出，重跑本自检；**未过自检的道具卡不得弹「锁定」选项卡**。资产库物化复用的卡为历史已锁定版本，无需重检。

**道具卡是可选产物**：只在道具是叙事关键且**反复出现**时才建卡并进 `ref_nodes`（每张卡占一个参考槽位）；单次出现的小道具写进镜头描述即可。**单镜 `ref_nodes` 数量 >2 的形态未实测**，加了道具卡就优先在 `balanced` / `quality` 档生成。

自检通过后出选项卡：锁定道具设计并继续（推荐）/ 重新生成道具卡 / 调整材质或配色 / 不要道具卡（改用文字描述）。

## STEP 5：七列标准镜头表

角色卡与场景卡锁定后，用 `canvas_write_node(kind=table, group="shot table")` 输出标准化镜头表。本步为强制步骤，不可与分镜或视频生成互换。

表格必须严格按以下顺序包含七列：

| 镜头编号 & 时长 | 连续性衔接 | 续接 | 参考锚点（空间+身份） | Hook 类型 | 镜头描述（每秒指令） | 音频与对白轨 |
|---|---|---|---|---|---|---|

列规则：

- **镜头编号 & 时长**：镜头号加计划时长，如 `S03 / 5s`。视频工作流按 24fps 帧数生成（124 帧 ≈ 5s），时长要能整除到帧。
- **连续性衔接**：本镜如何自然承接上一镜的结束画面、道具位置、眼神、姿态、声桥或情绪状态；以及本镜如何为下一镜开篇铺好钩子。这是跨镜连续性主链。
- **续接**（**规划分镜时就必须填，不许留到生成阶段现编**）——本镜**怎么获得画面连续性**，只允许四个取值：
  - `起链`：**场景第一镜**，以及**换场景后的新场景第一镜**（不与上一镜共享画面/音频，独立起头）。
  - `接 S0x`：**同场景内的后续镜**（接相邻的上一镜）——链式续接，`continuity_from=上一镜节点 id`。
  - `硬切`：**同场景内刻意硬切**（时间跳 / 视角重置 / 蒙太奇）——不传 `continuity_from`，但必须在 `连续性衔接` 写明 `HARD CUT — 原因`；跨场景仍只能走转场镜，不能用硬切代替。
  - `锚定 S0x↔S0y`：**跨场景转场镜专用**——i2v 双端锚定，首帧取前一场景尾镜 `S0x` 的末帧、末帧取下一场景首镜 `S0y` 的首帧，收尾精确落回 `S0y` 首帧。两种做法可选：**续接版**（+ `continuity_from=S0x`）额外继承 `S0x` 的尾部画面与音频（**此时首帧锚点会被丢弃**，末帧锚点保留）；**普通双端锚定**则是经典做法（画面从这张静帧起步）。规划时按需二选一并写明。
  - 硬约束：一条链内**首遍尺寸一致**（≈同档位：`fast` 832×480、`balanced`/`quality` 1344×768；交付尺寸可以不同）；`接 S0x` 的 S0x 必须是**相邻的上一镜**，不许跳镜接；**跨场景不直接续接**（跨场景的连续由转场镜承担）；标 `锚定 S0x↔S0y` 的镜，两个邻居都必须**已批准、已存在**（要抽它们的帧），且转场镜与全片**同档同分辨率**。
- **参考锚点（空间+身份）**：五个子字段全部必填。
  - `固定地标` — 来自场景卡的确切命名地标及其画面相对位置（如 `door-frame: 右侧 1/3`、`kitchen-island: 底部居中`）。
  - `人物位置（机位视角）` — 每个在屏角色的画面相对位置（左/中/右、上/中/下、前/中/后景）、朝向、初始姿态。
  - `退场人物状态` — 上一镜有但本镜没有的角色，记录离屏位置和原因（如 `Mia — 离屏左侧，最后出现于门框旁手持苹果筐`）。
  - `光位基线` — 从场景卡继承的主光/补光/轮廓光方向，加本镜调整项。
  - `绑定` — 精确的角色卡节点/资产 id + **本镜引用版本**（`Mia·single` / `Mia·three`；按 `state.characterCardVariant`，`fast` 镜强制 `single`）+ 场景卡节点/资产 id + **道具卡节点/资产 id（仅本镜有签名道具时）**。角色卡写节点/资产 id 即可，版本由 `ref_variant` 显式传入；场景卡与道具卡仍是单视图。**本 Skill 全镜参考绑定（`ref_nodes`），没有例外**：身份与环境永远由角色卡 + 场景卡保证；**续接只负责「接着往下走」，不负责认人**（角色换状态/换装、新角色登场都不影响续接资格）。
  - `背景人物` — **本镜画面里除绑定角色外的人**：没有就写 `无`；有则写 `exactly N` + 坐/站 + 衣色 + 虚化（例：`exactly 12，坐席，十二色衣，柔焦，不露脸`），进 prompt 的 `detailed_description`。**写 `exactly N`，不要用 `completely empty` 这类与「有人」自相矛盾的措辞**。字段本身**未单独实测**，只解决「prompt 没写、模型自由发挥人数」的信息缺口，不进任何门。
- **Hook 类型**：受控词表取一：`setup` / `visual-joke` / `reversal` / `reveal` / `callback` / `suspense` / `tender` / `chase` / `expression-beat` / `climax`。
- **镜头描述（每秒指令）**：景别、镜头运动、荷兰角设计、表演风格、音效、负向提示，并强制包含 `Per-Second Directives` 子节：按秒拆解 `0–1s`、`1–2s`…，亚秒关键节拍用 `2.0–2.5s` 标记。**单元格首行必须是 `剧本依据: B0x[, B0y]`**（回指 STEP 2 故事大纲的 beat 编号；拆镜时同一 beat 可被多镜引用）。每条每秒指令必须覆盖 5 个要素：
  1. 动作 / 姿态 / 表情（含 squash-and-stretch、anticipation、overshoot、follow-through）
  2. 镜头运动（推 / 拉 / 摇 / 倾 / 手持晃动 / 锁定 / 环绕）
  3. 空间位置（人物在哪、持有什么、地标在画面哪里）
  4. 音频线索（对白 / 音效 / 呼吸 / `silent`）
  5. 与下一秒或下一镜的交接
- **音频与对白轨**：本镜完整音频脚本，按时间顺序，独立于每秒指令。字段：
  - `模式` — 本镜是 `dialogue` 还是 `silent`（可与项目全局模式不同，如对白片里的静默镜）。
  - `对白` — 台词、说话人、语气、时间范围。**一镜只允许一个说话人。**
  - `口型` — 逐秒记录嘴部开合；说话人 `mouth-open`，同镜其他角色 `mouth-closed`，`silent` 镜全员 `mouth-closed`。
  - `声线参考` — 本镜说话人的 `voice:<id>` 或 `canvas:<音频节点 id>`（来自 STEP 3.5 声线清单）；`silent` 镜或未做声线的角色写 `none`。同一角色全片必须同一个引用。
  - `音效` — 关键音效，按时间锚定。
  - `BGM` — `N/A`，或本镜 BGM 计划（`in: 0–3s, sparse solo piano, slow, low under dialogue; out: 4.5s fade`）。**只有 `bgmMode=in-model` 才写；`none` 全表 `N/A`**。逐镜写，H3 看不到整本剧本。
  - `字幕` — 本镜要渲进画面的字幕文本（即台词本身，不加引号/书名号/括号）；`silent` 镜写 `none`；**项目字幕选 `none` 时全表写 `none`**（见 STEP 0）。
  - `画面文案` — 画面里**本来就该出现**的文字（牌匾 / 令牌 / 招牌 / UI，不是台词字幕）：`none` 或原文。**与 `字幕` 分开**：字幕走 `h3-prompt-writing` 的对白联动写法，画面文案走同一节的「画面内文案」写法（`reading exactly "…"`）；**项目字幕选 `none` 时，画面文案仍可单独声明**。字段未单独实测，只补数据缺口。
  - `表演备注` — 每条对白对应的眼神与身体动作变化。

表格全局规则：

- **`剧本依据` 是强制字段**：每镜 `镜头描述` 首行写回指的 beat 编号；没有 beat 编号的镜头表不得进入 STEP 5.5（先回 STEP 2 给大纲编号）。
- 每镜必须通过 `连续性衔接` 列自然继承上一镜画面状态，并为下一镜铺垫。
- 每秒指令必须具体到可直接生成分镜面板；避免「继续移动」这类缺少身体/镜头/道具细节的模糊描述。
- 表演必须夸张弹性，符合 squash-and-stretch、anticipation、overshoot、follow-through、overlap、弧线、快速姿态变化和清晰喜剧剪影。
- 景别必须在特写 / 大特写与其他景别间交替；避免重复景别。
- 荷兰角构图为追逐、失衡、惊吓或闹剧节拍设计。
- 台词语言仅在用户明确要求时使用；否则用最小化非语言反应或把台词标记为待确认。
- 已离屏角色在 `退场人物状态` 至少记录 1 镜，连续 2 镜明确不在场后再移除。
- 对白句长与镜头规划绑定：**句长容量与拆镜阈值按 `h3-prompt-writing`「字幕与画面内文案」§3 执行**（超限就拆成相邻两镜、每镜一句短对白）。拆镜 = 本表改行/拆行 + Step 5.5 自检重跑。

**签名道具写法（实测：无道具卡时有效）**

- **能建卡就建卡**：被手持 / 特写 / 承担剧情的道具，优先建道具卡进 `ref_nodes`（顺序：角色 → 场景 → 道具；总槽位先按 ≤3 用，`refs.max` 上限是 8，>3 未实测）。
- **无卡时写「形状 + 唯一特征 + 三条否定」**：A/B 实测（同 seed、只改这一句）——只写 `a small jade plaque` 出的是**圆头指状玉条/小瓶**；补成 `a flat rectangular jade plaque with a chipped upper-right corner, not a bottle, not an orb, not a cylinder` 后变成**带缺角的矩形玉牌**。极端形状再加 `as thin as a coin` / `held face-on to the camera`（边际改善）。
- **只对无生命道具用否定**；角色解剖仍按「铁律一」正向构造（解剖类否定堆叠会补全缺失肢体，已实测）。
- **道具句只放在「道具就是主体」的镜**（特写 / 递物 / 读牌）：实测加道具句会把镜头推成特写、劫持原计划景别；全景群戏里别塞。
- 未按上述处理的道具，**不要写「手持某物」**（模型会自由发挥）；改为「拳心半露」或只拍手部动作。

选项卡：批准表格并进入自检（推荐）/ 调整镜头连续性 / 让动画更夸张 / 调整特写节奏 / 调整荷兰角设计。

## STEP 5.5：镜头表自检门（强制）

进入分镜前必须对已批准的镜头表跑硬性自检。任何一项不通过必须先修订表格再重跑。

十四项必检：

1. **Hook 密度**：每镜都有 `Hook 类型`；每连续 3 镜至少 1 镜使用 `reveal` / `reversal` / `callback`；开场镜和收尾镜各带强 hook。
2. **单镜时长**：任何镜头不超过 15 秒（视频工作流单次生成上限）。节拍需要更长就拆镜。
3. **单镜角色数**：任何镜头不超过 3 个重要角色（有画面动作或对白的角色）。
4. **空间锚点继承**：含 2 镜以上的同场景，下一镜的 `固定地标` 与 `光位基线` 必须与上一镜一致，或含明确连续性备注（如 `door-frame 随镜头左环绕由右侧 1/3 移至中央`）。
5. **每秒指令覆盖**：从 `0s` 到镜尾每秒都有指令，每条含 5 个必填要素；允许亚秒节拍但不能留时间空隙。
6. **跨镜连续性**：逐行读 `连续性衔接` 列必须形成连续链——任何一镜都不能从与上一镜结束矛盾的状态起步。翻转眼神、人物位置、道具状态或光位的镜头必须明确标记（如 `HARD CUT — 时间跳 2h`）。
7. **音频模式、口型安全与声线参考**：每镜 `模式` 与项目全局模式兼容；`dialogue` 镜有且只有一个说话人，同镜其他角色全程 `mouth-closed`；`silent` 镜无对白无字幕、全员 `mouth-closed`；**字幕选 `burned-in` 时**字幕文本与对白文本逐字一致，**选 `none` 时全表 `字幕` 列必须都是 `none`**（不得残留任何字幕文本）。**`声线参考` 列**：每个说话角色在全片必须指向**同一个** `voice:<id>`（或一致地 `none`）；填了 id 的角色必须已在 STEP 3.5 入库、且该镜 `模式=dialogue`。**方案联动**：声线方案为 `audition` / `existing` 时，`dialogue` 镜的 `声线参考` **不允许为 `none`**（缺 id 就是不过门），除非该角色在声线清单里被明确标为「仅文本音色」并记录了风险；`text-only` 时全表必须一致写 `none`。
8. **转场帧洁净**：每个**跨场景边界**的**前一镜最后 0.5s 必须无对白无字幕**。两种继承都会把烧录字幕带过去：**转场镜的双端锚定直接拿前一镜末帧当首帧**（字幕原样出现在转场镜开场）；**续接镜则继承上一镜最后约 22 帧画面（≈0.9s）连同 1 秒音频**（字幕被整段继承）。不满足就把该镜的对白往前挪，或在镜尾补一个无声反应节拍。**字幕选 `none` 时本项只剩「无对白」要求**（没有可被继承的烧录字幕）。
9. **续接链闭合性**（逐行核对 `续接` 列）：① 每个场景的**第一镜必须是 `起链`**；② **换场景后的新场景第一镜必须是 `起链`**（跨场景不得直接续接）；③ 标 `接 S0x` 的镜，S0x 必须是**相邻的上一镜**（同场景），不许跳镜、不许接非相邻镜；④ 上游镜必须是**支持续接的实现**渲染的（正片镜走 r2v 且该实现支持续接，天然满足；i2v 镜只有**用支持续接的 i2v 实现**渲的才可续接，普通 i2v 产物不算）；⑤ **同一条链内采样尺寸必须一致**（≈同档；交付尺寸可以不同）；⑥ 标 `锚定 S0x↔S0y` 的**只能是跨场景转场镜**（不插在同场景续接链中间），且 `S0x` 必须是前一场景**尾镜**、`S0y` 必须是下一场景**首镜**，两镜都必须**已批准且已入画布**（转场镜在正片全部批准后才做）；⑦ 标 `硬切` 的镜必须是**同场景**，且 `连续性衔接` 写明 `HARD CUT — 原因`（跨场景硬切不合法，用转场镜）。
10. **续接可行（前 1 秒仍在上一镜尾里）**：标 `接 S0x` 的镜，**开场约 0.9–1s 的画面与声音仍然是上一镜结尾的延续**（latent 已钉住它），所以：① 本镜的 `连续性衔接` 必须与上一镜结尾的**运动方向、光位、姿态、音量**接得上（上一镜怎么动，本镜就从这个动势接着走；要转变就在本镜内完成转变）；② 本镜若要有**上一镜结尾没有的角色 / 道具 / 字幕登场**，该登场必须安排在**第 1 秒之后**（每秒指令里写明），不能要求一开场就出现；③ 真的需要「开场立刻是全新画面」时 → 同场景标 `硬切`（写明原因），场景第一镜标 `起链`。
   标 `锚定 S0x↔S0y` 的转场镜不适用本项（它不续接 latent），改按第 8 项（前一镜末帧无字幕；字幕关时自动满足）+ 第 9 项⑥（两邻居已批准）核对。
11. **角色卡双版本与参考图形态合规（按 STEP 0 选择 + 每镜实际档位）**：先确认每镜的 `绑定` 列选对了角色卡版本——**`fast` 镜必须绑单视图（single）；`balanced` / `quality` 镜按 `state.characterCardVariant`（用户 STEP 0 选择）绑 single 或 three**。`fast` 镜还要逐一核对**每一张**卡是否单主体 / 单视图 / 零文字 / 无拼图（库内复用来的三视图卡、多角度场景卡、多视图道具卡都在这里标出来）。不满足就先解决再进 STEP 6：把该镜升到 `balanced` / `quality`，或把该卡换成单视图卡（双版本流程下直接换同角色的 single 卡即可，不需要临时补卡）。**规划期就拦，不要留到渲染前才发现。**
12. **剧本覆盖与台词逐字**（单片读 STEP 2 大纲的 `B0x`；剧集委托模式读集制作包 8 列的第 8 列「集内节拍」）：
    - ① **每个 beat 至少被 1 镜覆盖**：大纲里列出的 `B01…Bxx` 必须能在某镜 `镜头描述` 首行 `剧本依据` 里找到；有 beat 无镜 = 不过。
    - ② **每镜至少回指 1 个 beat**：`剧本依据` 不得为空、不得只写 `—` / `无`。
    - ③ **事件顺序与大纲一致**：允许合并相邻 beat 到一镜、允许一 beat 拆多镜，**不允许换序、漏事件或新增剧本外的主线事件**。
    - ④ **台词 / 字幕逐字**：`dialogue` 镜的 `对白` 与剧本原文逐字一致（只允许省略说话人前缀与时间标记）；字幕选 `burned-in` 时 `字幕` 与 `对白` 逐字一致，选 `none` 时 `字幕` 全写 `none`、但 `对白` 仍须逐字对齐剧本。
    - ⑤ **关键道具 / 信息揭示 / 情绪锚点**必须在某镜的 `镜头描述` 或 `参考锚点` 中被明确承接（不能只写在大纲里）。
    - 任何一项不满足 → 回 STEP 5 补行 / 改行后重跑本门；**剧本层改动必须先改大纲 beat（改号或加拍）再改表**，禁止只改表不改大纲。
13. **对白容量**：逐镜数字数——单镜单句 **≤16 字**（12–13 字逐字最稳），**≥18 字整句必须拆成相邻两镜**，每镜一句短对白。阈值与拆镜口径按 `h3-prompt-writing`「字幕与画面内文案」§3（本节不复述）。拆镜 = 改表 / 拆行 + 重跑本门。
14. **资产—设定一致性（实测驱动，规划期必查）**：逐镜核对「本镜要求的物 / 人 / 光 / 环境」与 `绑定` 的卡是否一致——**卡里有台座就按台座写、卡里是玉柱就是玉柱**。不一致只能走两条路：① **改卡**（重出场景卡 / 道具卡，或给关键道具建卡）；② **改镜头设定**。**禁止用 prompt 否定卡里的内容**：A/B 实测——在 prompt 里写 `no pedestal, no dais` / `plain dark timber post` 去否认场景卡里的玉柱与台座，模型前 1/3 仍按卡画玉柱、后 2/3 被文字掰成木柱，产生**镜头内形变**（比原问题更贵）；台座也只被削弱、没消失。卡里**没有**、但本镜必须出现的东西（手持道具、背景人数）才走 prompt（写法见 STEP 5「签名道具写法」）。

十四项全过后，在画布表格节点顶部加 `shot-table self-check: passed at <时间戳>` 戳，并出选项卡：批准自检并进入分镜（推荐）/ 查看自检详情 / 修订失败项 / 重新跑自检。

任何一项不通过就不进入 Step 6：返回 Step 5，列出失败行，修好并重跑自检通过后才能再次展示分镜批准选项卡。

## STEP 6：单文本分镜文档（默认）+ 铅笔分镜图（opt-in）

自检通过后先出分镜模式选项卡，再生成任何分镜产物：

- **单文本分镜文档（默认，推荐）** — 整片一份画布文本节点，所有分镜作为文档内章节。承载完整质控载荷，成本几乎为零，是 Step 7 的权威渲染参考。
- **单文本分镜文档 + 多宫格铅笔图（可视化模式，opt-in）** — 文本文档仍是权威产物，额外为每镜生成一张多宫格铅笔图供人眼审稿。成本更高，适合想在付视频成本前做一次视觉预演，或弹性表演 / 姿态剪影是高风险项的情况。

把选中的分镜模式记入项目简报，并在 Step 7 与重生成纪律里复用。

### 默认路径：单文本分镜文档

生成一个画布文本节点，命名 `<标题> text storyboards`（group `text storyboards`），一个文档包含所有分镜。

**文档头部块**：项目标题、画面比例、生成档位（视频）、图片档位、音频模式、分镜模式、自检状态戳；一段目录列出每镜的 hook、`续接` 状态（`起链` / `接 S0x`）与章节锚点（`S01`、`S02`…）。

**每镜章节结构**（每个 `##` 标题对应一镜，按镜头顺序，字段顺序固定）：

1. **镜头标题 & 时长** — 简短可读的标题 + `S<N> / <duration>s`。
2. **Hook 类型** — 受控词。
3. **场景 & 角色** — 精确场景卡名、精确在屏角色名（绑定到角色卡）。
4. **空间锚点卡**（强制，四子字段）：`固定地标` / `人物位置（机位视角）` / `退场人物状态` / `光位基线`。
5. **连续性**：`续接` — `起链` / `接 S0x` / `锚定 S0x↔S0y`（**必须与镜头表 `续接` 列逐字一致**）；`承接 S(N-1)` 一两句交代上一镜结束状态；`交接 S(N+1)` 一句铺好下一镜开场。标 `接 S0x` 的镜，`承接` 句必须写成「从上一镜结尾的某个具体动势/光位/音量接着走」；标 `锚定 S0x↔S0y` 的转场镜，写成「从 S0x 结尾的某个状态运动过渡到 S0y 的开场构图/光线」。
6. **双绑定** — `[char:角色名] [scene:场景名] [hook:类型] [audio_mode:dialogue|silent] [speaker:角色名|none] [cont:start|S0x|anchor:S0x>S0y]`。这些是分镜专用参考标记，**视频渲染时必须剥离**。
7. **每面板四象限内容**（按时间顺序，就是镜头表里的每秒指令原样保留）：
   - `时间码` — 如 `0–1s`。
   - `姿态 + 表情` — 具体身体姿态、剪影、关键持握、眼神、表情路径；弹性节拍明确写出 squash / stretch / anticipation / overshoot。这是最大块内容，也是视频模型读取的视觉节拍。
   - `镜头` — 景别、镜头运动、荷兰角备注。
   - `音频 + 锚点` — 音频线索（`对白: …` / `SFX: …` / `silent`）+ 空间锚点备注。
   - `表演备注` — 逐秒口型（`mouth-open: <说话人>` / `mouth-closed: all`）、表情路径、眼神与身体动作变化。
8. **布局规则**：3 秒镜 3 面板、4 秒镜 4 面板、5 秒镜 5 面板、6 秒镜 6 面板、7 秒及以上每秒 1 面板；亚秒关键节拍按需加迷你面板（如 `2.0–2.5s`），仅当该节拍是本镜核心 hook。面板必须覆盖整镜时长，首帧到尾帧无空隙。
9. **每面板绑定**：绑定表格行列出的精确角色卡（锁定外观、脸、发型、身材、服装、签名道具、身份）与场景卡（保留环境、道具、地标、运动路径、空间逻辑），角色名与表格一致。
10. **ASCII 布局块（推荐，零成本）**：每镜一张组合草图，让用户秒扫空间布局而不必渲染图。ASCII 仅供人看，视频模型读上面的结构化四象限内容。
11. **分镜专用标记**：关键节拍在时间码后加 `[BEAT]`；需要交接特定状态时加 `[HANDOFF → S04 opening]`。

每镜章节模板（复制粘贴骨架）：


### 按镜抽取（重点迭代模式）

单文档形态针对阅读和跨镜连续性优化。当用户标记某镜需要重点迭代（通常是 climax / 追逐 / 闹剧节拍）：

1. 新建画布文本节点 `<标题> S05 text storyboard (extracted)`（同组 `text storyboards`）。
2. 把文档中 `## S05` 章节完整内容移到新节点。
3. 文档中原章节替换为占位行：`> S05 — 已抽取到独立节点（见 <标题> S05 text storyboard (extracted)）`。
4. Step 7 渲染 S05 时从抽取节点读取；其他镜仍从文档读取。
5. **回填**：用户满意后把内容折叠回文档（占位换成最新内容），独立节点归档。

多镜抽取时各自独立成节点，文档里用占位追踪。

### Opt-in 路径：多宫格铅笔分镜图

仅在用户选了可视化模式时，额外为每镜用 `comfy_generate_image` 生成一张多宫格铅笔图（group `text storyboards`）。铅笔图仅供人眼审稿，**不作为视频渲染参考，不进 `ref_nodes`**（图内含文字与多个身体，违反参考图硬规则）。**铅笔图同样用 STEP 0 的图片档位并显式传 `tier=`**（默认 `balanced`）。

每张铅笔图：

- 面板物理排版：3 秒镜 1×3 条；4 秒镜 2×2；5 秒镜 上 3 下 2；6 秒镜 2×3；7 秒以上 3 排均衡。每面板占相同画布面积。
- 每面板四象限：左上时间码；右上姿态 + 表情草图（最大区域）；左下镜头图标 + 运动箭头 + 荷兰角备注；右下音频线索与锚点备注。
- 面板按阅读顺序排布，不同镜头不合并到同一图。
- 纯黑白铅笔线稿：不上色、不带最终渲染光、不带精致 3D 渲染。**铅笔图不受所选风格锁影响**（它始终是纯黑白线稿，不要给它套风格后缀）。
- 可含分镜专用标记：铅笔结构线、动作箭头、镜头路径图标、时间标记、镜头号与双绑定标签。

铅笔图失败回退阶梯（布局塌陷 / 标签糊掉 / 面板合并 / 角色走样）：
1. 第一次重试：更紧的提示重画同一镜，明确写上四象限布局与每面板内容规则。
2. 第二次重试：去掉右下象限文字（保留空白格），减少文字负载。
3. 第三次重试：面板数减 1（合并动作最弱的两秒），镜头图标简化为单箭头。
4. 同一镜连续 3 次失败：选项卡问用户——切色块分镜（灰块占位姿态）/ 放弃该镜铅笔图仅靠文本分镜推进 / 回 Step 5 把该镜拆成两段更短的镜头并重跑自检 / 手动提供参考图。

默认文本模式没有这套回退——文本分镜失败就直接回 Step 5 修订该行表格。

### 分镜批准

选项卡：批准分镜并渲染镜头视频（推荐）/ 抽取或回填某镜 / 重画选定铅笔分镜（仅可视化模式）/ 修复角色一致性 / 修复场景逻辑 / 修复镜头标记 / 修复音频与口型标记。

## STEP 7：逐镜视频生成

### 渲染前的门

分镜批准后，**默认不再弹渲染参数卡**（档位 / 审查节奏 / 交付画质已在 STEP 0 定）；只有用户主动要改其中一项时，才弹一张「改规格确认卡」。渲染前的读回与校验照做：

**先读回审查节奏**：`canvas_get_state()` 取 `settings.reviewMode`（缺省 `per-shot`）——它决定门 3 的人工确认是**逐镜**还是**批量**。**在渲染第一个片段之前读**，不要凭对话印象或默认值判断；读不到就按 `per-shot` 走并在回复里说明。

**同时读回逐镜自检门**：`settings.shotGate`（缺省 `verdict` = **开启**）。`verdict` → 每镜必须 `extract_frame` + `canvas_record_check(pass)` 才能进下一镜（插件 pre-execute 硬门）；`frames` → 每镜抽帧即可、不强制记录结论；`off` → 门 3 的逐镜 AI 自检关闭（人工确认与失败回退照旧）。读不到按 `verdict` 走并在回复里说明。

**生成档位（视频）**：沿用 Step 0 选择；只有用户要改时才在「改规格卡」里选（切 `fast` 走通全片 / 升到 `balanced` / `quality` / 本镜临时改档）。**逐镜调用必须显式传 `tier=`**（`fast` / `balanced` / `quality`），不要依赖缺省——缺省是 `quality`，成本最高。分辨率由画布 `aspectRatio` + 档位自动推导（`fast` 长边 832、`balanced`/`quality` 长边 1344），不需要单独选分辨率；用户要单镜 hero 画质时才显式传 `width`/`height`。

**片段审查节奏**：沿用 Step 0 选择；只有用户要改时才在「改规格卡」里选 `per-shot` / `batch`。**改了就 `canvas_set_state(reviewMode=…)`**（改 state 即生效，见 STEP 0 与门 3）。这一项只改人工确认的时机，AI 自检是否逐镜由 `shotGate` 决定。

**逐镜自检门**：沿用 Step 0 选择；用户要改时在「改规格卡」里选 开启（`verdict`）/ 只要求抽帧（`frames`）/ 关闭（`off`），**改了就 `canvas_set_state(shotGate=…)`**。从下一镜起生效：新渲的片段按新档打标 / 不打标（`off` 不打标 = 不参与门控）；已渲片段不重做。

**镜头表一致性门（代码强制，生成前自动跑）**：插件按 `title` 里的 `Sxx` 在画布镜头表里找到该行，校验：prompt 里台词 / 字幕与表**逐字一致**、`length/24` 与表时长一致（±1s）、`audio_ref_nodes` 与 `声线参考` 一致、显式 `width`/`height` 与画布 `aspectRatio` 一致、`fast` 档不得用三视图卡（`ref_variant=three` / 直接传 three 卡）。不一致会 deny 并列出差异（同一 agent 连续 deny 2 次后降级放行）。⇒ **每镜 `title` 必须带镜头号**（如「S03 片段」）；转场镜（「S03→S04 转场」）、锚点式重渲（标题含「锚点」）、试镜片段不参与；**新镜 / 拆镜必须先把行写进镜头表再渲**，否则会被判「镜头表没有该镜」。

**档位与能力可用性**：一个能力支持多档，**具体有哪些档、每档什么代价，以 `comfy_list_workflows` 为准**（不同能力可以不同，用户在设置页增删实现后也会变）——不要假设档位数量或名称。请求了该能力没有的档会**显式报错并列出可用档位**（工具不会静默换档）。遇到这类报错就改请求可用档位，**不要原样重试同一请求**。用户选的**交付画质**若是「生成内放大」，要在选档时确认该档解析到的实现确实出高分辨率（显式宽高会被它锁定，工具会回 warning），并确认画幅/单镜帧数在它的限制内。

**角色卡版本（渲染前强制）**：先 `canvas_get_state()` 读 `settings.characterCardVariant`（STEP 0 用户选择；缺省按 `single`）。每镜的 `ref_variant` = **本镜 `tier==='fast'` ? `single` : `characterCardVariant`**；**必须显式传**，不要依赖工具默认。组装 `ref_nodes` 时传对应版本的角色卡（或双版本任意一张 + `ref_variant`），工具只做同角色换版，不再按 tier 自动选。

**参考图形态门禁（G-ref，渲染前强制；仅 `fast` 档）**：`fast` 镜必须是单主体 / 单视图 / 零文字 / 无拼图（判定方式与证据见「参考图形态与档位」节）。任一不满足 → **停在这里，不要调生成工具**，出选项卡给四个出路：升到 `balanced` / `quality` 按原图渲染（推荐）/ 换单视图卡后重渲 / 用户手动裁图上传 / 放弃该参考图。`balanced` / `quality` 档无此门禁。**混合档位下最常见的踩线点：项目档位是 `balanced` / `quality`（用户可能选了 three），却把某一镜临时降到 `fast`——本门禁对该镜立即生效（强制 single）**，要么升档、要么传 `ref_variant='single'`（双版本流程下直接强制单视图，不需要临时补卡）。

**提示词库（渲染前强制）**：本镜生成前必须已经用 `canvas_write_prompt_bank` 写好 `fast` / `balanced` / `quality` 三段；**当前策略三档写入同一份完整 quality 提示词（逐字一致）**。组装完成后传 `prompt_node=<库节点 id>`，**不要**把 prompt 直接塞进 `prompt=`（否则换档时无法按档读取，且会覆盖提示词库）。

**标记残留复查（渲染前强制，1 秒）**：发出去前扫一眼本镜提示词库该段——不得残留分镜标记：`[char:` / `[scene:` / `[hook:` / `[audio_mode:` / `[speaker:` / `[cont:` / `[BEAT]` / `[HANDOFF`。标记与参考图上的文字同类：**写进 prompt 就会被当成要画的内容**。命中就剥掉，用 `canvas_write_prompt_bank` 回写同一 nodeId（保持三档同文），再渲。

**字幕开关（渲染前读回）**：`canvas_get_state` **读不到**这一项（没有 state 字段）——从**项目简报**读 STEP 0 的「字幕」选择。`none` 时本镜 prompt **不写任何字幕声明**（`<d>…</d>` 对白照写）、负向尾句加 `no subtitle, no burned-in dialogue text`；`burned-in` 时按 `h3-prompt-writing` 的字幕规范写。**开关改了必须重写提示词库并重渲**（字幕是画面内生成物，不能后期补 / 裁）。

**档位与分辨率/耗时同源**：工具返回会带 `tier` / `resolution`（以及排查用的 `implementation`）。回复与交付清单按**「档位 + 交付尺寸 + 时长」**汇报（用户按档位决策，不按实现名）；`implementation` 只在排查问题或用户主动问「用的哪个工作流」时再提。实测参考（16:9 · 124 帧 ≈ 5.17s，随硬件/驱动/模型版本浮动，只作量级参考）：ref2v `fast`(832×480) 24.6s ｜ `balanced`(1344×768) 166.3s ｜ `balanced` 带加速 136.3s ｜ `quality`(1344×768) 396.6s ｜ `quality` 带加速 311.2s。**续接镜**耗时与同档独立镜接近（多采 22 帧再裁掉，实测在噪声内）；接缝质量实测：画面差 2.6–7.0（同 seed 不续接对照 32–68）。转场镜 / 锚点式重渲走 i2v：`fast` 26.1s ｜ `balanced`(1344×768) 177.3s ｜ `balanced` 带加速 130.5s ｜ `quality` 394.8s ｜ `quality` 带加速 314.7s。画质：`balanced`(8 步) 帧锐度比 `quality`(20 步) 高约 13%；`fast` 档细节最弱、适合调构图 / 走位。

**实现选择**：由配置决定（设置页），**不出工作流选项卡**，技能也不接受、不传递工作流 id。用户主动要求换模型时，引导他去设置页改该能力的「档位选择」，改完用 `comfy_list_workflows` 核对一遍即可。

### 续接策略（逐镜按镜头表 `续接` 列执行）

> 以下所有逐镜调用都要显式带 `type` 与 `tier=`（Step 7 渲染前的门选定），不要依赖缺省。

**正片镜头 = r2v + 参考绑定**：`type='r2v'`, `ref_nodes=[本镜全部在屏角色卡（按 STEP 0 版本选择；fast 镜强制 single）, 场景卡]`（角色卡可传画布节点 id，也可传资产 id 如 `character:luna`），`prompt_node=<本镜提示词库 id>`。**差别只在续接**：

- **`起链` 的镜 → 不传 `continuity_from`**：场景第一镜、换场景后的新场景第一镜。
  `comfy_generate_video(type='r2v', tier=档位, prompt_node=…, ref_nodes=[说话人角色卡, 场景卡], audio_ref_nodes=['voice:<id>'], title=…)`（`audio_ref_nodes` 仅在方案 `audition` / `existing` 时传；`text-only` 时删掉）
- **渲染前声线门（按 STEP 0 的方案执行）**：单片读项目简报里的声线方案；**连续短剧委托模式读集制作包 ⑥ 与 `production-state.json` 的 `voices[]`，不重问、不重抽**。
  - 方案是 `audition` / `existing`：`dialogue` 镜若 `声线参考` 没有 `voice:<id>`、或该 id 未入库 → **不许提交渲染**，回 STEP 3.5 补样本/复用；渲染命令必须带 `audio_ref_nodes=['voice:<id>']`，产物自检第 5 项核对 `params.audio_ref_nodes`。
  - 方案是 `text-only`：**照常渲染，但不要传 `audio_ref_nodes`**（传了反而会触发“参考音频为空绑定/只有文本”的误导）；`声线参考` 全为 `none`，交付清单记录“音色无保证”。
- **方案为 `audition` / `existing` 时，对白镜必须带声线参考**（来源 STEP 3.5）：`audio_ref_nodes=['voice:<id>']`（≤3 段、每段 2–15s、总 ≤15s）；`text-only` 时不传（并在 prompt 里只保留文本音色描述）。prompt 必须写 `<Audio 1> is the voice-timbre reference for <Subject 1> (S1).` + `<Audio 1>: reference - …`，否则工具会警告「参考可能只被当环境音」。只有 `type='r2v'` 支持；`i2v` / 2K / hires 实现会报 `audio-ref-unsupported`；`fast` 档会警告 turbo 削弱参考。参考音频管「是谁的声音」，续接管「接缝不断」——两者同镜可并用。
- **`接 S0x` 的镜 → 传 `continuity_from=上一镜节点 id`**：同场景内的后续镜、跨场景转场镜。
  `comfy_generate_video(type='r2v', tier=档位, prompt_node=…, ref_nodes=[本镜全部角色卡, 场景卡], continuity_from=上一镜节点 id, title=…)`
  效果：消费上一镜的服务端 latent，**逐帧钉住它的结尾**（约 22 帧 ≈0.9s 画面 + 1 秒音频），音频从接缝继续；画质无损，**不需要上传任何上一镜的图或视频**（参考图照常上传，负责身份与环境）。实测接缝画面差 2.6–7.0（同 seed 不续接对照 32–68）。
- **`硬切` 的镜 → 不传 `continuity_from`**：按 `起链` 同样独立生成；它有自己的 latent，下游标 `接 本镜` 可照常续接。同场景硬切必须在 `连续性衔接` 写明 `HARD CUT — 原因`。
- **跨场景的镜绝不直接续接**：跨场景的连续由**转场镜**承担（它自己续接前一场景的尾镜），下一场景的第一镜一律 `起链`。
- **链的硬约束**：① 一条链内**首遍尺寸必须一致**（＝采样器实际跑的尺寸，**不是交付尺寸**；普通实现两者相同，两阶段/学习式放大实现两者不同）——链上传递的是**首遍 latent**，latent 不能缩放，不一致会**显式报错**并指出两边的首遍尺寸。实务上等价于「**同档**」：`fast` 首遍 832×480，`balanced`/`quality` 首遍 1344×768，混档即踩线；但**交付尺寸可以不同**（例如 `-ctx-quality` 1344×768 接 `-ctx-quality-2k` 2688×1536 是合法的——两者首遍都是 1344×768）；② 上游镜必须是链式实现渲染的（本 Skill 全镜都是，天然满足）；③ 上游镜重渲 ⇒ 下游续接镜必须顺次重渲（见「重渲与续接链」）。
- **续接不继承身份**：同一角色有多个着装/状态卡时，按本镜状态选正确的那张——续接沿用上一镜的画面与声音，**不保证沿用服装/妆容**，认人永远看参考卡。`ref_variant` 只负责在 single / three 两版之间切换，**不会替你选着装状态卡**。

**两处走 i2v（不是续接）**：

- **转场镜**（`锚定 S0x↔S0y`）：`comfy_generate_video(type='i2v', tier=档位, first_frame_node=S0x 末帧节点, last_frame_node=S0y 首帧节点, …)` —— 双端锚定，见「跨场景转场镜」。
- **锚点式重渲**：`comfy_generate_video(type='i2v', tier=档位, first_frame_node=上游末帧节点, last_frame_node=下游首帧节点, …)` —— 见「重渲与续接链」。
- ⚠ **不支持续接的实现渲出的镜不能当续接源**：一条续接链里若有一环被这样的镜替换，那一环下游就不能再 `接` 它（会报「上一镜没有链式序号」）。i2v 里**支持续接**的实现可以照常作续接源，**不支持续接的**则不行——用 `comfy_list_workflows` 确认该档解析到的实现支持续接。

### prompt 组装（逐镜）

按以下顺序组装（先跑 1–6 得到**一份**完整的 quality prompt，**最后**把它原样复制到三档落库；**渲染时只传 `prompt_node`**）：

0. **提示词库（组装完成后落库，强制）**：用下面 1–6 步写出本镜的**完整 quality prompt**，然后**逐字复制成 `fast` / `balanced` / `quality` 三段**（三档同文，不另写精简版）。用 `canvas_write_prompt_bank(title="SXX 提示词（分档）", prompts={fast: p, balanced: p, quality: p}, group="shot prompts")` 写库，记下返回的 `nodeId`。换档重渲时复用同一个 `nodeId` + 新 `tier`，不重写 prompt。
1. **H3 结构化重写（委托 `h3-prompt-writing` skill，主路径）**：调用 skill 工具加载 `h3-prompt-writing`，按它的规范（官方 `base-en.txt` / `ref-en.txt` + `references/studio-mapping.md` 映射表）把本镜「分镜章节 + 镜头表 `参考锚点` / `音频与对白轨` 行」重写为 H3 结构化 prompt：
   - **正片镜（`ref_nodes`，无首末帧）→ Ref2VA 六段式**：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`；
   - **续接镜（`接 S0x`）的额外要求**：在 `detailed_description` 里显式写明"从上一镜结尾的**动势 / 光位 / 音量**继续"（本镜第 1 秒是上一镜结尾的延续，latent 已钉住），不要写成"全新开场"；`summary` 里点明这是同场景的连续镜头。
   - **转场镜 / 锚点式重渲（传了首/末帧）→ I2VA / FL2VA 三段式**：对齐指令（首行，独占一段）+ `integrated_multimodal_description` + `overall_soundscape` + `non_diegetic_music`。首帧内容作为 `[Shot 1]` 起点锚点，有末帧时写成首末帧之间的连续运动路径；转场镜只写运镜与光变，不写角色动作与对白。
   - **条件启用**：仅当解析到的工作流 id 前缀为 `minimax-h3-` 时走本路径；其他工作流跳过，直接走 2 的自由格式组装（模型无关，不写死模型名）。
   - 交给重写前先剥离分镜专用标记：**双绑定与续接标签**（`[char:…] [scene:…] [hook:…] [audio_mode:…] [speaker:…] [cont:…]`）与 `[BEAT]` / `[HANDOFF …]`——不能出现在渲染 prompt 里。
   - **BGM 映射**：`bgmMode=in-model` 时，把镜头表 `音频与对白轨.BGM` 交给 `h3-prompt-writing` 写入 `non_diegetic_music`；`bgmMode=none` 时固定写 `N/A`。`overall_soundscape` 只写环境音/物理音，不写 BGM。
2. **自由格式兜底（仅非 H3 工作流）**：从单文本分镜文档对应章节（已抽取的镜从独立节点）取每面板四象限内容，逐秒展开成自然语言镜头描述。
3. **角色形态描述（铁律一，两条路径共用）**：凡在屏角色含非人形 / 非常规解剖形态，其形态描述一律按铁律一正向构造清单（整体形状词 → 比喻锚点 → 部位关系 → 唯一附肢 → 解剖总括句）写入重写素材或自由格式正文——角色卡节点描述里已有合规解剖清单时直接引用，正文禁否定堆叠与"可能长四肢"暗示。
4. **风格锁后缀**：**所选风格文件的**风格锁后缀（英文关键词串）与负向约束（两条路径都追加）。**铅笔分镜图除外**（见 STEP 6）。
5. **字幕（按 STEP 0 的「字幕」选择 + 本镜模式）——写法一律委托 `h3-prompt-writing`**：
   - **`burned-in` + `dialogue` 镜**：把镜头表 `字幕` 字段与对白原文交给它的「字幕与画面内文案（唯一权威版）」处理（H3 路径内嵌正文对白处、自由格式路径紧随对白句），片型侧**不追加任何末尾字幕指令、不复述四条限定词、不定档位 / 实现策略**；字幕文本与镜头表 `字幕` 字段逐字一致。
   - **`none`（项目关字幕）**：**不写任何字幕声明**（定稿句式整段不用），`<d>…</d>` 对白照写（说话人绑定不变），负向尾句加 `no subtitle, no burned-in dialogue text`；**不要**写「XX 秒前不要字幕」这类负面时间约束（实测会压掉对白 / 音效）。
   - **`silent` 镜（两种选择都一样）**：不加字幕、不写任何 `<d>`，负向尾句加 `no subtitle, no text anywhere`。
6. **负向意图**：不要分镜线稿、不要手绘草图质感、不要面板边框、不要标签水印（“不要真人写实”之类的**风格性负向**由所选风格文件提供，见「视觉风格」节，不要在这里写死）。

`length` 为 24fps 帧数（124 ≈ 5s），按镜头表时长换算。片段写入 group `shot clips`，标题带镜头号。

### 逐镜失败回退阶梯

0. **（仅 H3 结构化路径）先检查重写本身**：若本镜走了 `h3-prompt-writing` 结构化重写且质量倒退（字幕 / 口型 / 一致性 / 音频任一指标），先回退该镜为自由格式 prompt 重渲（见 h3-prompt-writing 适配节「失败回退」），再走下面的重试阶梯。**回退时 prompt 首行加 `[PROMPT_FALLBACK]` 标记**（质检门据此放行，否则会被 H3 结构化校验拦截）。
0.5 **prompt 方法论合规自检（任何路径重试前必做）**：本镜含非人形角色时，先自查 prompt 是否违反「铁律一」（否定堆叠 / 暗示可能长四肢）；含对白字幕时，字幕写法的合规性**按 `h3-prompt-writing`「字幕与画面内文案（唯一权威版）」核对**（本节不复述其条目）。不合规就先修 prompt 再渲，**禁止不改 prompt 直接重试同请求**。
0.6 **参考图版本回退（`balanced` / `quality` 首查）**：本镜非 `fast`、且自检命中的是**参考图形态类**问题——画面里多出角色副本、参考图的版面 / 分格 / 文字被印进画面、环境被参考图内容替换——**先传 `ref_variant='single'`（或把 ref_nodes 换成同角色单视图卡），用同一份 prompt（优先同 seed）重渲本镜**；仍不过再进入下面的 prompt 阶梯。这类问题不是 prompt 能修的（实测「只出现一只」声明无效），不要在版本回退之前反复改 prompt 烧钱。其他类型的问题（动作 / 口型 / 字幕 / 构图）不强制先回退，但**第一次强化 prompt 后仍不过、且怀疑与参考图有关**时，也先做一次单视图对照。
1. **第一次重试**：强化 prompt——直接引用镜头表 `参考锚点` 块的地标与人物位置，缩短冗余措辞。
2. **第二次重试**：缩到 ≤6s，砍掉的秒拆成 Step 5 的新相邻行，重跑 Step 5.5 自检再重渲。
3. **第三次重试**：改档验证是 prompt 问题还是采样问题——字幕字准 / 漏烧类问题**升档**（`fast`/`balanced` → `quality`），**只是想省成本或排查链路才降档**（`quality` → `balanced`/`fast`）。**注意：改档会打断续接链**（一条链必须同首遍尺寸，而首遍尺寸跟着档位走）——单镜改档就只能把它当新链起点（不传 `continuity_from`，接缝会退化成硬切），要保住接缝就用**全片同一档重出**；或简化动作、去掉一个道具、降低 hook 强度。（同档换实现的可行性按 `h3-prompt-writing`「字幕与画面内文案」§4 的口径取证后再说。）
   **改档/重做前先问超分**：用户是在追"更好看"还是"更大尺寸"？若本镜**内容本身没问题、只是不够清晰**，先说清「`video_upscale` 放大不会重画内容、也不会改档，因此**不打断续接链**」并问他要不要走这条路；只有用户要重出画面时才改档重渲。改档会连锁影响整条链（下游续接镜要顺次重渲），所以这个选择必须在动手前问清，不要先渲了再回退。
4. **同一镜连续 3 次失败**：选项卡问用户——换档位（先 `comfy_list_workflows` 核对可用档）/ 放宽要求 / 跳过该镜并在下游标记 `placeholder: missing clip` / 手动提供参考视频。

不要重复提交未改动的同一请求。

### 片段门控（门 3：逐镜自检按 `shotGate` 开关，人工确认按 `reviewMode` 逐镜或批量）

**自检门开关（`settings.shotGate`，STEP 0 用户选择，默认开启）**：`verdict` = 开启——每镜必须抽帧核对并 `canvas_record_check(verdict="pass")` 才能进下一镜；`frames` = 只要求抽帧（不强制记录结论）；`off` = 关闭——本片不做逐镜 AI 自检留痕（**人工确认与失败回退阶梯照旧**，`reviewMode=per-shot` 时变成「渲完 → 直接人工确认」）。渲染前 `canvas_get_state` 读回。

**两种模式共用的部分（`shotGate≠off` 时不可省）**：每渲完一镜，AI **立即**自检；**自检绝不允许推迟到全部渲完之后**——`batch` 批量审查省的只是「人工确认次数」，不是「自检次数」。转场镜走同一道门。

每镜渲染后的 **AI 自检**（渲染完立即执行，任一不过不进审查卡）：

1. **与计划一致**：对照镜头表该行 + 分镜章节，核对景别、动作节拍、空间锚点（地标落位 / 人物位置 / 离屏方向）、光位。**关键帧抽样，不只看末帧**——按下面采样表用 `extract_frame` 抽取后用当前模型自身视觉逐帧核对（当前模型不支持图片输入时回退 `describe_image`）：
   - 每镜必抽 **首帧 / 中段帧（约 1/2 处）/ 末帧** 三帧；镜长 ≥5s 或动作密集镜按 ~1.5–2s 间距加抽，单镜上限 5–6 帧；
   - `dialogue` 镜在说话时间窗内加抽 1–2 帧查口型；带字幕镜（字幕=`burned-in` 且有对白）抽说话窗帧核对字幕文字；字幕=`none` 时同一帧改为核对「画面里没有任何字幕 / 烧录文字」；
   - 转场镜**必抽中段帧**（实测：短 length + fast 档中段易糊 / 建筑形变）；
   - 末帧必抽：既用于本镜核对，也是**与下游续接镜接缝的一致性依据**——下游标 `接 本镜` 时，它开场约 0.9s 就是这里的延续，可对照确认没有突变（构图/光位/人物位置突然跳变就是接缝失败）。抽出的检查帧归 `shot clips` 组作中间产物，终检不计入镜头数。
2. **人物一致性与参考图版本**：用第 1 项抽出的关键帧，把画面中每个角色对照**本镜绑定**的角色卡（画布节点 id / 资产 id）逐项核对——脸型、发型、身材、服装、签名道具、不可改特征无漂移；同一角色多状态卡时确认用的是**本镜正确状态卡**（如「穿宇航服」状态）；同镜多角色各自对照各自的卡。同时核对**本镜实际版本是否等于 `ref_variant` 应传值**（`fast` → single；`balanced`/`quality` → `state.characterCardVariant`）。不过 → 若属参考图形态类问题，**先按 0.6 用 `ref_variant='single'` 重渲**；否则强化 prompt 直引角色卡外观锚点重渲（或先检查 `ref_nodes` 是否绑错卡/绑错版本），重跑自检。
3. **口型与字幕（有对白的镜必查）**：`dialogue` 镜只有说话人动嘴、同镜他人闭嘴；**字幕选 `burned-in` 时**字幕文本与镜头表 `字幕` 字段逐字一致、无引号书名号括号、无错字，且**无整段缺失**；**字幕选 `none` 时改为核对「画面里没有任何字幕 / 烧录文字」**（出现即算不过）；`silent` 镜无字幕、全员闭嘴（用第 1 项关键帧抽样的说话窗 / 字幕帧核对）。**不过关 → 不弹批准卡**，弹处置选项让用户选：**重新生成本镜 / 升档重渲**（`fast`/`balanced` → `quality`；换档会打断续接链，见失败回退阶梯第 3 步）。写法侧的问题按 `h3-prompt-writing`「字幕与画面内文案（唯一权威版）」核对，本门不复述其条目。
4. **无污染（含参考图形态类问题判定）**：无分镜痕迹（面板边框 / 箭头 / 标签 / 时间标记 / 双绑定与续接标签）、无参考图带出的文字水印与角色副本。**`fast` 档镜必须写明 G-ref 已过**（进 `ref_nodes` 的都是单主体单视图零文字无拼图）——缺这条留痕即算本项未过。**非 `fast` 档若用的是三视图卡，出现以下任一项即判定为参考图形态类问题**：画面里同一角色多出副本、参考图的分格 / 版面结构被印进背景、参考图上的文字被转印、环境材质被参考图内容替换 → 按 0.6 用 `ref_variant='single'` 重渲（同 prompt / 同 seed 优先），再重跑本门。
5. **音频与声线**：先查画布节点 `params.audio_ref_nodes` 是否等于镜头表 `声线参考`（对白镜必须传；`silent`/`none` 镜必须为空），以及 `params.audio_ref_declared === true`（prompt 里有 `<Audio N>`）。AI 不能听音——把「对白清晰 / 音色与声线样本是否同一人 / 音效与画面同步 / 无杂音幻听」列入确认卡，由人工听核；转场镜重点核对有无幻听人声。
6. **风格一致**：本镜画面符合**所选风格锁**（`references/styles/<id>.md`），与已锁定的卡片及相邻镜无风格漂移；风格锁后缀与负向约束确已追加到本镜 prompt。

**自检结论必须落画布（工具层硬门，不可跳过）**：每镜自检结束后立刻 `canvas_record_check(nodeId=<本镜片段节点>, verdict="pass"|"fail", frames=[本镜抽出的帧节点 id], checks={plan,character,lipsync,subtitle,contamination,audio,style}, notes=<判定摘要>)`。**`checks` 把上面六项落成结构化结论**（值 `pass` / `fail` / `na`）：
- `plan` = 第 1 项（与计划一致）；`character` = 第 2 项；`lipsync` = 第 3 项的口型；`subtitle` = 第 3 项的字幕（`silent` 镜与字幕 `none` 时可 `na`）；`contamination` = 第 4 项；`audio` = 第 5 项（AI 不能听音 → 写 `na`，由人工听核给结论；若本镜 `silent` 且无声线要求也可 `na`）；`style` = 第 6 项。
- **`verdict="pass"` 时任何一项 `fail` 都会被工具拒绝**（先改判 `fail` 重渲，或确认后改回 pass/na）。
- `pass` 必须有抽帧证据（`extract_frame` 产物，或用 `frames` 显式给出）；**未 pass 的镜头会被插件 pre-execute 门直接挡在下一镜之前**（`comfy_generate_video` 被 deny 并给出下一步）；`video_concat` / `video_upscale` 是后处理，不受此门约束。`fail` 时改 prompt / 参数后**复用同一 nodeId 重渲**（重渲会把自检重置为 `pending`），不要新开节点。人工确认按 `reviewMode` 照旧——自检门只管 AI 自检留痕，不替代人工确认。项目设置 `shotGate` 控制强度：`verdict`（默认，必须 pass）/ `frames`（只要求抽过帧）/ `off`（关闭——此时不做本段留痕，也不被插件拦；人工确认照旧）。

失败处置：任一不过 → 先 `canvas_record_check(verdict="fail")` 留痕，再走「逐镜失败回退阶梯」重渲本镜（参考图形态类问题先换单视图卡 / 强化 prompt / 缩时长 / 降档 / 简化动作）后重跑自检；**未过自检的片段不进任何审查卡**。若片段与已批准的 `参考锚点` 漂移（门框落到错边、人物从错边离屏、光位翻转），用直接引用 `参考锚点` 块的强化提示重渲。

**人工确认的时机由 `settings.reviewMode` 决定**（STEP 7 渲染前 `canvas_get_state` 读回；缺省 `per-shot`）：

#### A. `per-shot` 逐镜审查（默认）

正片**逐镜生成、逐镜确认**，不做「全部渲完再批量批准」：每渲完一个镜头，AI 先自检，再把该片段交人工确认；确认通过才进入下一镜生成。上一镜未批准，不推进下一镜。转场镜同样逐个走本门。

确认卡（每镜一次 `ask_user_question`）：批准本镜并生成下一镜（推荐）/ 重渲染本镜 / **换单视图角色卡重渲（参考图形态类问题）** / 升档重渲本镜（字幕字准 / 漏烧类问题；字幕关时改为口型、画面瑕疵类）/ **放大本镜（`video_upscale`，内容不变、不打断续接链）** / **补帧本镜（`video_interpolate`，48fps）** / 修复角色不一致 / 修复场景不一致 / 修复跨镜空间锚点漂移 / 查看自检详情。

#### B. `batch` 批量审查

1. **生成阶段**：按镜头表顺序连续生成（链式续接 / 独立镜起链的规则完全照旧），每镜渲完**立即自检**；通过就直接推进下一镜，**不弹卡**；不过就按「逐镜失败回退阶梯」自动重渲。**同一镜连续 3 次失败仍必须弹选项卡**（求助门不可省，不许静默跳过、不许降级交付）。
2. **例外（两种模式一致）**：门 3 自检第 3 项（口型 / 字幕字准）不过关时**当场**弹单镜处置卡（重新生成本镜 / 升档重渲 / 改短句 / 拆镜）——这类问题人工决定比 AI 闷头重试省成本，**不压到批量卡里**。
3. **批量审查卡**：全部正片镜 + 转场镜渲完、且**全部通过自检**后，出**一张** `ask_user_question`，逐条列出：镜头号 → 画布节点标题 / 节点 id → 时长 → 自检结论（含关键帧抽样核对项、`fast` 档的 G-ref 留痕）→ 需要人工听核的音频项。选项：**全部批准并进入拼接（推荐）** / 重渲染选定镜（报镜头号，**说明会连锁重渲下游续接镜**）/ **换单视图卡重渲选定镜** / 升档重渲选定镜 / 放大选定镜（`video_upscale`，内容不变、不打断续接链）/ 补帧选定镜（`video_interpolate`，48fps，整片同帧率）/ 查看某镜自检详情与抽帧 / 改回 `per-shot` 逐镜审查（后续镜改为逐镜确认）。
4. **批准语义**：整卡「全部批准」＝全部片段批准，可直接进 STEP 8 拼接；**不接受部分批准**——要改就选「重渲染选定镜」，重渲后**重新出批量审查卡**（只列受影响的片段）。
5. **代价必须提前讲清**（STEP 0 选项卡与渲染档位卡都要说）：坏镜头晚发现；续接链上任何一镜重渲都要**顺次重渲下游**，「重渲与续接链」那笔账在批量模式下一次结清。
6. **音频仍由人工听核**：AI 不能听音，批量卡必须逐条列出片段与听核要点，不能只写一句「已全部生成」。
7. **渠道提醒**：`batch` 下一次 `ask` 会触发插件把**全部片段**自动送达（飞书单文件上限 20 MiB，超限记在节点 `params.deliveryError`）——片段多 / 体积大时先把片段清单写进回复正文，并提示用户到画布取。

### 用户修改与计划冲突的处理（权威链：镜头表 → 分镜 → 片段）

已批准镜头表 + 分镜文档是**计划权威**（分镜是 Step 7 渲染的权威参考）。用户在任何关口提出修改时，先归类再执行，**禁止静默改渲让片段与计划漂移**：

1. **计划内微调（行内重渲）**：修改不改变镜头表该行的景别 / 时长 / 动作节拍 / 锚点 / 音频与字幕（如「动作再夸张点」「这句演得更委屈」「门框别挡脸」）→ **先更新本镜提示词库的 quality 源文本，并把同一份同步到 fast / balanced 两段**，再重渲本镜，走门 3 自检 + 人工确认（人工确认按 `reviewMode`：`per-shot` 当场确认，`batch` 并入重出的批量审查卡），无需改表。
2. **偏离镜头表行（必须先落表）**：用户要求改变景别 / 时长 / hook / 台词字幕 / 说话人 / 锚点等本行计划内容、与已批准表格不一致 → **不得直接按口头要求重渲**；先把修改写进镜头表对应行（或拆行 / 新增行）→ 跑 **STEP 5.5 十四项自检**（不过就继续改表）→ 同步更新分镜文档对应章节（已抽取的镜同步其独立节点）→ **重写本镜提示词库的 quality 源文本，并同步三档（三档同文）**→ 再重渲受影响镜。
3. **改动连续性 / 交接的修改**：涉及角色离场、道具状态、光位、为下一镜铺的开场状态 → 除本行外沿 `连续性衔接` 链检查后续行（锚点继承 / 第 9 项续接链闭合性 / 第 10 项续接可行（前 1 秒仍在上一镜尾里）/ 第 8 项转场帧洁净），必要时按「重渲与续接链」处理下游（下游续接镜必须顺次重渲）。
4. **意图冲突时先澄清**：用户口头修改与已批准计划冲突且未明说改表 → 先出选项卡澄清（改表走自检 / 行内微调重渲 / 维持原计划），按用户选择执行；AI 不自行猜测吞掉冲突。
5. **修改全部落画布**：更新后的镜头表 / 分镜 / 片段为当前批准版本，旧版标记废弃，重跑 `video_concat` 与终检（遵守「重生成与最新资产纪律」）。

### 跨场景转场镜

只有**跨场景边界**才需要转场镜；**同场景内部不需要**（相邻镜已经靠续接连续，插转场反而暴露剪辑点）。本 Skill 的短片不用交叉溶解（有 PPT 感），而是让镜头真的运动过去。

**默认做法：i2v 双端锚定**（把两个场景的首末帧钉在一起，收尾精确落回下一镜首帧）——**需要在下一场景首镜的真实首帧已存在时做**：`per-shot` 模式下是「正片片段全部逐镜批准之后」，`batch` 模式下正片渲完即可补（转场镜与正片一起进同一张批量审查卡）。

> **增强选项（实测可用）**：若该档解析到的 i2v 实现**支持续接**，**同一次调用再加 `continuity_from=前一场景尾镜节点 id`** 就能同时拿到「尾部画面 + 音频的连续性」与「末帧精确落点」。实测行为：**续接的 i2v 会丢弃 `first_frame_node`**——也就是说开头由上一镜尾部决定、落点由末帧决定，**这是转场镜的当前最优解**；只传首末帧（普通 i2v）是它的降级版。

1. 触发条件：相邻两镜的场景卡不同。正片片段**自检通过并获批准**后补转场镜（`per-shot`：逐镜批准后；`batch`：正片渲完即可，转场镜并入同一张批量审查卡）。
2. `extract_frame(video_node=前一场景尾镜节点, frame_index=-1)` → 前一镜末帧。
3. `extract_frame(video_node=下一场景首镜节点, frame_index=0)` → 后一镜首帧。
4. `comfy_generate_video(type='i2v', tier=档位, first_frame_node=末帧节点, last_frame_node=首帧节点, length=…, prompt=过渡意图, group="shot clips", title="S03→S04 转场")` —— **FL2VA 双端生成**，模型自己补出中间的运动，**收尾精确落回后一镜首帧**（镜头表 `续接` 列标 `锚定 S0x↔S0y`）。工具会自动把过渡 prompt 持久化为提示词库节点并返回 `promptNodeId`；升档重出转场镜时用 `prompt_node=<该 id>` + 新 tier 复用同一 prompt。
5. 转场镜作为**普通片段**参与 Step 8 的拼接顺序，插在两镜之间；下一场景的第一镜标 `起链`（它自己不续接，连续性由这个转场镜给）。

**备选做法（仅当下一场景首镜还没生成、又想先看过渡效果时）**：`type='r2v'` + `continuity_from=前一场景尾镜节点 id`，prompt 只写运镜与光变。它能**从上一场景结尾长出来**（开头约 1s 是那一镜的延续），但**无法把结尾精确落到下一镜首帧上**——它是草稿手段，**成片前应换回双端锚定版**（两者都是普通片段，替换节点后重跑拼接即可）。

转场镜走**同一道门 3**（渲染后 AI 自检抽**首 / 中 / 末**帧核对运镜与光变——中段必查防形变，确认无杂音幻听）：`per-shot` 模式**逐个生成、逐个确认**（人工确认 → 再生成下一条）；`batch` 模式与正片一起进**同一张批量审查卡**（正片渲完就先补转场镜，不必多开一张卡）。

转场 prompt 只写镜头运动与光线变化（如「镜头快速上摇掠过屋顶冲向天空，暖色黄昏光渐变为高空冷蓝光」），**不写角色动作、不写对白**，音频模式按 `silent` 处理。

**两种做法的能力差别（选之前先想清楚）**：

| | i2v 双端锚定（默认） | r2v + 续接（备选/草稿） |
|---|---|---|
| 开头 | 直接等于前一镜末帧，画面/光位严丝合缝 | 继承前一镜最后 22 帧 + 1 秒音频（更长更自然，但光位/运镜带着前一镜的走向） |
| 结尾 | **精确落回下一镜首帧** | 只停在「朝向下一场景」的状态，靠硬切进入 |
| 时序要求 | 需要一个**已批准**的下一镜首帧 | 下一镜还没生成也能做 |
| 提示词 | I2VA/FL2VA 三段式 | Ref2VA 六段式 |

无论走哪种，下一场景的接续感还应加上：① 下一镜的场景卡与 `光位基线` 与转场镜保持一致；② 拼接硬切本身不承担叙事转折，转折留给转场镜的运动。要让某镜首帧**完全可控**，就把它当 hero 镜单独打磨（必要时 `起链` 重渲）。

三条实测约束，必须遵守：

- **避开带字幕的帧**（实测硬规则）。`dialogue` 镜的末帧带烧录字幕：双端锚定直接拿它当首帧，字幕会**原样出现在转场镜开场**；备选的续接做法更狠——把**最后约 22 帧（≈0.9s）画面连同 1 秒音频整段钉进转场镜开头**。两个办法：① 镜头表把跨场景边界的前一镜设计成**最后 0.5s 无对白**，末帧天然干净（首选，流程层消解问题）；② 抽帧时往前挪，用 `frame_index=-12` 之类取字幕消失后的帧。**字幕选 `none`（STEP 0 关字幕）时本风险自动消失**（没有烧录字幕可继承），这两个办法仍可当「末帧画面干净」的优化。
- **`length` 走 17k+5 网格**（5 / 22 / 39 / 56 / 73 / 90 / 107 / 124…），且模型训练区间是 **124–362 帧**。短于 124 属未测区，实测 `length=39` + fast 档的中段会糊、建筑有形变。转场镜建议至少 `length=56`；**成片用与正片同档重出**（单片默认 `quality`；连续短剧跟随项目档位，默认 `balanced`），fast 只用于验证链路。**不要单独把转场镜升 quality**——连续短剧整季同档，混档会让拼接后出现清晰度跳变。
- **分辨率/档位要与正片一致**（观感纪律，不是拼接的硬门槛）。i2v 转场镜不参与续接链，所以**不受"链内首遍尺寸一致"约束**（锚点帧进来时会自动缩放对齐）；转场镜显式传与正片相同的 `width`/`height` 并**与正片用同一档位**——不是为了能拼上（`video_concat` 在 ffmpeg 后端下 stream copy 失败会**自动重编码**，分辨率不同不至于拼不起来），而是 ① 混合分辨率会让成片出现清晰度跳变，② 后端退化到 ComfyUI 纯节点链路时的行为不如 ffmpeg 可控。**跨档升档必须在生成前决定**（全片同一档），不要到拼接时才发现混档；已经混档的片段建议先统一档位重出再拼。

自检抽出的关键帧图片节点也归 `shot clips` 组，它们是中间产物，终检时不计入镜头数。转场镜自带模型生成的音频，终检时必须逐条听过，有杂音或幻听人声就重出。

### 片段收集（门 3 的确认已完成）

正片与转场镜全部**自检通过并获批准**后（`per-shot`：逐镜批准；`batch`：批量审查卡批准），按镜头表顺序放到画布（group `shot clips`）。**不再设额外的「批准片段」选项卡**——`per-shot` 的确认在各镜生成当下完成，`batch` 的确认在批量审查卡完成；整体复查需求留给 STEP 8 交付批准卡的「补做终检某一项 / 重渲染选定片段」选项。严禁在交付时静默混合修正版与未修正版片段。

## STEP 8：拼接、交付与终检

**模式差异**：单片写交付清单 + 弹交付卡；剧集委托模式只写本集终检/片段清单，**不弹交付卡、不写系列交付包**（见 `references/series-delegated-mode.md`）。

### 拼接全片

全部片段**经门 3 批准**后（`per-shot` 逐镜批准 / `batch` 批量审查卡批准），用 `video_concat(nodes=[按镜头表顺序的片段节点 id，含转场镜], title="拼接成片", group="final delivery")` 拼成完整成片（含音轨）。后端由插件自动选择——本机有 ffmpeg 走 ffmpeg，没有就走 ComfyUI 纯节点链路，两者对本 Skill 透明。

拼接的三条限制，必须提前告知用户：

- **拼接本身只做硬切，没有溶解**。跨场景过渡由 Step 7 生成的转场镜承担——把转场镜按顺序放进 `nodes` 即可。如果没做转场镜，成片就是直切。
- **建议全片同分辨率、同档同实现**。`fast`（长边 832）与 `balanced`/`quality`（长边 1344）**不要混在同一条成片里**——分辨率不同会让成片出现清晰度跳变；`balanced` 与 `quality` 长边同为 1344，拼接本身能过，但**同片混不同实现会导致观感/像素漂移**，非必要不混。**跨档升档要在生成前决定**（全片同档），不要到拼接时才处理。后端差别：**ffmpeg 后端**下 stream copy 失败会**自动重编码**，所以混分辨率不会硬失败（代价是重编码 + 观感跳变）；**ComfyUI 纯节点兜底**走 `ImageBatch` 左折叠，**要求各段尺寸一致**，混了会报错。因此「全片同分辨率」在两种后端下都是安全做法。
- **BGM 模式**：`none`（默认，H3 `non_diegetic_music: N/A`）或 `in-model`（H3 逐镜自带 BGM，烘进片段；不可单独替换/duck，硬切可能换曲）。`separate`（Music 3 独立音轨 + 后期混音）下一期；插件目前没有混音/贴轨工具，**不要声称独立 BGM 已混入成片**。

### 提分辨率 / 超分（按 STEP 0 的「交付画质」选择执行）

**这项在 STEP 0 就问过用户**（原生 / 后处理逐镜超分 / 生成内放大），本节是它的执行口径。没问过就直接按原生交付是不合规的——**别替用户默认**。

- 用户选了**后处理逐镜超分**，或中途改主意要「更高清 / 2K / 4K」：按下面两条路线做，且**必须先把代价说清楚**（分钟级到十几分钟级，不是几秒）。
- 用户选了**原生**：跳过本节；**交付卡里保留「逐镜超分到 2K / 4K」选项**，用户想加随时能加（不单独再问一次）。
- **这个选择在「换档重做」时同样要重新问**：用户嫌不够清晰时，先分清是**要更大尺寸**（超分，不重画内容、不打断续接链）还是**要更好的画面**（改档重渲，会打断链并连锁重渲下游）。两者代价与影响完全不同，动手前问清。

| 路线 | 怎么做 | 代价与注意 |
|---|---|---|
| **逐镜超分（推荐优先试）** | `video_upscale(video_node=某镜片段节点, tier='quality', target_width=…)` 对**单个片段**放大 | 逐帧 CNN，**不经过 H3、不重画内容**（只提分辨率，不会改变表演），音轨原样带回。代价线性（≈2.2–2.6 s/帧）。**比例永远跟源片**：H3 是 1.75:1，所以「4032 宽」= 4032×2304，不是 16:9 的 3840×2160 |
| **生成时就出高分辨率** | 让该档解析到**放大类实现**（在配置页把该档指到它；用 `comfy_list_workflows` 查该档有没有、交付多大） | 这类实现**锁定自己的采样尺寸**：显式 `width`/`height` 与画布比例**都不生效**（工具会回一条 warnings 说明），交付尺寸由该实现决定、大于采样尺寸；**比例与单镜帧数可能受限**（例如仅 16:9、单镜上限 124 帧）；耗时远高于同档普通实现。可与续接叠用，但**全片要固定同一档**（同档采样尺寸才接得上） |

三条纪律：

1. **对单个分镜放大，不要对拼好的成片放大**。成片先拼后放会让失败代价与显存峰值都放大到全片；逐镜放大也便于只重做坏掉那一镜。
2. **放大后要重跑拼接**（`video_concat` 吃的是放大后的节点），并用放大前**同样的顺序**。
3. **超分不改变内容，所以不能用它"救"内容问题**。构图错、动作糊、口型不对是生成问题，放大只会把错误放大——先重出那一镜，再考虑放大。

⚠️ **交付体积**：2K/4K 片段很容易超过 `send_file` 的 20 MiB 上限（飞书自动送达会失败并记在节点 `params.deliveryError`）。要么用 `target_width` 收敛、要么提高上限配置，要么提示用户到画布取。

### 提帧率 / 补帧（48fps，按 STEP 0 的「交付画质」选择执行）

**48fps 是「观感更顺」的后处理，不是分辨率**——它只增加时间信息、不重画任何一帧（保留帧与源一致，实测 PSNR 41–42 dB），所以：

- 只对**单个片段**补：`video_interpolate(video_node=某镜片段节点, target_fps=48)`（RIFE ×2，时长与音轨不变）。**绝不对成片补**：模型没有场景检测，硬切/转场处会生成两场之间的形变帧（实测切点 PSNR 13.9 dB，肉眼是交叉淡化鬼影）。含**内部硬切**的片段（拼接产物、一场多镜的合集）跳过。
- **顺序：先超分 → 再补帧**。超分不改 fps，补帧最后做；两者都是后处理、**不打断续接链**。
- 补帧后**抽 1–2 帧核对**：双影 / 字幕拉丝 / 纹理沸腾。烧录字幕的镜：中间帧文字边缘会变软（实测 PSNR 32.8–34.9 dB，仍可读），密集小字镜先核对再批。
- **全片必须同一帧率**：`video_concat` 会**拒绝**混帧率拼接（混了不会报错但非首段会半速播放）。只补部分镜 = 其它镜也要补到同一帧率才能拼；做不到就整片不补。
- 代价（A800 实测）：768×1344 / 124 帧 ≈ **10.5s/镜**；体积与 24fps 源基本持平（2.00 MB vs 2.00 MB）。
- 30/60fps：需要本机 ffmpeg（插件自动向上层目录找，也可配 `ffmpegPath`/`DSH_SVS_FFMPEG`）；60fps 走 120fps 母版 + 抽取，体积与平台兼容性另算。**默认只提供 48fps**。

### 交付清单

在 group `final delivery` 写一个交付清单文本节点，包含：

- 拼接成片的节点 id 与媒体路径、总时长。
- 按镜头表顺序的片段清单（镜头号 → 画布节点 id → 媒体路径 → 时长）。
- BGM：`bgmMode=none` 写“无 BGM”；`in-model` 写“BGM 已随片（H3 自带），无独立 BGM 轨；硬切/跨场景可能换曲”；`separate` 未实现时列“独立 BGM 建议”（情绪弧、节奏、duck 点）。
- 未落地项：需要人工补的溶解转场位置（如有）。

**终检清单**（逐条核对并写进交付节点）：

- 角色一致性：跨镜同一角色的脸、发型、身材、服装、签名道具无漂移；换装镜用的是正确状态卡。
- 场景连续性：对照 `参考锚点` 列逐镜验证每个地标是否落在表格说的位置；光位无意外翻转。
- 情绪锚点回收。
- 镜头意图清晰度；景别有交替，无重复景别堆叠。
- **口型硬卡**：每个 `dialogue` 镜只有一个说话人在动嘴，其他角色全程闭嘴；`silent` 镜全员闭嘴。
- **字幕正确（按 STEP 0 的选择核对）**：`burned-in` 时字幕文本与镜头表 `字幕` 字段逐字一致，无错字、无引号书名号括号；`none` 时全片**不得出现任何字幕**（逐镜抽说话窗帧确认），此条按「无字幕」核对；`silent` 镜无字幕。
- 音频可听：对白清晰，音效与画面同步。
- **无分镜痕迹**：没有面板边框、铅笔线、箭头、标签、手写备注、时间标记、姿态残影，**也没有双绑定标签**（`[char:…] [scene:…] [shot:…] [dur:…] [hook:…]`）。
- **无参考图污染**：成片里没有从参考图带进来的文字 / 水印，也没有同一角色的多个副本。**多主体参考图只在 `fast` 档会漏**（`balanced` / `quality` 实测干净）——若出现，先检查该镜是否走了 `fast` 而绕过了 G-ref。
- **道具一致性**：跨镜出现的签名道具，形状 / 比例 / 材质 / 配色与道具卡一致、无漂移；有道具卡的镜用的是正确的那张卡。
- **风格一致性**：全片视觉风格与 STEP 0 选定的一致，跨镜无风格漂移；卡片、片段与成片看不出换过风格。
- 缺失或薄弱片段；任何可能需要重做的资产。
- **交付画质与 STEP 0 的选择一致**：项目简报里记的「交付画质」决定成片该是原生尺寸还是 2K/4K——选了超分就必须真的做了（且**拼接吃的是放大后的节点**），选了原生就别凭空声称高分辨率；实际交付尺寸以节点记录的 `width`/`height` 为准，写进交付清单。**交付帧率同理**：选了 48fps 就必须真的逐镜补过（拼接用的节点都是补帧产物），没补不得声称 48fps。

### 渠道交付（飞书 / TUI）

「画布」tab 只在 Web 可见；跑在 TUI / 飞书时用户看不到画布，交付阶段要把产物送达用户，而不是只写交付清单：

1. **ask 前自动送达**：飞书渠道下，插件会在每次 `ask_user_question` 执行前自动把画布中未送达的产物经 `send_file` 送达——角色卡/场景卡/逐镜片段/拼接成片等媒体直接发原文件；简报/大纲/镜头表/分镜等文本节点自动导出为 .pdf 一并送达（飞书可直接预览；本机无 PDF 工具时兜底 .html）。**发送的文件名取自节点标题**（如 主角卡.png、简报.pdf），所以给节点起有意义的标题（「S01 片段」而非「视频1」）。**不要手动调 `send_file`**，避免重复。群聊会先弹审批卡、再出选项卡，照常调用、由用户在飞书确认。
2. **文本同时进回复**：文本产物除 .pdf 文件外，把要点写进 ask 前的回复正文，飞书回复本身即可读。
3. 没有 `send_file`（Web / TUI）则产物已在画布/工作区，无需推送；TUI 用户按工具返回的 `absPath`（绝对路径）自行打开。
4. `send_file` 单文件默认上限 20 MiB：成片或长片段超限导致自动送达失败时改用 fast 档 / 更短镜头 / 分镜分开发，或提示用户到画布取。

选项卡：批准交付（推荐）/ 重渲染选定片段 / 升档重出全片（`balanced` / `quality`，全片同档）/ **逐镜超分到 2K / 4K（`video_upscale`；可只对选定片段做，然后重跑拼接）** / 补做终检某一项。

## 画布归组纪律

每生成一个耐用产物立刻上画布并归组（生成工具自动上画布的不重复写）。本 Skill 的分组词汇（已在 Step 0 通过 `groupOrder` 声明）：

`story planning`（简报 + 大纲）· `character cards` · `voice auditions`（试镜片段 + 抽出的声线节点 + 声线清单）· `scene cards` · `prop cards` · `shot table` · `text storyboards`（分镜文档 + 抽取节点 + 铅笔图）· `shot prompts`（每镜提示词库，三档同文）· `shot clips`（片段 + 检查帧 + 转场镜）· `final delivery`（交付清单 + 终检）

一轮生成产出 2 个或更多产物时立刻 `canvas_group_nodes` 归组并起清晰标题。顺序错乱时用 `canvas_reorder` 修正。

## 用户选项卡纪律

每个需要用户确认的地方都用 `ask_user_question`，不允许用纯对话问题或散文代替。

- **单片**：门清单见 `references/single-film-mode.md` §3（13 张规格卡 + 阶段卡；默认 `per-shot`）。
- **剧集单集**：只出 3 张卡（方案 / 片段 / 交付），见 `references/series-delegated-mode.md`；AI 自检仍逐镜做。
- **改规格卡**：仅当用户主动要改档位 / 审查节奏 / 逐镜自检门 / 交付画质时弹（STEP 0 已定过，不重复问）。
- **异常门**：G-ref / 同一镜连续 3 次失败 / 口型字幕不过 / 意图冲突 → 当场打断，不许静默降级。

默认推荐项放最前，始终允许用户自定义输入。用户说「继续」时按选了推荐项处理。

## 重生成与最新资产纪律

用户重做或修订任何产物时，下游步骤必须用最新批准的产物：

- 角色卡重做后，后续镜头表、分镜、片段必须按精确角色名引用新卡；旧卡节点在画布上明确标记为废弃。**改设定只能改三视图**：三视图重出后必须**重新裁一次单视图**（复用同一 nodeId 重裁）并保持 `pairedNodeId` 双向有效——禁止只换单视图、也禁止让单视图停在旧设定。
- 场景卡重做后同理，并重新核对所有引用该场景的 `固定地标` 与 `光位基线`。
- 镜头表修订后，分镜（文档 + 抽取节点）与片段必须用新表，**Step 5.5 自检必须重跑**才能恢复分镜。
- 分镜某章节修订后，对应片段必须用新章节内容；已抽取的镜以独立节点为权威。
- **提示词库是唯一 prompt 权威**：本镜计划变化时先更新 `SXX 提示词（分档）` 的 quality 源文本，并同步到 fast / balanced 两段（三档同文），再重渲；**换档重渲只改 `tier`、复用同一个 `prompt_node`**，不要把旧 prompt 手抄进 `prompt=`。重渲后工具会把本次实际使用的 prompt 回写该档段，不需要另存。**开关字幕（STEP 0 的「字幕」选择）也走这条纪律**：改简报 + 重写受影响镜的提示词库 + 重渲（字幕是画面内生成物，不能后期补 / 裁）。
- 铅笔图重画不强制重渲视频（它不是渲染参考）。
- **重渲的续接链连锁（铁律）**：任何镜重渲都会在**服务端生成一个新的 latent 槽位**；所有标 `接 <该镜>` 的下游镜（同场景后续链，以及该镜是场景尾镜时的转场镜）**必须顺次重渲**——下游重渲时 `continuity_from` 换成**重渲后的新节点 id**（旧节点已过期），逐级推进到链尾，每级重渲后都跑门 3 自检（人工确认按 `reviewMode`：`per-shot` 逐镜确认；`batch` 这一轮重渲完**重新出一张批量审查卡**，只列受影响的片段，见门 3 §B 第 4 条）。
  示例：`S1 起链 → S2 接 S1 → S3 接 S2 →（S3 是场景尾镜）T 转场接 S3 → S4 起链`；重渲 S2 ⇒ 必顺次重渲 S3 与 T；S1 不受影响；S4 是新链起点也不受影响。**禁止只重渲单镜而保留旧下游续接镜**（下游消费的是旧 latent，接缝会对不上：画面/声音在切点跳变）。
- **锚点式重渲（例外路径，i2v 双端锚定）**：当重渲动机只在**中段**、而结尾交接状态不变（下游镜开场仍应与计划一致）时，可以用双端锚定把新结尾钉回下游计划首帧：
  `comfy_generate_video(type='i2v', tier=档位, first_frame_node=上游末帧节点, last_frame_node=下游镜首帧节点)`
  效果：本镜新末帧**精确落回下游首帧**，下游不会因为"结尾变了"而需要重渲。
  **代价与出路（必须知道）**：若用**不支持续接的实现**重渲，产物**没有可续接的 latent** ⇒ 本镜就从续接链上摘了下来，下游若仍标 `接 本镜` 会直接报错「上一镜没有链式序号」，只能改成"同样用 i2v 锚定接上"或"改 `起链`（硬切）"。
  **优先选支持续接的 i2v 实现**做锚定重渲：它自己存 latent，**下游照旧 `接 本镜` 即可，不需要重渲**，锚定与续接两全（代价：重渲时把 `continuity_from` 也传上，本镜才在链内）。此时首帧锚点会被丢弃（head 决定开头），**末帧锚点保留**并精确落回下游首帧——正是我们要的效果。
  **适用判断**：**「精确接上已批准的下游首帧」比「续接的 22 帧画面 + 1 秒音频连续」更重要时用它**（如下游镜已人工批准、不想再动）；否则优先**顺次重渲整条续接链**（接缝质量最好）。
- **其余不想动下游的理由都不成立**：只改本镜 prompt 细节、**且结尾画面不变**时，可先跑下游门 3 自检确认接缝未坏、再只在项目简报记录并请用户确认（例外，不写进默认流程）。
- 片段重渲（含连锁）后，必须用新片段重跑 `video_concat`，交付清单与终检也随之更新。
- 换工作流重渲时，在项目简报记入新工作流，并确认选中的实现**声明了链式续接**（否则该镜会变成链条断点：它自己可以起链，但下游必须改成 `起链` 或换回链式实现）。

任何重做后：在下一条回复中标明重做产物为当前批准版本；后续调用一律用新节点 id；画布上同时存在多版本时先指明当前选用版本再继续；被替换的旧片段节点与旧检查帧一并标记过期，**不再用作任何镜的 `continuity_from`**；不要在交付清单里静默混合新旧资产。

## 边界

单张图、简单修图、单段独立镜头、logo 设计、纯提示咨询不用本 Skill。音频模式只支持 `silent` 与 `dialogue-led`，**旁白主导不在范围**。不用于真人实拍素材的剪辑 / 合成（本 Skill 只做生成，不做实拍剪辑）。
