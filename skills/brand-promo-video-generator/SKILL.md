# 品牌宣传短片生成器（dsh-short-video-studio 适配版）

官方 MiniMax H3 brand-promo-video-generator 适配到本插件执行层（本地 ComfyUI 能力注册表 + 画布 + 资产库 + 飞书交付）。当用户想把品牌素材或一个想法做成宣传短片时使用本 Skill。流程从素材收集到最终交付，所有主要产物按生产顺序落到画布，并在高成本或关键创意节点用选项卡让用户确认。

核心规则：**真素材先行、生成在后；身份素材绝不虚构；开场用选项卡确认生产规格；产物按顺序上画布；带身份识别素材（LOGO / 产品界面 / 包装 / 人物 / 吉祥物）绝不重绘或近似——画布原件可用时首帧锁定，否则精确描述锚点；镜头表确认并自检通过后逐镜生成 → 拼接 → 终检；BGM / 旁白由视频 AV 模型原生生成，不单独生成音乐轨。**

参考图硬规则（单视图 / 图内零文字 / 不拼图 / first_frame 只用于同场景续接 / 入库由用户人工点按钮）由插件工具契约统一定义，本文不复述；品牌素材的增量规则见 STEP 3。

## 能力覆盖规则（诚实能力声明）

本 Skill 的生成承诺依赖以下能力，开场先 `comfy_list_workflows` 核对一遍：

- `image.text2image` — 静帧板（概念帧 / 氛围底板 / 抽象动效层）。
- `image.image2image`（参考图生图）— 仅用于**授权素材的抽象化 / 氛围版迭代**（如把产品照片转为抽象动效层的底板），**绝不用于重绘或近似 LOGO / 产品界面 / 包装 / 吉祥物等身份识别素材**——品牌素材不可重绘规则优先于本能力。
- `video.reference2video` / `video.image2video` — 单镜头视频（AV 模型，自带原生音频）。
- `image.from_video`（抽帧）与 `video_concat`（拼接）。

降级规则（对应官方 Tool Coverage Rule）：

- **缺图片或视频能力** → 明确把交付物降级为**前期方案包**（品牌事实表 + 来源清单 + 创意方向 + 镜头表 + 每镜 prompt 文本），并告知缺哪个能力；不要声称能出成片。
- **独立旁白 / BGM 轨**：注册表当前无 `audio.tts` / `audio.music` 工作流。旁白与 BGM 由视频 AV 模型原生生成（写在 prompt 里）。用户明确要求「可单独替换的 BGM 轨 / 录音棚级旁白 / 独立于视频的精确音乐时长」时，核对注册表：无此能力就明确降级——用原生音频 + 把独立轨需求列入交付清单未落地项（用户后期添加），或接受用户提供的音频文件。**绝不让同一条声轨生成两遍**（原生音频 + 独立音频重复）。
- **无后期剪辑能力**：本插件没有视频剪辑 / 合成工具。凡需要「把真实 LOGO 贴到画面上」的镜头，用**首帧锁定**（官方 LOGO 板作 first_frame）让画面原生继承，不做贴字合成。

## 品牌视觉锁

品牌事实表确认后，从中提炼**品牌视觉锁**（写进事实表节点描述，逐镜 prompt 复用）：

- 品牌色：主色 / 辅助色（带色名与使用倾向）；全片 2–5 个色彩状态，每个绑定一个含义（记在镜头表光位与色彩状态里）。
- 排版：画面文案的字体风格（来自品牌字体规范；无官方字体时用「干净的无衬线 / 品牌感字体」描述，不指定具体商业字体名）。
- 调性：2–3 个关键词（如科技冷峻 / 消费温暖 / 高端克制留白），驱动动效强度、光线与构图语言。
- 材质与光倾向：哑光 / 金属 / 玻璃质感、主光方向倾向。
- 负向约束：不模仿其他品牌视觉语言、不出现未验证指标、不出现第三方水印、不出现事实表之外的品牌元素（贴纸 / 吉祥物 / 标语）。

风格锁后缀（色彩状态关键词 + 调性 + 负向约束）追加到每次生成的 prompt 尾部，确保跨镜品牌一致。

## STEP 0：素材收集与生产规格

捕捉：品牌 / 产品名称；用户手上有哪些素材（LOGO / 产品图 / UI 截图 / 官网链接 / 只有一个想法）；推广目标（新品发布 / 官网展示 / 社媒推广）；投放渠道；目标受众；推广重点。

**素材收集（强制问询）**：在任何故事规划或生成之前，请用户提供可核验素材：

- LOGO 文件或官方 LOGO 来源页面
- 字体文件 / 字体名称 / 字体规范，或能体现品牌字体的官方网站页面
- 品牌颜色、色彩系统、风格指南，或能清楚体现官方色彩的页面
- 产品图片、UI 截图、包装、渲染图、视频素材
- 产品信息：官方产品名称、功能列表、发布重点、宣传主张、CTA、免责声明、目标受众
- 公司 / 产品官网或官方资料包

默认把用户上传素材视为可用于前期方案与概念制作，不要在第一轮反复单独追问「是否有授权」。只有出现具体风险信号时才追问（可见第三方水印、明显抓取的电商 / 图库图、用户表述互相矛盾、涉及法律 / 医疗 / 金融合规主张、用户明确要求商用发布）——此时素材仍记录为「用户提供」，在来源清单里标注权利注意事项，而不是阻塞流程。

**语言规则**：旁白与画面文案语言按品牌素材、目标受众与投放平台判断，不机械跟随聊天语言。品牌素材与可见来源文案以英文或全球企业英文为主时，默认英文旁白与文案，除非用户明确要求中文本地化。用户用中文聊天或说「我是新用户测试」时，聊天回复保持中文，但视频实际文案按最适合该品牌传播的语言规划。**只有用户明确指定语言时才锁定语言。**

**身份核验红线**：LOGO、产品界面、人物、吉祥物、包装、字体、色彩系统等带身份识别资产无法认证时，停下索要授权原件；不生成「看起来像」的替代品。

随后查库与生产规格（选项卡，依次）：

1. **查库**：`asset_list()`。库中已有品牌风格锚点（如 `style:acme-brand`）或产品资产时，出【复用范围】选项卡：本次复用（直接以资产 id 引用）/ 全新 / 部分复用。
2. **画面比例**：16:9 横屏（官网 / 大屏推荐）/ 9:16 竖屏短视频 / 1:1 方形 / 4:5 社媒竖图 / 4:3 / 3:4 / 匹配用户参考图。
3. **总时长**：15 秒（推荐，快速发布片）/ 30 秒 / 45–60 秒 / 自定义。镜头数：15s → 2–3 镜，30s → 3–6 镜，45–60s → 5–10 镜（单镜 5–15 秒，见镜头表规则）。
4. **音频模式**：`silent` 纯音乐音效（BGM + SFX，无口播，零口型风险，产品宣传片推荐）/ `narration-led` 旁白主导（原生旁白 + BGM，讲解式宣传）。`dialogue-led` 不在本 Skill 范围。
5. **生成档位**：`fast`（调试 / 调构图，长边 832）/ `balanced`（日常，画质与耗时平衡，长边 1344）/ `quality`（成片，长边 1344）。允许先 fast 走通全片再升档重出（`fast`→`balanced`、`fast`→`quality`、`balanced`→`quality` 都允许）。

确认后用 `canvas_set_state` 持久化（aspectRatio / duration / audioMode / mode），**同一次调用一并传 `groupOrder=["brand intake","creative plan","asset plates","shot clips","final delivery"]`**，并写入生产简报。

> **档位必须逐镜显式传**：之后每次 `comfy_generate_video` 都显式写 `tier=fast|balanced|quality`，**不要依赖缺省**——缺省是 `quality`（成本最高档）。

画布产物按以下顺序创建，每产出一个立刻上画布，不要把长篇生产内容只丢在对话里：

1. 生产简报（text，group `brand intake`）
2. 品牌事实表（text，group `brand intake`）
3. 来源清单（table，group `brand intake`）
4. 品牌资产节点（image，group `asset plates`；用户素材上画布 + 生成板）
5. 创意方向（text，group `creative plan`）
6. 六列标准镜头表（table，group `creative plan`）
7. 单镜头视频片段（video，group `shot clips`）
8. 拼接成片（video）+ 交付清单与终检（text），均 group `final delivery`

**分组名由本 Skill 定义**（插件不预设任何片型词汇）。之后所有 `group` 参数必须用上面这五个精确名字；未声明的分组会排在末尾。

## STEP 1：品牌事实表

研究或检查最可靠的来源，写品牌事实表到画布文本节点（group `brand intake`）。来源可信度层级：

1. 用户提供的原始导出文件
2. 官方网站、静态资源包、新闻中心、品牌门户、媒体包、新闻资料包或官方仓库（用 `web_search` 检索）
3. 公司控制的官方媒体库
4. 授权图库或授权合作方资料包

**不要**使用 LOGO 聚合站、搜索缩略图、粉丝重绘、Pinterest 转发或 AI 生成替代品作为带身份识别的来源。程序化图形只可作为非写实动效层：遮罩、渐变、色块、网格、辉光、粒子、轨迹、排版、已验证数据图表、转场几何。

提取项（逐项写进事实表；核验不了的标「未核验，待用户确认」）：

- 精确 LOGO 变体、安全空间、使用限制
- 官方字体或可见的字体行为
- 主色、辅助色、动态品牌色
- 品牌语气、原则、视觉母题、交互语言
- 当前产品名称、功能、场景、指标、口号、CTA、免责声明
- 官方摄影、渲染图、UI 截图、视频素材、媒体包内容清单
- **产品外观卡**（供 prompt 复用）：产品外形、颜色、材质、文字元素、包装细节、签名交互——用当前模型自身视觉从用户素材逐项精确描述（当前模型不支持图片输入时回退 `describe_image`）

选项卡：沿用此事实表继续（推荐）/ 补充素材 / 修正部分事实 / 调整品牌调性。

## STEP 2：来源清单

把来源清单写成画布表格节点（group `brand intake`），覆盖每个带身份识别的资产：

| 资产 ID | 角色 | 画布节点 | 来源 | 来源类型 | 验证目标 | 权利说明 | 真实性状态 |
|---|---|---|---|---|---|---|---|

- 资产 ID：`brand:acme-logo`、`brand:acme-product-front` 这类稳定 id，供镜头表引用。
- 来源类型：官网 / 媒体包 / 用户原件 / 授权图库 / AI 生成抽象层（抽象层不算身份资产，不得占用身份资产 ID）。
- 真实性状态：`verified`（与官方来源比对一致）/ `user-supplied`（用户提供原件）/ `licensed`（已授权）/ `blocked`（核验失败，不得作身份锚点）。
- 来源清单本身不等于发布授权。授权不明确时，成片标注为**非官方概念片**，并告知用户商业发布需要许可。

选项卡：批准清单（推荐）/ 修正某条来源 / 标记某资产为 blocked。

## STEP 3：品牌资产上画布与绑定策略

参考绑定（`ref_nodes` / `first_frame_node`）只接受**画布图片节点 id 或资产库 id**。用户给的 LOGO / 产品图通常是聊天附件或本地文件，需要上画布：

1. **先查库**：`asset_list()` 命中同一素材（如 `style:acme-brand`）就 `asset_to_canvas(id=资产 id)` 物化到画布，直接以资产 id 引用，不再上画布。
2. **拿到文件**：请用户把素材放进会话工作区（Web：在聊天输入框发送图片并告知 Agent 文件位置；飞书：文件已在会话工作区），或直接给绝对路径。
3. **核验后上画布**：用当前模型自身视觉确认是官方版（与事实表一致、无第三方水印、无价格标签 / 货号贴纸；当前模型不支持图片输入时回退 `describe_image`）。核验不过 → 拒绝上画布，索要官方原件。
4. **写入画布节点**：把文件复制到工作区 `canvas/<sessionId>/`，取插件会话 token 后调插件 API 创建图片节点（实测可用）：

   ```bash
   SID="$DSH_SESSION_ID"
   TOKEN=$(curl -s "$DSH_WEB_URL/dsh-short-video-studio/" \
     | grep -o '__DSH_SVS_TOKEN__ = "[^"]*"' | sed 's/.*"\(.*\)"$/\1/')
   curl -s -X POST "$DSH_WEB_URL/dsh-short-video-studio/api/canvas/node?sessionId=$SID" \
     -H 'content-type: application/json' -H "x-dsh-svs-token: $TOKEN" \
     -d '{"kind":"image","title":"acme logo 板","media":"canvas/<sessionId>/logo.png","group":"asset plates"}'
   ```

   节点标题必须起得有意义（飞书自动送达用节点标题作文件名，如「acme logo 板」而非「图片1」）。返回的节点 id 记入来源清单「画布节点」列。
5. **提示人工入库**：告诉用户可在画布点该节点的「入库」按钮登记为跨会话复用资产（人工登记，AI 不自动入库）。
6. **上画布失败**（API 不可用等）→ 该素材降级为**描述锚点**，来源清单标注「上画布失败，描述锚点」。

**两级资产绑定策略**（STEP 7 按镜头表「策略」字段逐镜执行）：

- **一级 · 真锚点（素材已上画布 / 在库）**：
  - **LOGO 锁定镜**：LOGO 板作 `first_frame_node`（首帧锁定）——画面逐像素继承 LOGO，prompt 只写动效（辉光 / 粒子 / CTA 文案浮现），LOGO 绝不重绘。
  - **界面锁定镜**（UI 需原样呈现）：UI 截图作 `first_frame_node`，屏幕内容保持真实，prompt 只写镜头与光线。
  - **产品英雄镜**：干净产品图（无图内文字）作 `ref_nodes` 参考绑定。
- **二级 · 描述锚点（素材只在聊天里，未上画布）**：
  - prompt 引用事实表的「产品外观卡」精确描述产品外观，模型原生渲染。
  - 终检严格对照事实表核对成片中的 LOGO / 产品：不准 → 请用户给文件走一级上画布重出该镜，或明确标注「概念片」。

品牌素材的参考图硬规则增量（在插件契约之上）：

- LOGO 板只用**单张整图**；不要把深浅色变体 / 多配色拼成一张图。
- UI 截图与 LOGO 字标的图内文字是固有的，不同于角色卡——因此只能**首帧锁定**使用；**不要把含文字的 LOGO 板 / UI 截图放进 `ref_nodes`**（图内文字会被印进环境）。
- 产品图带电商水印、价格标签或货号贴纸时，先请用户给干净版；拿不到就不上画布。

## STEP 4：创意方向

用户尚未选定方向时，给出 2–3 个简短创意方向（推荐一个并给一句理由）写到画布文本节点（group `creative plan`），确认后继续。按产品类别选叙事脊柱：

- AI / SaaS：用户意图 → 思考或规划 → 能力 → 执行 → 有用输出 → 证明 → LOGO
- 实体产品：英雄展示 → 交互 → 功能特写 → 使用场景 → 结果 → LOGO
- 服务 / 公司：背景 → 流程 → 证据 → 成果 → 承诺 → LOGO
- 图像主导品牌：真实影像 → 视觉母题 → 利益点 → 情绪回报 → LOGO

故事必须产品专属：展示真实功能、交互、场景、输出与证明，不要用抽象特效掩盖薄弱的产品叙事。

选项卡：选方向 A（推荐）/ 方向 B / 方向 C / 自定义。

## STEP 5：六列标准镜头表（节拍计划）

创意方向确认后，用 `canvas_write_node(kind=table, group="creative plan")` 输出镜头表。本步为强制步骤。表格必须严格按以下顺序包含六列：

| 镜头编号 & 时长 | 视觉主导 & 资产绑定 | 节拍功能 | 镜头描述（每秒指令） | 文案与字幕轨 | 音频与转场轨 |
|---|---|---|---|---|---|

列规则：

- **镜头编号 & 时长**：镜头号加计划时长，如 `S03 / 5s`。视频工作流按 24fps 帧数生成，时长走 17k+5 帧网格（124 ≈ 5s / 141 ≈ 6s / 158 ≈ 7s / 175 ≈ 8s / … / 362 ≈ 15s）。单镜 5–15 秒（`balanced` / `quality` 档；短于 5s 属未测区，仅 `fast` 档调试可用）；总时长之和必须等于生产简报的总时长。
- **视觉主导 & 资产绑定**：三个子字段全部必填。
  - `视觉主导` — 本镜叙事主体：产品 / UI / 手部交互 / 抽象动效 / 品牌角色。
  - `资产` — 来源清单的精确资产 ID + 画布节点 id / 资产 id（`text` 策略写 `none`）。
  - `策略` — `first-frame`（首帧锁定：LOGO / UI）/ `ref`（参考绑定：干净产品图）/ `text`（纯文字生成：抽象动效层，无身份资产）。
- **节拍功能**：受控词表取一：`brand-hook` / `intent-setup` / `mechanism` / `capability` / `scenario` / `proof` / `payoff` / `logo-cta`。
- **镜头描述（每秒指令）**：按秒拆解 `0–1s`、`1–2s`…，每条每秒指令必须覆盖 5 个要素：
  1. 构图与主体位置（产品 / UI 在画面哪个 1/3、前 / 中 / 后景、视觉主导位置）
  2. 镜头运动（推 / 拉 / 摇 / 倾 / 环绕 / 锁定 / 手持 / 升降）
  3. 产品或主体动作（交互、光效、滚动、光标、边缘运动、光流）
  4. 光位与色彩状态（全片 2–5 个色彩状态之一 + 主光方向）
  5. 交接（与下一秒或下一镜如何衔接）
  另加镜级负向约束：不生成事实表之外的品牌元素、无未验证指标、无水印。
- **文案与字幕轨**：字段：
  - `画面文案` — 文案文本 + 语言 + 出现时机 + 可读停留（≥1.5s）；**每镜 ≤2 行**；无文案写 `none`。
  - `CTA` — 仅尾镜：行动号召（按钮文案 / 口号 / 官网）。
  - `旁白`（仅 narration-led）— 画外讲述人的台词、语气、时间范围；**一镜一个讲述人，无出镜说话角色**。
  - 文案在成片中以**画面内原生文字**呈现（H3 路径的 on-screen text 声明，见 STEP 7），不需要后期字幕。
- **音频与转场轨**：字段：
  - `BGM 状态` — `buildup` / `sustain` / `peak` / `brake` / `resolve`；全片弧线完整（只在关键信息处制动）。
  - `SFX` — 产品声 / UI 声 / 转场声，按时间锚定。
  - `转场` — `hard-cut` / `motion-handoff`（出场动作带出下一镜）/ `transition-shot`（跨场景边界，需生成转场镜）。

表格全局规则（动效语言规范）：

- 镜头数：15s → 2–3 镜，30s → 3–6 镜，45–60s → 5–10 镜；**尾镜必须是 `logo-cta`**（LOGO 锁定 + CTA）。
- 每镜（除开场 `brand-hook`）必须呈现产品 / 品牌证据（功能 / 交互 / 场景 / 输出），不允许纯氛围填充镜。
- 每秒一个主动作；次级层稍作延迟。全片 2–3 个高能峰值 + 安静制动时刻。
- AI / SaaS 产品至少包含一条可读链路（提示词 → 规划 → 并行能力 → 生成结果 → 证明）；实体 / 服务产品展示从用户动作到具体成果的因果。
- 避免虚假 HUD、随意玻璃卡片、装饰性文字墙、未经验证的指标，以及全片同一种缓动。
- 色彩状态 2–5 个、各绑定含义；每秒指令显式引用色彩状态名。
- 画面文案语言遵循 STEP 0 语言规则。

选项卡：批准表格并进入自检（推荐）/ 调整镜头连续性 / 加强产品证据 / 调整文案节奏 / 调整色彩状态。

## STEP 5.5：镜头表自检门（强制）

进入生成前必须对已批准的镜头表跑硬性自检。任何一项不通过必须先修订表格再重跑。

八项必检：

1. **总时长与网格**：镜头时长之和等于总时长（±1s）；每镜时长在 17k+5 帧网格上（124 / 141 / 158 / …）且 ≥124 帧；单镜 ≤15s。
2. **节拍覆盖**：创意方向（脊柱）的每个节拍都被某镜覆盖；尾镜是 `logo-cta`；AI/SaaS 有可读链路、实体产品有因果链。
3. **证据镜**：每镜（除开场 `brand-hook`）呈现产品 / 品牌证据；无纯氛围镜。
4. **文案可读**：每镜画面文案 ≤2 行、可读停留 ≥1.5s、语言与简报一致；尾镜有 CTA；文案文本可逐字落板（无「xxxx」占位）。
5. **资产绑定**：每个 `first-frame` / `ref` 策略都有真实画布节点 id / 资产 id；镜头表引用的身份资产在来源清单里均为 `verified` / `user-supplied` / `licensed`；无 AI 生成替代。
6. **色彩状态一致**：2–5 个色彩状态已定义（记录在事实表 / 视觉锁），每秒指令引用它们；无未说明的色彩跳变。
7. **转场链**：每镜 `转场` 与下一镜开篇衔接一致；**每个跨场景边界的前一镜最后 0.5s 无画面文案且无旁白**（末帧干净，转场镜不继承烧录文案）。
8. **音频一致**：BGM 状态弧线完整（有 buildup / peak / brake / resolve）；narration-led 镜有台词 + 时间范围且讲述人为画外；silent 镜无旁白；未与原生 BGM 并存「独立 BGM 轨」计划。

八项全过后，在画布表格节点顶部加 `shot-table self-check: passed at <时间戳>` 戳，并出选项卡：批准自检并进入硬确认（推荐）/ 查看自检详情 / 修订失败项 / 重新跑自检。

任何一项不通过就不进入 STEP 6：返回 STEP 5，列出失败行，修好并重跑自检通过后才能再次展示硬确认选项卡。

## STEP 6：生成前硬确认

生成任何视频或图片序列之前，必须先向用户展示完整**前期方案包**（要点写进回复正文，产物已在画布）：

- 来源清单（或摘要）
- 品牌事实表（或摘要）
- 已选创意方向
- 镜头表（节拍计划）
- 画面文案、CTA、旁白与声音方案
- 已知的真实性、授权或占位说明（含「概念片」标注）

选项卡（硬门）：批准并开始生成（推荐）/ 调整镜头表 / 调整画面文案 / 调整创意方向 / 暂停制作。

用户在看过方案后明确表达推进意图（「确认」「生成」「go ahead」「继续」「可以」等）即视为批准，除非同一句话同时要求修改；但选项卡前必须先展示前期方案包摘要，不静默开跑。用户要求跳过流程时，先给简版来源清单 + 事实表 + 镜头表，用户明确同意推进后再生成。

## STEP 7：逐镜视频生成

### 渲染前的门

前期方案包批准后，先确认渲染参数选项卡：

**生成档位**：沿用 STEP 0 选择（推荐）/ 切 `fast` 先走通全片 / 升到 `balanced` 或 `quality` 出成片 / 本镜临时改档。**逐镜调用必须显式传 `tier=`**（`fast` / `balanced` / `quality`），不要依赖缺省——缺省是 `quality`，成本最高。分辨率由画布 `aspectRatio` + 档位自动推导（`fast` 长边 832、`balanced`/`quality` 长边 1344）；用户要单镜 hero 画质时才显式传 `width`/`height`。

**档位与能力可用性**：一个能力支持多档，**具体有哪些档、每档什么代价，以 `comfy_list_workflows` 为准**（不同能力可以不同，用户增删工作流后也会变）——不要假设档位数量或名称。请求了该能力没有的档会**显式报错并列出可用档位**（工具不会静默换档）。遇到这类报错就改请求可用档位，**不要原样重试同一请求**。

**档位与分辨率/耗时同源**：工具返回会带 `tier` / `implementation` / `resolution`，回复与交付清单里如实回报**实际用到的实现 id**（透明化）。实测参考（16:9 · 124 帧 ≈ 5.17s，随硬件/驱动/模型版本浮动，只作量级参考）：ref2v `fast`(832×480) 24.6s ｜ `balanced`(1344×768) 166.3s ｜ `balanced` 带加速 136.3s ｜ `quality`(1344×768) 396.6s ｜ `quality` 带加速 311.2s；i2v `fast` 26.1s ｜ `balanced`(1344×768) 177.3s ｜ `balanced` 带加速 130.5s ｜ `quality` 394.8s ｜ `quality` 带加速 314.7s。画质：`balanced`(8 步) 帧锐度比 `quality`(20 步) 高约 13%；`fast` 档细节最弱、适合调构图 / 走位。

**工作流**：默认由能力注册表 `preferred` 决定，不出选项卡。仅当用户主动要求换模型时，先 `comfy_list_workflows` 核对能力，再出工作流选项卡，选定后用 `comfy_render` 显式传 `workflow`，并把选择记入生产简报。

### 参考绑定策略（逐镜按镜头表「策略」执行）

> 以下所有逐镜调用都要显式带 `tier=`（STEP 7 渲染前的门选定），不要依赖缺省。

- **`first-frame` 镜（LOGO / UI 界面锁定）**：`comfy_generate_video(tier=档位, first_frame_node=板节点 id, …)` —— 首帧锁定，身份逐像素继承自帧。
- **`ref` 镜（产品英雄）**：`comfy_generate_video(tier=档位, ref_nodes=[干净产品图节点 id])` —— 参考绑定。
- **`text` 镜（抽象动效层）**：不传参考图，纯文字生成。
- **同场景续接镜（i2v 首帧串联）**：先 `extract_frame(video_node=上一镜片段节点)` 抽末帧，再 `comfy_generate_video(tier=档位, first_frame_node=末帧节点)` —— 首帧串联，环境直接从真实画面继承。**不传 `ref_nodes`**（i2v 工作流无参考图注入点，传了会被静默忽略）；且仅当上一镜末帧已包含本镜全部在屏主体（产品 / 吉祥物 / 人物）时才可用——末帧缺任一主体（如新主体登场）的镜禁止 i2v，必须改走 `ref` 参考绑定。
- **跨场景镜绝不带上一镜末帧**（跨场景过渡交给下面的转场镜）。
- 节点 id 可用画布节点 id 或资产 id（如 `style:acme-brand`）。

### prompt 组装（逐镜）

按以下顺序组装：

1. **H3 结构化重写（委托 `h3-prompt-writing` skill，主路径）**：调用 skill 工具加载 `h3-prompt-writing`，按它的规范（官方 `base-en.txt` / `ref-en.txt` + `references/studio-mapping.md` 映射表）把本镜「镜头表行 + 品牌视觉锁」重写为 H3 结构化 prompt：
   - **`ref` 镜**（无首末帧）→ **Ref2VA 六段式**：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`；
   - **`first-frame` 镜** → **I2VA 三段式**：对齐指令（首行）+ `integrated_multimodal_description` + `overall_soundscape` + `non_diegetic_music`；
   - **转场镜** → **FL2VA 三段式**（首帧 + 末帧）。
   - **条件启用**：仅当解析到的工作流 id 前缀为 `minimax-h3-` 时走本路径；其他工作流跳过，直接走 2 的自由格式组装（模型无关，不写死模型名）。
   - **画面文案**：H3 路径下文案声明**内嵌在 `detailed_description`**（on-screen text 声明，与字幕同一实验定稿手法：英文双引号声明 + `reading exactly "原文"` 逐字要求 + 强调描边/对比 + **只给结束点、不给起止时间窗**），不追加末尾中文指令。**配方以 `h3-prompt-writing` 的 §字幕（唯一权威版）为准**（画面内原生文案与字幕同源同法）。
   - **画面文案的档位不是硬规则**：每一档都能要求出画面文案，由用户 / 脚本需求决定；实测 `quality` 20 步画面内文字逐字一致、`balanced` 8 步画面内**英文标牌**亦逐字一致，但**字幕（对白联动）**在 `balanced` 实测整段未烧、`fast` 有错字 —— 因此**身份/文案关键的镜建议走 `quality`**，其余档出文案必须经自检门逐镜核对字准，不过再给「升档重渲该镜 / 改短文案 / 拆镜」选项（**不是"文案镜必须 quality"的硬规则**）。
   - **BGM**：`non_diegetic_music` 写品牌安全的器乐（风格 / 速度 / 情绪 + 本镜 BGM 状态，如 `minimal electronic, 100 bpm, confident, build-up`）；**全片基底描述保持一致**（同一底色的曲），各镜只变强度；纯 SFX 无 BGM 的镜写 `N/A`。
   - **旁白**（narration-led）：用官方 off-screen voiceover 句式 + `<d>语言 台词</d>`；无出镜说话角色，无口型要求。
2. **自由格式兜底（仅非 H3 工作流）**：从镜头表每秒指令展开成自然语言镜头描述；画面文案在末尾加中文指令：「画面指定位置显示清晰文字「<文案文本>」，可读停留至 <时间>」。
3. **品牌视觉锁后缀**：色彩状态关键词 + 调性 + 负向约束（两种路径都追加）。
4. **负向意图**：不生成其他品牌元素、无未验证指标、无水印、无真人面孔（除非品牌素材即人物）、无分镜痕迹、不把参考图内文字印进环境。

`length` 为 24fps 帧数（124 ≈ 5s），按镜头表时长换算。片段写入 group `shot clips`，标题带镜头号与功能（如「S03 产品交互镜」）。

### 逐镜失败回退阶梯

0. **（仅 H3 结构化路径）先检查重写本身**：若本镜走了结构化重写且质量倒退（文案字准 / 身份一致性 / 音频任一指标），先回退该镜为自由格式 prompt 重渲，**prompt 首行加 `[PROMPT_FALLBACK]` 标记**（质检门据此放行），再走下面的重试阶梯。
1. **第一次重试**：强化 prompt——直接引用事实表「产品外观卡」与品牌视觉锁，缩短冗余措辞。
2. **第二次重试**：缩到 ≤6s（141 帧），简化动作（减少每秒动作数），或把一行文案拆到两镜。
3. **第三次重试**：改档验证是 prompt 问题还是采样问题——**文案字准类问题升档**（`fast`/`balanced` → `quality`），**只是想省成本或排查链路才降档**（`quality` → `balanced`/`fast`，注意 `first-frame`/续接/转场镜走 i2v，无 `balanced`，会报错）；或降低节拍强度。
4. **同一镜连续 3 次失败**：选项卡问用户——换工作流（先 `comfy_list_workflows`）/ 放宽要求 / 跳过该镜并在下游标记 `placeholder: missing clip` / 用户手动提供素材或成片片段。

不要重复提交未改动的同一请求。

**语义失败恢复**（来自官方，跨镜适用）：

- LOGO 不准 / 近似：移除，重新上画布官方文件（一级锚点）或改描述锚点，重出该镜；绝不「美化仿制品」。
- 产品 / UI 看起来虚假：替换为官方 / 用户原件 / 授权素材；不要美化仿制品。
- 好看但通用：加入完整产品交互、已验证主张或真实输出。
- 快但混乱：减少同时动作，指定视觉主导，保持跨镜头匹配运动。
- 顺滑但太慢：缩短停留，让出场动作带出下一镜，只在关键信息处制动。
- 资产不可用：索要授权原件，绝不猜测。

### 跨场景转场镜

所有正片片段出完后，为每一个**跨场景边界**（如棚拍 → 生活场景、产品特写 → 使用场景）生成一个转场镜：

1. `extract_frame(video_node=前一镜片段, frame_index=-1)` → 前一镜末帧。
2. `extract_frame(video_node=后一镜片段, frame_index=0)` → 后一镜首帧。
3. `comfy_generate_video(tier=档位, first_frame_node=末帧节点, last_frame_node=首帧节点, length=…, prompt=过渡意图, group="shot clips", title="S03→S04 转场")` —— 首末帧串联，模型自己补出中间运动，收尾精确落回后一镜首帧。
4. 转场镜作为**普通片段**参与 STEP 8 的拼接顺序，插在两镜之间。

转场 prompt 只写镜头运动与光线变化（如「镜头掠过产品边缘滑向生活场景，冷棚光渐变为暖日光」），**不写产品动作、不写文案与旁白**，音频按 `silent` 处理。

三条实测约束，必须遵守：

- **避开带文案的帧**（实测硬规则）。`narration-led` 或有画面文案的镜，末帧上可能烧录文案——自检门第 7 项已强制「跨场景边界前一镜最后 0.5s 无文案」；仍命中时抽帧往前挪（如 `frame_index=-12`）取文案消失后的帧。
- **`length` 走 17k+5 网格**（5 / 22 / 39 / 56 / 73 / 90 / 107 / 124…），模型训练区间 **124–362 帧**；短于 124 属未测区（实测 `length=39` + fast 档中段会糊）。转场镜建议至少 `length=56`，**成片一律用 `quality` 档重出**，fast 只验证链路。
- **分辨率必须与前后镜一致，否则拼接失败**；转场镜显式传与正片相同的 `width`/`height`，并**与正片用同一档位**——`fast`（长边 832）与 `balanced`/`quality`（长边 1344）出的片段混在同一条成片里会因分辨率不一致而拼接失败。**跨档升档必须在生成前决定**（全片同一档），不要到拼接时才发现混档；已混档的片段要先统一档位重出再拼。

同场景续接镜不需要转场镜——首帧串联本身已经连续，插转场反而暴露剪辑点。

抽出的末帧 / 首帧图片节点也归 `shot clips` 组，它们是中间产物，终检时不计入镜头数。转场镜自带模型生成的音频，终检时必须逐条听过，有杂音或幻听人声就重出。

### 片段批准

所有片段渲染完成后按镜头顺序放到画布（group `shot clips`），出选项卡：批准片段并进入交付（推荐）/ 重渲染选定片段 / 修复身份不一致 / 加强品牌锁一致性 / 修复跨片段色彩状态跳变。

若片段与已批准的镜头表漂移（产品位置、色彩状态、文案时机），用直接引用该镜头表行的强化提示重渲；不要在交付时静默混合修正版与未修正版。

## STEP 8：拼接、交付与终检

### 拼接全片

所有片段批准后，用 `video_concat(nodes=[按镜头表顺序的片段节点 id，含转场镜], title="拼接成片", group="final delivery")` 拼成完整成片（含音轨）。后端由插件自动选择（ffmpeg / ComfyUI 链路），对本 Skill 透明。

拼接的三条限制，必须提前告知用户：

- **拼接本身只做硬切，没有溶解**——跨场景过渡由 STEP 7 生成的转场镜承担；没做转场镜的成片就是直切。
- **所有片段必须同分辨率**（同一档位出的片段天然满足）。`fast` 长边 832 与 `balanced`/`quality` 长边 1344 **不能混在同一条成片里**——混了就先统一档位重出。**跨档升档要在生成前决定**（全片同档），不要到拼接时才处理：`balanced` 与 `quality` 长边相同（1344），拼接不会失败，但**同一条片子里混不同实现会导致观感/像素漂移**，品牌片尤其不要混。
- **无独立 BGM 工作流**——BGM 与旁白是各镜原生生成音频，拼接时原样保留；用户需要可单独替换的轨时列入未落地项。

### 交付清单

在 group `final delivery` 写一个交付清单文本节点，包含：

- 拼接成片的节点 id、媒体路径、总时长。
- 按镜头表顺序的片段清单（镜头号 → 画布节点 id → 媒体路径 → 时长）。
- 未落地项：可单独替换的 BGM / 旁白轨（若用户要求）、需要人工补的转场位置、平台裁切建议（9:16 vs 16:9）。
- 权利说明：官方 / 非官方概念片；商用发布需确认身份资产授权状态。

**终检清单**（逐条核对并写进交付节点）：

- **身份真实性**：LOGO 与身份资产来自已验证 / 用户授权来源（来源清单）；最终 LOGO 未被拉伸、裁切或重建（首帧锁定镜逐像素核对）；描述锚点镜的产品外观与事实表一致，不一致的标注「概念片」。
- **文案正确**：产品名称、功能表述、主张、指标、口号、CTA 与官方来源一致，或被明确标注为概念文案；画面文案文本与镜头表 `画面文案` 字段逐字一致，停留足够、无错字。
- **简报符合**：视频时长、画面比例、语言符合生产简报。
- **品牌一致**：色彩状态 2–5 个不超配；品牌视觉锁跨镜一致；无其他品牌元素、无未验证指标、无第三方水印。
- **无参考图污染**：成片里没有从参考图带进来的水印 / 标注，也没有同一身份的多个副本。
- **音频可听**：BGM 弧线完整且跨镜连贯（不像多段拼接）、SFX 与画面同步；narration-led：旁白清晰；无幻听人声（转场镜逐条听过）。
- 缺失或薄弱片段；任何可能需要重做的资产。
- 下一轮可改进的具体建议：节奏、主张清晰度、CTA、音频或平台裁切。

### 渠道交付（飞书 / TUI）

「画布」tab 只在 Web 可见；跑在 TUI / 飞书时用户看不到画布，交付阶段要把产物送达用户，而不是只写交付清单：

1. **ask 前自动送达**：飞书渠道下，插件会在每次 `ask_user_question` 执行前自动把画布中未送达的产物经 `send_file` 送达——片段 / 成片 / 板等媒体直接发原文件；事实表 / 来源清单 / 镜头表 / 交付清单等文本节点自动导出为 .pdf 一并送达（本机无 PDF 工具时兜底 .html）。**发送的文件名取自节点标题**（如「S03 产品交互镜.mp4」「来源清单.pdf」），所以给节点起有意义的标题。**不要手动调 `send_file`**，避免重复。群聊会先弹审批卡、再出选项卡，照常调用、由用户在飞书确认。
2. **文本同时进回复**：交付清单要点除 .pdf 文件外，写进 ask 前的回复正文，飞书回复本身即可读。
3. 没有 `send_file`（Web / TUI）则产物已在画布 / 工作区，无需推送；TUI 用户按工具返回的 `absPath`（绝对路径）自行打开。
4. `send_file` 单文件默认上限 20 MiB：成片或长片段超限导致自动送达失败时改用 fast 档 / 更短镜头 / 分镜分开发，或提示用户到画布取。

选项卡：批准交付（推荐）/ 重渲染选定片段 / 升档重出全片（`balanced` / `quality`，全片同档）/ 补做终检某一项 / 给出下一轮迭代建议。

## 画布归组纪律

每生成一个耐用产物立刻上画布并归组（生成工具自动上画布的不重复写）。本 Skill 的分组词汇（已在 STEP 0 通过 `groupOrder` 声明）：

`brand intake`（生产简报 + 事实表 + 来源清单）· `creative plan`（创意方向 + 镜头表）· `asset plates`（品牌资产上画布节点 + 生成板）· `shot clips`（单镜片段 + 转场镜 + 抽取帧）· `final delivery`（拼接成片 + 交付清单 + 终检）

一轮生成产出 2 个或更多产物时立刻 `canvas_group_nodes` 归组并起清晰标题。顺序错乱时用 `canvas_reorder` 修正。

## 用户选项卡纪律

每个需要用户确认的地方都用 `ask_user_question` 选项卡，不允许用纯对话问题或散文代替。强制门：

- 查库后（库非空）：复用范围
- 任何产物之前：画面比例 / 总时长 / 音频模式 / 生成档位
- 事实表后 · 来源清单后 · 创意方向后
- 镜头表后（门 1：批准表格进入自检）
- 自检通过后（门 2：批准自检）
- 生成前硬确认（门 3：前期方案包）
- 渲染档位确认 · 片段后 · 交付后
- 任何「同一镜连续 3 次失败」的求助点

默认推荐项放最前，始终允许用户自定义输入。用户说「继续」时按选了推荐项处理。

## 重生成与最新资产纪律

用户重做或修订任何产物时，下游步骤必须用最新批准的产物：

- 品牌事实表 / 来源清单修订后，下游镜头表、prompt 与片段必须用新表事实与资产 ID；旧版本在画布上明确标记废弃。
- 品牌资产重新上画布后，所有引用该资产的镜头必须用新节点 id；旧上画布节点标记废弃。
- 镜头表修订后，**STEP 5.5 自检必须重跑**通过后才能进入生成。
- 创意方向更换后，镜头表必须重建。
- 片段重渲后，必须用新片段重跑 `video_concat`，交付清单与终检也随之更新。
- 换工作流重渲时，在生产简报记入新工作流，并重检该镜的绑定策略。

任何重做后：在下一条回复中标明重做产物为当前批准版本；后续调用一律用新节点 id；画布上同时存在多版本时先指明当前选用版本再继续；不要在交付清单里静默混合新旧资产。

## 边界

KOC 口播带货广告、复杂屏幕演示教学、单张图片、简单修图、长篇剧情影片不用本 Skill。音频模式只支持 `silent` 与 `narration-led`，**`dialogue-led` 不在范围**。注册表无独立 `audio.tts` / `audio.music` 工作流——可单独替换的 BGM / 旁白轨无法生成（只能原生音频或用户提供的音频文件）。不用于缺少授权素材时仿造真实品牌标识、虚构产品功能，或商用发布前未确认授权。
