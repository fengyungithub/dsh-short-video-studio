# 剧本变更 Runbook（production 过程中改剧本）

> 权威原则：**剧本只由 `short-drama-series-writer` 改；production 不改台词；story 不改台词。**
> 集制作包、状态、成本、交付由 production 重建/重批；拍摄规则与重渲执行由 story 负责。

---

## 1. 先定级（L1–L4）

| 级别 | 改什么 | 例子 | 重建 | 重渲 |
|---|---|---|---|---|
| **L1 台词级** | 措辞/语气/句长；事件、场次、人物不变 | 「你走吧」→「你现在就走」 | ③ 对白表、④ 台词/时长、提示词库 | 首个受影响镜 + 下游续接链 |
| **L2 场次级** | 增删/重排场次、走位、人物进出、道具状态 | 办公室戏改走廊戏 | ②③④⑤、镜头表、分镜 | 受影响场景 + 跨场景转场 |
| **L3 结构级** | 集目标/事件/钩子/卡点、拆集/并集、前后集连续性 | EP08 拆成 EP08/EP09 | ①–⑥ 整包、目录、相邻集包 | 整集；相邻集受影响部分 |
| **L4 资产级** | 新增/换角色、场景、道具、声线 | 加兼美、换绛珠声线 | ⑤、资产台账、`asset_ingest` | 所有引用该资产的集 |

> L1 也可能连锁：台词变长会改镜长，`接 S0x` 的下游必须顺次重渲。不要只看“这一句”。

---

## 2. 七步流程

### 2.1 停线 + 登记
- 该集 `stage=paused`；不删旧片段，只标「待定」。
- state 写 `changeRequest`：
  ```json
  { "id": "chg-ep003-01", "level": "L1", "scope": ["S04","S05"],
    "reason": "台词改短", "requestedBy": "user", "at": "…", "status": "open" }
  ```
- 受影响范围不再提交新渲染。

### 2.2 回 writer 改剧本
- 加载 `short-drama-series-writer`，改 `episodes/epNNN.md`（必要时 `episode-directory.md`）。
- writer 跑单集自检 / 合规；`scriptVersion` +1（v1→v2）。
- **production 不直接改台词；story 更不许改。**

### 2.3 production 影响分析
- diff v1/v2：场、句、人物、钩子、相邻集。
- 定级 L1–L4；列出受影响镜号/资产/相邻集；估重渲成本。
- 出 **G-CHG「剧本变更卡」**：
  - 变更摘要（逐条）
  - 影响面
  - 选项：**按影响面重渲（推荐）** / 只改台词不重排 / 整集重做 / 取消变更

### 2.4 重建集制作包
- 用新剧本重生成 `package.md`，`packageVersion` +1，跑 12 项包自检。
- 更新 ③④⑤、镜头预算、成本估计；L2/L3 重做场次/镜头意图；L4 加 `TO-BUILD`/asset id。
- 写入 `scriptVersion` / `packageVersion` / `episodeVersion`。

### 2.5 重新过门
| 门 | 什么时候必须过 |
|---|---|
| **G-B** | 剧本内容变更（writer 批次门） |
| **G-CHG** | 每次 production 期变更（批准影响面/成本） |
| **G-P 方案卡** | 镜头表/分镜/渲染参数有变化时 |
| **片段卡** | 重渲后，只审受影响片段 |
| **G-E 交付卡** | 重拼后重新交付 |
| **G-A 增量** | 新增/换角色/场景/道具/声线；先入库再进包 |

### 2.6 按级别重渲
- **L1**：改该镜 prompt bank → 重渲该镜 → 顺续接链重渲下游直到场景尾；重拼。
- **L2**：重做镜头表/分镜 → 重渲受影响场景 → 跨场景补转场镜 → 重拼。
- **L3**：整集重做；相邻集只改前情/钩子相关镜；目录与下集预告同步。
- **L4**：资产版本 +1 / 新 id；所有引用集按出现顺序重渲；已交付标 `superseded`。

**铁律**：
- 台词变 → 音频/口型都变，**不能只换音轨保留旧画面**。
- 镜长变 → 下游续接链必须顺次重渲，不能跳镜。
- 已交付不覆盖；新版本另存，旧版标 `superseded`。
- story 发现“装不下”只能退回，不许改字。

### 2.7 收尾
- state：`scriptVersion` / `packageVersion` / `episodeVersion` / `stage` / `costMinutes` / `rework`。
- 交付包带版本号；台账记「因剧本 v2 重渲 N 镜」。
- 改到钩子/卡点/人物关系 → 更新 `episode-directory` 与相邻集前情/下集预告，跑跨集抽查。

## 3. 不同时点改，代价不同

| 时点 | 代价 | 做法 |
|---|---|---|
| 建包前 | 最低 | 只改剧本，重建包 |
| 有包、未出镜头表 | 低 | 重建包 + 方案卡 |
| 有镜头表/分镜、未渲 | 中 | 重做表/分镜 + 方案卡；无片段成本 |
| 已渲部分 | 中高 | 首受影响镜 + 下游链重渲；重拼/重交付 |
| 已交付 | 高 | 重开新版本；旧版 superseded；只重做受影响范围 |
| 影响相邻集 | 最高 | 目录 + 多集包 + 跨集抽查 |

---

## 4. 三个例子

**EP03 改一句台词（L1）**
writer v2 → production 变更卡 → 包 ③④ 更新 → 方案卡（表未变可只批 diff）→ 该镜 + 下游链重渲 → 片段卡 → 重拼 → 交付卡。资产不动。

**EP05 加兼美（L2+L4）**
writer v2（场次级 cast 列全）→ 包 ⑤ 加 TO-BUILD → G-A 增量（生成卡/入库/台账）→ 包 ②③④⑤ 重做 → 方案卡 → 受影响镜重渲 → 交付。后续集复用 asset id。

**EP08 拆两集（L3）**
writer/目录改分集 → 生成 EP08/EP09 两包 → 重排 state 与目录 → 两集各自方案卡 → 重渲；EP07/EP10 前情/钩子同步检查；旧 EP08 标 superseded。

---

## 5. 反模式（不许做）

- ❌ production 在 `package.md` 里直接改一句台词。
- ❌ story 在镜头表里改字让它“装得下”。
- ❌ 只换音轨保留旧画面（口型对不上）。
- ❌ 改了镜长却只重渲本镜、不重渲下游续接。
- ❌ 覆盖已交付成片；新旧片段混拼。
- ❌ 资产改了但不入库/不更新台账，下一集又找不到。

---

## 6. 交接字段（story → production）

每集收尾仍交：`finalNodeId` / `clipNodeIds` / `shots` / `rework` / `costMinutes` / `warnings` / `assetNodeIds`；变更集额外交 `changedShots`（受影响镜号）与 `scriptVersion`。
