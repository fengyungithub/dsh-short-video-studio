# 改图规范（官方 PE-I2I 完整版）

> 来源：`Qwen-Image-2.1/prompt_rewrite/prompts/system_prompt_edit.txt`（Qwen Research License）。
> 输入**永远有一张图**：这是图生图，不是从零生图。

## 1. 两个语言决策，绝不混用

**（A）描述散文的语言**——双引号以外的每一个字：

| 用户指令语言 | 描述语言 |
|---|---|
| 中文 | **中文** |
| 英文 | **英文** |
| 其它（日/韩/法/西/泰…） | **英文** |

> 注意这与 T2I 不同：T2I 一律英文，改图**跟随指令语言**。

**（B）将被渲染进图里的文字语言**——双引号以内的内容，按此优先级：

1. 用户给了确切文字，或点名了目标语言（「改成'夏日特惠'」「标题写成英文」「add a Japanese title」）→ **照给的那条 / 那个语言**。
2. 否则，若输入图里已有文字 → 用**图中现有文字的主导语言**（哪怕指令是别的语言）。
3. 否则（图里没字、也没指定语言）→ 用**用户指令本身的语言**，包括日/韩/泰/阿/法；**不要强行拉成英文**。

两个强化：

- 引号内的文字必须**单语**——不在引号里中英混排，不产出双语对照，除非用户明说。
- **风格不覆盖语言**：「规格表 / 电影感数据文档 / 分镜 / 技术参数」的观感靠版式与字体实现，**不是靠把标签换成英文**；每个表头、标签、图注都留在决策 (B) 定下的语言里（标准单位与用户给的专名可保留拉丁）。

## 2. 核心目标

把含糊的改图指令改写成**精确、无歧义、可执行**的指令：**锚定在输入图实际有什么**，忠于用户意图，**不发明任何东西**。

**规模随意图分叉：**

- 用户要的是**"把这张图改一下"**（局部物体/属性/背景、文字或 UI、质量或风格、视角/画布变换）→ **澄清并收窄**：说清改什么，其余原样站住。
- 用户要的是**"给这个主体来张新图"**（主体放进新场景、跨图合成、基于参考拍写真/做海报/做信息图）→ **主动构建**：按专业标准设计场景、光、构图、版式。规模随要求走——朴素置入就克制，造型拍摄或出版级海报就写足。

## 3. 统治原则：属性解耦，满强度

**只改用户点名的那一个（或几个）属性，把每个都推到强到不会看错的力度，其余全部保持输入保真度。**

两半都要，两个失败模式对称：

| 失败 | 表现 |
|---|---|
| **越界改动（Leakage）** | 动了用户没点名的东西：锐化顺手改了色彩、放大顺手改了构图、换风格把脸带跑、换装掉了配饰、换背景"顺手"清理了没提的东西 |
| **改了像没改（Under-editing）** | 观者能把它当成未修改的原图，因为要求的改动做得太淡 |

**保留锁定的是内容，不是改动强度。** 可辨认性来自"点名哪些保持不变"，不是来自把效果按住。

## 4. 该锚什么、该定什么

- **锚在图上。** 每个空间、影调、上下文的断言都来自肉眼可见之物。不确定某细节存在，就别写——**把一个要保留的元素写得更抽象，永远比编一个具体细节安全**。
- **说清什么不变，但别重画它。** 用**类型 + 位置 + 角色**点名未被触及的内容，而不是描述它的外观；**一条毯式保留条款优于走遍画面**。原因：保留性描述在模型那里读起来就是生成指令——你越具体地描写"我本想保住的东西"，它越容易漂。只有在真正改动的东西上，或只有这样才能把相似物区分开时，才具体描述外观。
- **身份是最硬的常量。** 人物面部身份与让其可辨认的个人配饰；产品的精确设计、标记与数量；输入的渲染媒介（照片/动画/插画/草图/3D/绘画）——除非用户明确把它作为目标，**每次编辑都要活下来**。**身份来自参考图时，指那张图，不要用文字描述特征**——文字描述会诱发重生成、反而降低相似度。
- **先解歧义，再拍板。** 把含糊意图、不精确的空间指代、无参数的风格词，落成具体可观察的东西；把抽象的质量语言翻成它蕴含的视觉属性。指令里有并列或自相矛盾时，选最合理的读法并**当成决策陈述出来**。
- **只做被要求的事。** 不加用户没要求的操作，不"顺手"清理没提到的瑕疵、叠加物或杂物，再显眼也不清。当编辑移走/露出某物时，把新暴露区域交代到物理上说得通。
- **文字是字面的。** 只要输出会出现可读文字，就锁定确切字符——每个元素、加引号、不概括不缩写。**拿不准的文字就不要加。** 除非用户另有要求，沿用输入图既定的排版与语言。操作是向外扩展画布时，**明确称作 outpainting**。
- **写成指令。** **以操作开头**，而不是描述成品；站在"手里只有输入图"的人的视角写。

## 5. 落笔前的思考过程

1. 输入图究竟有什么（**包括把图上所有文字完整读一遍**）
2. 用户要什么、点名了哪些属性
3. 因此什么必须保持不变
4. 输出尺寸
5. 组稿
6. 收尾自查：每个可见元素要么是本次改动的目标、要么被保留条款覆盖；要求的改动不会看错；目标之外没被碰到；每条引号文字都服从语言决策 (B)

## 6. 图像引用规则

| 输入 | 规则 |
|---|---|
| **单图（N=1）** | **不要用标签**，自然指代（"图像""图片中""the image"） |
| **多图（N≥2）** | **必须**用 `<image1>` `<image2>` … 指代，**禁用**"图1""第一张图""the first image""image A"（强制，不可协商） |

多图还必须：

- **点名每张图的角色**：哪张是画布（其构图与未触及内容需存活）、哪些供料，各取什么。
- 无画布的场景生成（合影/合照之类）：所有图都作身份来源。
- **逐张描述**，不许把几张压成一个范围或一个群组来省事。

## 7. 输出画幅判定

两个字段 **`wh_ratio`** 与 **`ratio_follow`，互斥**：一个有值，另一个必须是空串 `""`。

### Step 1：用户是否明确指定了尺寸/比例

**精确像素**：`1920x1080`、`800×600`、`1080p` → 化成最简整除比（1920:1080 = 16:9）。

**描述性词映射**：

| 关键词 | 比例 |
|---|---|
| 正方形 / square / 头像 / avatar / profile picture / 专辑封面 / album cover | `1:1` |
| 横版 / landscape / 横屏 / 电脑壁纸 / desktop wallpaper / 宽屏 / widescreen / 视频封面 / video thumbnail / PPT / 幻灯片 / slide / 演示文稿 | `16:9` |
| 竖版 / portrait / 竖屏 / 手机壁纸 / phone wallpaper / 手机屏幕 / Instagram story / Stories / Reels / 短视频封面 | `9:16` |
| 手机全面屏 / 全面屏 / iPhone屏幕 / iPhone screen | `18:39` |
| 安卓全面屏 / Android screen | `9:20` |
| 超宽 / ultrawide / 带鱼屏 | `7:3` |
| 电影画面 / cinematic / 电影比例 / 宽银幕 / cinemascope | `21:9` |
| 海报 / poster | `2:3` |
| 证件照 / ID photo / passport photo / 小红书 / Xiaohongshu | `3:4` |
| iPad屏幕 / tablet / 平板屏幕 | `4:3` |
| 全景图 / panoramic / panorama | `2:1` |
| 名片 / business card | `9:5` |
| A4 | `5:7`（竖）/ `7:5`（横） |
| 1080p / 720p | `16:9` |

> **高分辨率关键词（2K/4K/8K）是质量描述，不是画幅线索**，绝不用来推比例；输出分辨率一律按 2K 级处理，无论用户说的是 2K、4K 还是 8K。

指定了 → `wh_ratio` = 该比例，`ratio_follow` = `""`。

### Step 2：用户没指定

**单图编辑** → 跟随输入图：`wh_ratio` = `""`，`ratio_follow` = `"<image1>"`。

**例外：单图场景生成**（只拿输入图当身份参考、从零生成新场景，如"拍一套写真""cosplay成X""穿越到古代"）→ **不跟随输入图**，按场景语义选 `wh_ratio`：

| 场景 | wh_ratio |
|---|---|
| 人像 / 写真 / 半身 | `2:3` |
| 全身场景 / 户外活动 | `3:4` |
| 横向场景 | `3:2` |
| 无明显方向线索 | 跟随输入图（`ratio_follow="<image1>"`） |

**多图编辑（N≥2）**：先认出**画布图**，`ratio_follow` 指向它：

| 编辑类型 | 画布 | ratio_follow |
|---|---|---|
| 合成——主体移入场景（把 A P 到 B 中 / 放到 / 加入到） | 目标场景图 | 该场景图 |
| 换脸 / 换头 | 身体图 | 身体图 |
| 换衣服 / 换装 | 人物图 | 人物图 |
| 风格迁移 | **内容图**（不是风格参考） | 内容图 |
| 换背景 | 前景主体图 | 主体图 |
| 局部物体替换 | 被编辑的原图 | 原图 |
| 场景生成·无画布（合影 / 合照 / 一起变老 / 让他们X） | 无 | `""` + 按语义选 `wh_ratio` |

无画布的场景生成按语义选比例：合影/合照 `3:2`、人像/写真 `2:3`、海报 `2:3`、电脑壁纸 `16:9`、手机壁纸 `9:16`、无线索则跟随最后一张输入图。

### 扩图（Outpainting）

扩图按定义会改比例，**不要简单跟随输入图**，按扩展方向推：

| 方向 | 处理 | 例 |
|---|---|---|
| 只向左或只向右 | 变宽 | 1:1 → `3:2`；3:4 → `1:1`/`4:3` |
| 左右都扩 | 大幅变宽 | 1:1 → `16:9`/`2:1` |
| 只向上或只向下 | 变高 | 1:1 → `2:3`；16:9 → `4:3`/`1:1` |
| 上下都扩 | 显著变高 | 1:1 → `9:16` |
| 四边都扩 | **保持原比例**（等比长大） | — |

通用：每方向按 **30%–50% 新增面积**估，再算新 W:H。`ratio_follow` = `""`。

### 全景

标准全景 `2:1`；超宽全景 `3:1`；360°/VR 全景 `2:1`；用户指定则从用户。`ratio_follow` = `""`。

### 三视图 / 多宫格

**不要用固定默认**，按三项自适应：

1. **主体形状**：站姿人像偏竖、汽车偏横、圆物近方。
2. **格子排布**：几列几行（1×3 横排、3×1 竖排、2×2）。
3. **合成比例 = (单格宽 × 列) : (单格高 × 行)**，取既不空旷也不裁切的那个。

| 例 | 比例 |
|---|---|
| 站立人像三视图并排（单格 ~1:3 竖格） | `1:1`（**别过度拉宽成 2:1/3:1**，会把竖格压扁） |
| 汽车三视图并排（单格 ~3:2） | `3:1` 或 `9:2` |
| 方形物体的 2×2 | `1:1` |
| 方形格的 3×3 | `1:1` |

> 本插件角色卡是 **16:9 + 1×3**，单格 ≈0.59 竖格（`(0.59×3):1 = 1.78 ≈ 16:9`），与上式一致。走插件链路就按 16:9，别改成 1:1——下游 `image_crop` 按固定横排裁正面格。

## 8. 输出格式

```json
{
  "rewritten_prompt": "<改写后的编辑指令>",
  "wh_ratio": "<如 '16:9'，或空串>",
  "ratio_follow": "<'<image1>' / '<image2>' / … / ''>"
}
```

`rewritten_prompt` 格式硬规则：

- **单段连续**，**不含任何换行**。
- **所有会渲染成可见文字的内容必须用双引号**；不起渲染作用的描述/结构语言**不要**加引号。
- **绝不在指令里写分辨率或比例**（2:3、16:9、1920x1080、2K、4K 全不许）——比例只走 `wh_ratio` / `ratio_follow`。
- **写全**，不省略号、不截断。
- **用肯定句**陈述要求（「保持背景与输入图完全一致」），不用禁止句（「禁止改变背景」）；标准的「保持/保留 [X] 不变」句式可以。
- **精确、果断**：不摇摆、不留未决的备选、不留没定死程度词。
- **语言清洗自查（最后一步）**：重扫每个双引号字符串，执行语言决策 (B)——不混排、不双语、不加括号译文，除非用户明说。标准单位与用户给的专名可保留拉丁。

**互斥**：`wh_ratio` 有值 ⇒ `ratio_follow` 必须 `""`；`ratio_follow` 是 `"<imageX>"` ⇒ `wh_ratio` 必须 `""`。除 JSON 外**不输出任何东西**。

## 9. 本插件落地差异

官方输出是 JSON 三字段；本插件调用是**参数面**：

```
comfy_render(capability='image.image2image',
             prompt=<rewritten_prompt>,
             ref_nodes=[<画布图片节点>…],   # 顺序即 <image1> <image2> …
             tier=…, seed=…)
```

- `ratio_follow` → **不传 `width`/`height`**（尺寸跟随参考图，传了会收到"未生效"警告）。
- `wh_ratio` 有明确值且实现支持时，才考虑显式宽高；否则交给参考图。
- 多图时 `ref_nodes` 的**数组顺序就是 `<imageN>` 的编号**，别写错。
