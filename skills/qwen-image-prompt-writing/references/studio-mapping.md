# 与本插件的对接（dsh-short-video-studio 适配）

> 原则：本 skill 只产出 **prompt 文本**（+ 画幅判定 + 尺寸建议）。**不写死模型名或工作流 id**——实现由配置面决定，换实现不该改这个 skill。

## 1. 工具映射

| 目的 | 调用 | 关键参数 |
|---|---|---|
| 文生图 | `comfy_generate_image(prompt, tier, width, height, seed, count, title, group)` | `prompt` 用增强后的描述；`width`/`height` 缺省由画布 `aspectRatio` × 档位长边推导（snap 32） |
| 图生图 / 改图 | `comfy_render(capability='image.image2image', tier, prompt, ref_nodes, …)` | **尺寸跟随参考图，不传 `width`/`height`**（传了会收到"未生效"警告） |
| 角色卡双版本 | `comfy_generate_image(card_variant='three', character=…)` → `image_crop(panel=0, panels=3, card_variant='single', paired_node_id=…)` | 单视图**由裁切得到**，不重新生成 |
| 抽卡迭代 | `tier='fast'` 试方向 → 定稿 `tier='quality'` | 成本差一个数量级 |
| 多镜复用 | `canvas_write_prompt_bank(title, prompts={fast,balanced,quality})` | 本插件策略：**三段同文**，换档只变采样 |
| 查档位/尺寸 | `comfy_list_workflows()` | 各档实际长边与耗时的唯一权威 |

## 2. 档位口径（图片）

| 档位 | 长边 | 步数 | 适合 |
|---|---|---|---|
| `fast` | 1024 | 20 | 试构图、试描述方向、废稿 |
| `balanced` | 1344 | 30 | 日常、卡片试版 |
| `quality` | 2048 | 40 | 定稿、海报、成片素材 |

- 实际尺寸 = **画布 `aspectRatio` × 该档长边**，snap 到 32 的倍数；显式 `width`/`height` 可覆盖（只传一边时另一边按比例补）。
- 三档都是 `cfg=1` ⇒ **没有负向提示词**（这也意味着一件事：档位只改像素与步数，不改"能听指令多少"）。
- **描述密度不随档位缩水**：别为了 fast 把 prompt 写短——短 ≠ 快，只是更差。

## 3. 角色卡尺寸表（先三视图、再裁正面格）

| 档位 | 三视图（16:9） | 单视图 = 正面格 |
|---|---|---|
| `fast` | 1024 × 576 | 341 × 576 |
| `balanced` | 1344 × 768 | 448 × 768 |
| `quality` | 2048 × 1152 | 682 × 1152 |

- 单格 ≈ **0.59 竖格**，`(0.59 × 3) : 1 ≈ 16:9`——与官方"合成比例 = (单格宽×列):(单格高×行)"一致。**别把三视图改成 1:1**，下游裁切按固定横排。
- 单视图**不要再单独文生图**（旧 2:3 尺寸已废）：裁切是纯像素操作，两版同源、身份按构造一致。
- 视频引用哪一版由 STEP 0 的用户选择驱动（`characterCardVariant=single|three`；`fast` 只能 single）——但那**不影响本 skill 写 prompt**，卡本身照 §五 写。

## 4. 画布落点（耐用产物不留在对话里）

| 产物 | 落成什么 |
|---|---|
| 增强后的 prompt | 文本节点（`canvas_write_node(kind='text', title='<对象> 提示词')`），或每镜一份 `canvas_write_prompt_bank` |
| 画幅判定与尺寸理由 | 写进同一节点的 `note` 区（**别写进 prompt 段**，会被当 prompt 发出去） |
| 出图 | 工具已自动写画布；标题带对象名与档位 |
| 挑图对比 | 多张放同组，标题带序号，便于用户选 |

## 5. 与门禁的关系

- 本 skill **不引入任何门禁**，也不改 `lib/index.js`。
- 逐镜自检门 / 镜头表一致性门 / 制片门都是**视频侧**的，与本 skill 无交集；这里只保证图片 prompt 不把风险带进后续视频链路：
  - **零文字**：参考图上的文字会被视频模型当内容投影，卡类 prompt 一律不带任何字面。
  - **单主体**：卡片 prompt 不写"多个角度各来一个"以外的额外人物，不拼图。
  - **纯底**：不写环境、不写道具（道具卡除外）。

## 6. 写作与失败的处置

| 现象 | 先怀疑什么 | 怎么改 |
|---|---|---|
| 太素 / 空 | 描述密度不足（短 prompt） | 补材质、补位置、补光照句；**不是加质量词** |
| 缺元素 | 位置短语没覆盖 / 元素没点名 | 补位置短语到 8–14 个，点名每件物 |
| 文字错 / 乱码 | 没逐字给 / 没给字重与位置 | §⑥ 逐条写：位置 + 字重 + 颜色 + 引号原文（原语种） |
| 构图偏 | 缺少明确机位与景别 | 开篇补媒介与方向；正文补 `shot from …`、`at three-quarter view` |
| 出现奇怪的文字块 | prompt 里混进了版式标注或指令句 | 删掉"正面/侧面"类标注与非画面语言 |
| 画面被参考图"污染" | 参考图本身带文字/多主体 | 回到卡片规则（零文字、单主体、纯底），必要时重出参考图 |
| 改图改多了 | 没写保留条款 / 保留条款写太具体 | 用毯式保留条款，按类型/位置点名，别细写外观 |
| 改图几乎没动 | 强度不足 | 把改动推到"强到不会看错"，并让它可观察（方向、程度、色相） |

## 7. 交付给用户时说清三件事

1. **用了哪个能力与档位**（不要报工作流 id）。
2. **画幅与最终尺寸**，以及它是怎么来的（画布比例 × 长边 / 显式覆盖 / 实现锁定）。
3. 工具返回的 `warnings` **如实转述**，不要复述一个没生效的档位或尺寸。
