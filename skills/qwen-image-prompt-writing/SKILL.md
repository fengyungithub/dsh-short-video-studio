# Qwen-Image 提示词增强

一句话需求 → 一段**像在描述已完成的画面**的长英文段落（T2I），或一条**只说改什么、其余全保住**的精确指令（改图）。别名：Qwen-Image 2.1 官方提示词改写器（PE-T2I / PE-I2I）的本地替代。

> 规范来源：Qwen 官方 `Qwen-Image-2.1/prompt_rewrite/prompts/system_prompt_{t2i,edit}.txt`（Qwen Research License），本 skill 为本地化适配版，未修改其规则。

## 先读：五条硬事实（它们决定怎么写，不是建议）

1. **没有负向提示词。** 本插件的图片链路 `cfg=1`（三档都是），负向字段不参与采样。**所有约束必须写成正向陈述**——「不要模糊」⇒「edges are crisp and sharply defined」。
2. **比例与尺寸不进 prompt。** 走 `width`/`height` 或画布 `aspectRatio`（snap 32）。描述里出现 `16:9`、`2048×1152`、`4K` 都是噪声，官方规范明令禁止。
3. **只描述，不下指令。** 现在时、第三人称、陈述句。禁「create / make sure / 请生成」，禁质量词（masterpiece、8K、highly detailed、award-winning——写了不会更好，只会挤掉真实描述）。
4. **图内文字用双引号逐字给，并保持原语种。** 中文就写中文，不要译成英文；给位置、字重、颜色、相对字号。不打算被读的文字，明说「blurred / too small to read」，别让模型去编。
5. **透明背景有固定句柄**：`This is an RGBA image with transparency. <主体描述>. The image has alpha channel and the background is transparent.` 不套这个壳就出不来 alpha。

## 第一步：判定任务类型

| 类型 | 判据 | 走哪节 |
|---|---|---|
| **T2I 长描述** | 从零出一张图（含角色卡/场景卡/道具卡/封面海报） | §二 八步骨架 |
| **I2I 改图指令** | 已有图，只改某几处（换装/换背景/改文字/风格迁移/扩图） | §四 属性解耦 |
| **卡类图纸** | 角色卡、场景卡、道具卡（纯底、单主体、零文字） | §五 四类对象 |

拿不准就问一句：「这是从零出图，还是改现有的一张图？」

## 二、八步骨架（T2I）

八步**按顺序**走，每步只定一个决策，后面的步骤不回头改前面的。

### ① 拆题：哪些是用户钉死的，哪些是你来定的

- **必留（逐字保留）**：要出现的文字、点名的物体、数量、说过的颜色、说过的位置、指定的画幅。
- **尤其要抓「用户没写、但语义上一定有的」**：短需求靠语义先验自动补上标志性主体（"极乐世界"→金佛 + 宝池，"佛国圣地"→佛像 + 石塔），而长描述会把这份先验**稀释成字面场景**。所以凡语义上应有的主体与标志物，**必须显式写进固定项**——不写就不会出现，八步写出来的画面可能比一句短 prompt 更"空"（实测：`A/B 测试` 画布结论）。
- **你来定**：其余一切。**三词的需求和三万词的需求，产出一样长**——短需求意味着你在发明画面的大部分，不是写得更少。
- **第三类：关于"活儿"的指令**（"用双引号""不要硬边色块""文字要清晰"）——照做，但**永远不要写回描述里**。

### ② 定画幅

用户给了就用；没给：横 `3:2`、竖 `2:3`（两个默认，覆盖大多数），方形徽标/图标/封面 `1:1`，宽银幕/演示 `16:9`，手机屏/竖 banner `9:16`。
**比例只进参数，绝不写进描述。**

### ③ 开篇一句（约 20 词）

```
The image is a <竖向/宽幅/方形> <风格> <photograph|poster|illustration|scene|portrait|infographic|card|sheet|logo>
of <主体>, <背景与色调>.
```

- **媒介名词永不可省**（photograph / poster / illustration…）。
- **风格词只在这里点一次**（realistic、photorealistic、minimalist、flat-vector、cinematic、watercolour、isometric、hand-drawn、3D-rendered、retro），可在收尾句复述一次。

### ④ 先盘点，再落笔

两张家底清单：

- **每个元素 + 它在画面里的位置**（upper-left、across the top、on the far right、in the lower-third、in the centre、in front of、behind、tucked into the corner）。要 **8–14 个位置短语（通常 ~10 个）**，且必须同时覆盖四角、边缘和中心——**不许全挤在中间**。
- **每一条会出现在图里的可读文字**，按阅读顺序排好。

### ⑤ 走一遍画面

按画面怎么被填满选路线：

- **分区块**（海报 / 页面 / UI / 多元素宽景）：**背景与承托面 → 顶部横带 → 左侧 → 中央 → 右侧 → 底部横带**。每区 1–2 句。
- **单一主体占满**（人像 / 特写 / 单体）：**背景及其虚化 → 姿态与画面位置 → 头脸 → 身体与每件衣物/表面 → 手持或相触之物 → 边缘零星**。主体内部继续用位置短语（behind the left shoulder、along the lower edge）。

**约三分之一的句子直接以位置短语开头**（"On the right side of the frame, …"），读者才始终知道自己在看哪。
**默认一整段**；只有画面真是堆叠区块（分栏 / 卡片 / 幻灯片）才分段，一段一区，且每段开头就交代该区在哪。

### ⑥ 逐条定文字

画面里没有要读的字就**跳过这步**（约三分之一的图本就没有文字，硬编招牌是错的）。有则按阅读顺序，每条写清：**位置 + 长什么样 + 说了什么**：

> a bold black headline across the top reads "夏日特惠"

- 双引号、原语种、给字重/颜色/大小写/相对字号。
- 换行说成「second line」，不要往字符串里塞真换行。
- 图表/表格：坐标轴、刻度、图例、系列、单元格值 **都是文字，要写出来**。
- 不该被读的（远处招牌、玻璃后的标签、密集正文）：写「blurred / indistinct / too small to read」，别编字母。

### ⑦ 光单独一句

每张图都有光，描述永远交代它：**光源、方向、质感、留下的高光与阴影**。
> The lighting is soft diffused daylight from a window on the left, …

要么独立成句（`The lighting is …`），要么并进它塑造的那个表面的句子里。**必须显式，不许暗示。**

### ⑧ 收尾一句（唯一）

```
The overall composition <is / uses / feels> …
```

平衡与对称、配色、风格、情绪，**收在这一句里**。写完就停，**不要再补第二句总结**。

## 三、写作纪律（贯穿全篇）

| 项 | 要求 |
|---|---|
| **篇幅** | 约 20 句 / 400–500 词（≈25 词/句）。密集版面更长，安静主体更短——**薄需求不换薄描述** |
| **语气** | 现在时、第三人称、陈述；没有 you、create、make sure、the AI should |
| **拿不准就含糊** | appears to be / likely / suggesting，或给二选一「a notebook or a tablet」；只有用户钉死的才斩钉截铁 |
| **颜色必带修饰** | deep navy、muted olive、pale cream、warm terracotta、soft dusty rose、charcoal——不写裸色名；hex 只在用户给时用 |
| **给材质不只给名词** | brushed metal、matte plastic、glossy ceramic、coarse linen、weathered wood、frosted glass、paper fibre、visible brush strokes |
| **枚举不概括** | 「several items」「various decorations」不算描述；逐个大写写出，小数量用英文单词；部分被挡就说被挡、并描述可见部分 |
| **人给可观察表面** | 体型、姿态、视线、表情、头发、肤色、每件衣物的颜色与材质；年龄写生命阶段（a child / a young adult / in her thirties）**不写岁数**；脸转开或被裁就说转开 |
| **物按类别不按品牌** | a silver laptop、a mirrorless camera——除非用户点了品牌；摄影/设计词汇欢迎（shallow depth of field、bokeh、negative space、drop shadow） |
| **物理自洽** | 影子背离光源、反射对准物体、相邻物体比例一致、表面对其上之物有反应 |
| **歧义词必须锚定物理性质** | `a column of light` 会被画成喷泉/水柱；写成 `a volumetric shaft of light, its edges dissolving into backlit haze` 才稳。光、烟、雾、能量这类无实体物象，一律补「体积/边缘/衰减」的物理描述 |

**语言**：描述用**英文**（用户中文需求也一样——这是官方 PE-T2I 的裁定；基础模型虽原生吃中文，但走增强路径统一英文更稳）。**唯一的例外是图内文字，保持原语种。**

## 四、改图（I2I）：属性解耦

核心一句：**只动用户点名的那一个属性、把它推到明确无误的强度，其余全部保持输入保真度。**

两个对称的失败模式，都要防：
- **越界改动（Leakage）**：锐化顺手改了色、放大顺手改了构图、换装把配饰弄丢了。
- **改了像没改（Under-editing）**：效果太弱，观者以为没动。

四条最实用：

1. **保留条款要抽象，不要重画。** 用类型/位置/角色指代要保住的东西（"the two background bystanders on the left"），**不要细写它的外观**——你越具体地描写"要保住的东西"，模型越容易把它重绘漂移。一条毯式保留条款优于逐条走一遍画面。
2. **身份是最硬的常量。** 人脸同一性、让人认得出的配饰、产品的精确设计与数量、输入图的渲染媒介（照片/动画/插画/草图/3D），默认全部继承。**身份来自参考图时，指那张图，不要用文字描述五官**——文字描述会让模型重造、相似度反而下降。
3. **写成指令，以动作开头**，站在"手里只有输入图"的人的角度写；**肯定句优先**（「保持背景与输入图完全一致」优于「不要改背景」）。
4. **多图输入必须用 `<image1>` `<image2>` 标注**，禁用「第一张图 / image A」；每张图点名其角色（谁是画布、谁供货）；**单图输入则不许用标签**。

改图细则、画幅决策表（场景生成 / 扩图 / 全景 / 三视图 / 多图画布）见 `references/edit-spec.md`。

## 五、本插件四类常用对象

| 对象 | 关键约束 | 写法要点 |
|---|---|---|
| **角色卡·三视图** | **纯底、单主体、零文字** | 先开篇定媒介与风格 → 三格并排、每格一个机位（正/侧/背，全身）→ 逐格写体格、发型、每件衣物与材质 → 光一句 → 收尾。**图上绝不留角色名或"正面/侧面"标注**（会被视频模型烙进画面）。总数 = `(单格宽×3) : 单格高`，本插件固定 16:9 + 1×3 ⇒ 单格 ≈0.59 竖格 |
| **角色卡·单视图** | 同上 | **不要单独文生图**：用 `image_crop(panel=0, panels=3)` 从三视图裁正面格（纯像素、身份按构造一致） |
| **场景卡** | 单视图空镜、无主角、零文字 | 按「分区块」走：背景与天光 → 中景主体结构 → 前景观感 → 光 → 收尾；写明时段与色温 |
| **封面 / 海报** | **文字是主角** | 先盘点全部文字并逐条定位置/字重/颜色（§⑥），再走版式；**中文字面量最大的收益点就在这里** |
| **i2i 改绘** | 保身份、保构图 | 走 §四；点名"改什么"，其余一条毯式保留条款 |

铅笔分镜、风格测试图等参考图资产：同样跑八步，但省掉 §⑥（零文字），并把风格词与线条/材质描述写足。

## 六、自检（交付前必跑）

```bash
node scripts/check_prompt.mjs <prompt-file|-> --mode t2i|edit|card [--json] [--strict]
```

它替你抓**机械性错误**（比例泄漏、质量词、指令动词、篇幅、位置覆盖、光照句、收尾句、引号配对、卡类误带文字）。**它抓不了的**是你得自己看一眼：

- [ ] 开篇有没有媒介名词？
- [ ] 位置短语是否覆盖四角/边缘/中心（不是全挤中间）？
- [ ] 每条要读的文字都逐字、原语种、带位置与字重？
- [ ] 光照是否独立成句？
- [ ] 收尾是否**只有一句**且覆盖平衡/配色/风格/情绪？
- [ ] 有没有一句是"指令"或"质量夸奖"混进来了？
- [ ] 所有否定式约束是否都翻成了正向陈述？

**error 必须修；warning 逐条判**——判"故意为之"就放过，判"漏了"就补。

## 七、落到工具

| 目的 | 调用 |
|---|---|
| 出图 | `comfy_generate_image(prompt=<增强后的描述>, tier=fast/balanced/quality, width/height 或交给画布比例, ...)` |
| 改图 | `comfy_render(capability='image.image2image', prompt=<改图指令>, ref_nodes=[参考节点], ...)`（**尺寸跟随参考图，不要传 width/height**） |
| 抽卡迭代 | `tier=fast` 试构图/试描述方向，定稿再上 `quality`（成本差一个数量级） |
| 多镜复用同一段 prompt | `canvas_write_prompt_bank` 写三段（本插件策略：三档同文，换档只变采样） |

**三档只是像素与步数**（长边 1024 / 1344 / 2048，20 / 30 / 40 步）：**描述密度不随档位缩水**，别为了 fast 把 prompt 写短。

产物与 prompt 都要落画布（文本节点或提示词库），别只留在对话里。
