# 3D 动画短片生成器（dsh-short-video-studio 适配版）

当用户想把一句话创意做成完整的故事优先动画短片时使用本 Skill。流程从创意开发到最终交付，所有主要产物都必须按生产顺序落到画布，并在高成本或关键创意节点用选项卡让用户确认。

核心规则：**先故事、再资产；接到创意后立刻用选项卡确认生产规格；产物按顺序上画布；所有需要用户确认的地方必须用选项卡；角色/场景卡锁定后固定顺序为：六列标准镜头表 → 镜头表自检门 → 单文本分镜文档（可视化模式再加铅笔图）→ 逐镜视频生成 → 交付复查；成片必须清除所有分镜痕迹。**

参考图硬规则（单视图 / 图内零文字 / 不拼图 / first_frame 只用于同场景续接 / 入库由用户人工点按钮）由插件工具契约统一定义，本文不复述，全流程严格遵守；first-frame（i2v）的**启用资格与传参硬规则**见 STEP 5.5 第 9 项与 STEP 7「参考绑定策略」。

## 全局视觉风格锁

除非用户明确指定其他视觉风格，所有角色卡、场景卡、铅笔分镜、单镜头视频片段与成片都必须使用以下视觉风格：

- 渲染风格：皮克斯感 3D 卡通渲染，C4D + Octane 渲染器质感，高级动画电影质量。
- 角色造型：夸张几何概括与极佳材质质感的平衡。不追求 100% 真人解剖结构，使用高概括度几何形体、强剪影和高辨识度设计。
- 比例语言：亲和的风格化比例；适合可爱或幼态角色时采用 2.5–3 头身 Q 版比例，大头小身、体块清晰、轮廓易读。
- 发丝 / 毛发：整体造型有清晰块面结构，边缘保留精细发丝或绒毛细节；光照下既硬朗有形，又有细腻触感。
- 皮肤 / 材质：温润次表面散射（SSS）质感，耳朵、脸颊、鼻尖、指尖可有微红透光；避免生硬塑料感。
- 表演风格：夸张灵动的迪士尼 / 皮克斯式角色动画表演，运用挤压与伸展，强化眉毛、眼角、瞳孔、嘴唇、脸颊形变。
- 动态风格：高能量态势、清晰动作线、前倾势能、强预备动作、快速但可读的节奏、弹性身体机制和丰富微表情。
- 情绪尺度：在可爱与爆发力之间取得平衡；强情绪可以有戏剧性面部变形，但必须保留角色魅力。

负向风格约束：不要写实真人摄影、不要扁平二次元、不要塑料玩具皮肤、不要僵硬人体姿势、不要真实解剖僵硬感、不要无生命表情。

风格锁写进每次生成的 prompt 尾部（图片与视频通用后缀），确保跨镜风格一致。

## 实测 prompt 铁律：形态正向构造（STEP 3 / 5 / 7 引用）

以下铁律由插件 AV 视频模型实测沉淀（13+ 版否定堆叠失败后一次突破，之后全程稳定）。角色卡形态描述（STEP 3）、镜头表对白规划（STEP 5）、逐镜 prompt 组装与失败重试（STEP 7）都按此执行。**字幕写法的规范不在这里**，见下方「字幕与画面内文案：本节不定义写法」。

### 铁律一：角色形态用「正向生物构造描述」，不用否定堆叠

原理：模型对否定词执行力很弱。`NO front legs / NO arms / NO hands` 这类命令式否定会被理解成"有东西要避免"的暗示，反而按默认角色模板（四肢齐全的"可爱小生物"）补全缺失附肢；否定词堆得越多，越像在强调"可能长四肢"。正向构造描述给出"这个物种本来就只有这些零件"的完整解剖图景，模型跟随"长什么样"而非"不要长什么样"。

**成功写法六要素**（按顺序组织成一段）：

1. **整体形状词** — 先定义它是"一个什么形状的单一整体"：`its head and body are ONE seamless pear-shaped unit`。
2. **比喻锚点** — 调用模型已有的视觉原型：`like a smooth dark pebble with a face`（亦可 `like a small dark pearl with a tail`）。
3. **部位间关系** — 头身一体而非拼接：`no seam, no neck, no shoulder between head and body; the whole front surface is one continuous smooth curved skin`。
4. **唯一附肢清单** — 用"唯一"正向锁定数量与生长位置：`its only limbs are TWO short thick bent hind legs with small round toes growing from the lower rear of its body`。
5. **解剖总括句** — 结尾锁定总数：`Its anatomy is exactly: one pear-shaped head-body, two hind legs, one tail — that is all`。
6. **姿态即形态** — 让角色持续做该物种的自然行为（如连续游动巡游）；静止悬浮时模型容易把它"补全"成标准生物。

配套纪律：正文一次也不出现"它可能长前肢"类暗示；必须出现的否定词收敛到 prompt 末尾一行；成长阶段（形态 A/B/C）各阶段独立写清解剖清单，阶段切换 = 换状态卡 + 换描述，绝不在镜头内变形。

### 字幕与画面内文案：本节不定义写法（只有指针）

**写法、失败写法、容量 / 拆镜阈值、档位与实现口径，一律以 `h3-prompt-writing` 的「字幕与画面内文案（唯一权威版）」为准**——本节及本 skill 其它位置都**不复述、不简化、不另立策略**（简化版漏限定词 → 字幕整段不烧，是已实测缺陷）。

片型侧在本流程里只负责三件事（都在下面的步骤/门里）：

1. **数据**：镜头表 `字幕` 字段填本镜要渲进画面的字幕文本（即台词本身），`silent` 镜写 `none`；字幕文本与对白原文逐字一致（STEP 5.5 自检）。
2. **抽查**：门 3 自检对**有对白（含字幕）的镜**抽说话窗帧，核对字幕文字。
3. **处置**：抽查不过 → 交用户选择 **重新生成本镜 / 升档重渲**（见门 3）。

**自检速查**（角色 prompt 送出前过一遍）：

- 形态：整体形状词给了吗？比喻锚点有吗？唯一附肢清单列了吗？总括句锁定总数了吗？还有否定堆叠 / "可能长前肢"暗示要删吗？

## STEP 0：接收需求、查库与生产规格

捕捉：一句话创意或粗略故事；目标产物（只要蓝图 / 只要资产 / 到镜头表 / 到分镜 / 到逐镜片段 / 到交付）；用户已说明的时长与画幅；视觉基调（默认温暖风格化 3D 动画）；台词需求。**只有用户明确指定台词语言时才锁定语言，不要默认英文台词。**

会话开始先 `asset_list()` 查跨会话资产库。库非空时先出【复用范围】选项卡：列出库内已有资产（如 `character:luna`、`scene:bridge`），问本次复用 / 全新 / 部分复用（可混选）。复用的资产后续直接以资产 id 引用，不再重新生成对应卡片。

随后（无论库是否为空）在项目简报或任何下一步之前，必须依次出以下选项卡：

**画面比例**：16:9 横屏（电影短片推荐）/ 9:16 竖屏短视频 / 1:1 方形 / 4:5 社媒竖图 / 自定义。
**总时长**：30–60 秒（推荐）/ 15–30 秒 / 60–90 秒 / 90–180 秒 / 自定义。
**音频模式**：`dialogue-led` 对白主导（一镜一人 + 反应切镜，说话人绑定 + 非说话人闭嘴）/ `silent` 静音（纯画面 + SFX，口型风险为 0）。旁白主导不在本 Skill 范围。
**生成档位**：`fast`（调试 / 调构图，长边 832）/ `balanced`（日常，画质与耗时平衡，长边 1344）/ `quality`（成片，长边 1344）。允许先 fast 走通全片再升档重出（`fast`→`balanced`、`fast`→`quality`、`balanced`→`quality` 都允许）。

四项确认后用 `canvas_set_state` 持久化（aspectRatio / duration / audioMode / mode），**同一次调用一并传 `groupOrder`**（见下方分组清单），并写入项目简报。这些设置贯穿镜头时长、分辨率推导、分镜、逐镜生成与交付。

> **档位必须逐镜显式传**：之后每次 `comfy_generate_video` 都显式写 `tier=fast|balanced|quality`，**不要依赖缺省**——缺省是 `quality`（成本最高档）。同一镜头要换档时改 `tier` 重渲，不要靠「隐式默认」蒙。

画布产物按以下顺序创建，每产出一个立刻上画布，不要把长篇生产内容只丢在对话里：

1. 项目简报（text，group `story planning`）
2. 故事大纲（text，group `story planning`）
3. 角色卡（image，group `character cards`）
4. 场景卡（image，group `scene cards`）
5. 六列标准镜头表（table，group `shot table`）
6. 单文本分镜文档（text，group `text storyboards`；抽取节点与铅笔图同组）
7. 单镜头视频片段（video，group `shot clips`）
8. 拼接成片（video）+ 交付清单与终检（text），均 group `final delivery`

**分组名由本 Skill 定义**（插件本身不预设任何片型词汇）。在 Step 0 用 `canvas_set_state(groupOrder=["story planning","character cards","scene cards","shot table","text storyboards","shot clips","final delivery"])` 一次性声明展示顺序，画布即按此顺序渲染分组。之后所有 `group` 参数必须用这七个精确名字；未声明的分组会排在末尾。

## STEP 1：项目简报

写一份精炼简报到画布文本节点（group `story planning`）。包含：工作标题、一句话 What-if、情绪前提、目标观众感受、主要交付物计划、已确认的画面比例 / 总时长 / 音频模式 / 生成档位、台词模式与语言（用户未指定就写 `language not specified`，保持最小化对白或后续再确认）、初始风险、台词意图。

选项卡：沿用此方向继续（推荐）/ 重新生成前提选项 / 修订情绪前提 / 调整台词方向。

## STEP 2：故事大纲与守门

写故事大纲到画布文本节点（group `story planning`）。包含：主角 Want / Need / 缺陷、核心世界规则、8 拍因果故事骨架、情绪锚点与回收、音频脊柱（每拍的对白/静默意图）、红线检查。

守门检查：主角是主动的；危机由主角缺陷放大；巧合不能解决问题；结局回收早前情绪锚点；反派压力不是扁平反派；台词揭示关系变化而非解释主题。

选项卡：批准故事并继续（推荐）/ 修订节拍 / 修订情绪曲线 / 修订台词节拍 / 返回前提。

## STEP 3：角色卡

先 `asset_list(type=character)` 查库；命中复用就 `asset_to_canvas(id=资产 id)` 把卡片物化到画布（复用的卡也必须在画布可见），未命中才 `comfy_generate_image` 新建。推荐顺序：主角卡 → 对比 / 施压角色卡 → 可选配角卡。

每张角色卡的硬性要求：

- **单视图正面全身，画面内不得出现任何文字**（工具契约硬规则）。不画三视图拼图，不画角色名 / 视图标注 / 道具标签。
- **背景纯净**（浅灰或纯白），只有角色本人，无第二个身体、无剪影、无镜像。
- 角色定位、签名道具、年龄段、身材、发型、服饰色、不可改特征、`speaks_on_screen` 等标注信息**只写在画布节点标题与描述里**，绝不画进图内。
- **同一角色的不同着装状态分别建单视图卡**（如「不穿宇航服 / 穿宇航服」），按镜头状态选用；两张卡在标题里用统一角色名 + 状态后缀。
- **记录 seed**：生成后把 seed 写进节点描述，需要微调重出时复用同一 seed 保身份。
- **非人形 / 非常规解剖角色**（如「圆头无颈 + 两条后腿 + 一尾」的蝌蚪类生物）：形态一律按「实测 prompt 铁律一」写**正向构造清单**（整体形状词 → 比喻锚点 → 部位关系 → 唯一附肢 → 解剖总括句），卡 prompt、节点描述与后续镜头 prompt 共用同一份正向解剖描述；**禁止否定堆叠**——`NO front legs / NO arms / NO nubs` 类写法实测会让模型按"四肢齐全小生物"模板补全缺失附肢，否定堆得越多越糟。成长阶段（形态 A/B/C）各建独立状态卡，每张卡独立写清该阶段解剖清单；阶段切换只靠换状态卡 + 换描述，绝不在镜头内变形。
- 风格锁后缀必须带上。

### 角色卡 AI 自检（自检点 1：生成后、交人工前，强制）

每张**新建**的角色卡生成后、出「锁定」选项卡之前，AI 必须先用当前模型自身视觉读生成图自检（当前模型不支持图片输入时回退 `describe_image`），任一不过不许交人工：

1. **参考图硬规则合规**：单视图正面全身；画面内零文字（无角色名 / 视图标注 / 水印 / 道具标签）；背景纯净，无第二身体 / 剪影 / 镜像；无三视图拼图。
2. **与角色设定标注一致**：对照节点标题与描述里的定位（年龄段 / 身材 / 发型 / 服饰色 / 签名道具 / 不可改特征 / `speaks_on_screen`）逐项核对画面；着装状态与目标状态卡一致；整体符合全局视觉风格锁。
3. **失败处置**：任一不过 → 复用同 seed 微调重出（见上方「记录 seed」）或修订节点描述后重出，重跑本自检；**未过自检的卡不得弹「锁定」选项卡**。资产库物化复用的卡为历史已锁定版本，无需重检。

自检通过后出选项卡：锁定角色设计并继续（推荐）/ 重新生成主角卡 / 调整具体视觉细节 / 增加另一张角色卡。

锁定后提示用户：想跨会话复用就在画布点该卡的「入库」按钮人工登记（AI 不自动入库）。同时警告：后续修改已锁定的角色设计会连带重做镜头表、分镜与已渲片段。

## STEP 4：场景卡

先 `asset_list(type=scene)` 查库，命中就 `asset_to_canvas`，未命中才生成。**场景卡只展示环境，不出现人物、人群、剪影、手、脸或角色客串，画面内同样零文字。** 角色动作属于镜头表、分镜与视频片段。

包含：主环境总览；关键光态（日景 / 夜景）；情绪子空间；**连续性地标**（同场景跨镜头必须保持屏幕位置的固定物体，如厨房中岛、沙发、门框、树、邮筒）；环境中的重要道具。地标名与位置写在节点描述里，供镜头表的 `参考锚点` 列直接引用。

### 场景卡 AI 自检（自检点 2：生成后、交人工前，强制）

每张**新建**的场景卡生成后、出「锁定」选项卡之前，AI 必须先用当前模型自身视觉读生成图自检（当前模型不支持图片输入时回退 `describe_image`），任一不过不许交人工：

1. **参考图硬规则合规**：画面内零文字；只展示环境，无人物 / 人群 / 剪影 / 手 / 脸 / 角色客串。
2. **与场景设定一致**：主环境布局、关键光态（日景 / 夜景）、情绪子空间与节点描述一致；镜头表 `固定地标` 列要引用的地标真实存在、屏幕位置可读、未被杂物遮挡。
3. **失败处置**：任一不过 → 复用同 seed 微调重出或修订节点描述后重出，重跑本自检；**未过自检的场景卡不得弹「锁定」选项卡**。资产库物化复用的卡无需重检。

自检通过后出选项卡：锁定场景设计并继续（推荐）/ 重新生成场景卡 / 增加另一个场景角度 / 调整光位或布局。同样提示人工入库。

## STEP 5：六列标准镜头表

角色卡与场景卡锁定后，用 `canvas_write_node(kind=table, group="shot table")` 输出标准化镜头表。本步为强制步骤，不可与分镜或视频生成互换。

表格必须严格按以下顺序包含六列：

| 镜头编号 & 时长 | 连续性衔接 | 参考锚点（空间+身份） | Hook 类型 | 镜头描述（每秒指令） | 音频与对白轨 |
|---|---|---|---|---|---|

列规则：

- **镜头编号 & 时长**：镜头号加计划时长，如 `S03 / 5s`。视频工作流按 24fps 帧数生成（124 帧 ≈ 5s），时长要能整除到帧。
- **连续性衔接**：本镜如何自然承接上一镜的结束画面、道具位置、眼神、姿态、声桥或情绪状态；以及本镜如何为下一镜开篇铺好钩子。这是跨镜连续性主链。
- **参考锚点（空间+身份）**：五个子字段全部必填。
  - `固定地标` — 来自场景卡的确切命名地标及其画面相对位置（如 `door-frame: 右侧 1/3`、`kitchen-island: 底部居中`）。
  - `人物位置（机位视角）` — 每个在屏角色的画面相对位置（左/中/右、上/中/下、前/中/后景）、朝向、初始姿态。
  - `退场人物状态` — 上一镜有但本镜没有的角色，记录离屏位置和原因（如 `Mia — 离屏左侧，最后出现于门框旁手持苹果筐`）。
  - `光位基线` — 从场景卡继承的主光/补光/轮廓光方向，加本镜调整项。
  - `绑定` — 精确的角色卡节点/资产 id + 场景卡节点/资产 id + 本镜参考策略（`ref` 参考绑定 / `first-frame` 同场景续接）。**`first-frame` 仅在同场景续接、且上一镜末帧画面已包含本镜全部在屏角色时可用；本镜若出现上一镜末帧中没有的角色（新登场 / 从画外进入）必须标 `ref`，禁止标 `first-frame`。**
- **Hook 类型**：受控词表取一：`setup` / `visual-joke` / `reversal` / `reveal` / `callback` / `suspense` / `tender` / `chase` / `expression-beat` / `climax`。
- **镜头描述（每秒指令）**：景别、镜头运动、荷兰角设计、表演风格、音效、负向提示，并强制包含 `Per-Second Directives` 子节：按秒拆解 `0–1s`、`1–2s`…，亚秒关键节拍用 `2.0–2.5s` 标记。每条每秒指令必须覆盖 5 个要素：
  1. 动作 / 姿态 / 表情（含 squash-and-stretch、anticipation、overshoot、follow-through）
  2. 镜头运动（推 / 拉 / 摇 / 倾 / 手持晃动 / 锁定 / 环绕）
  3. 空间位置（人物在哪、持有什么、地标在画面哪里）
  4. 音频线索（对白 / 音效 / 呼吸 / `silent`）
  5. 与下一秒或下一镜的交接
- **音频与对白轨**：本镜完整音频脚本，按时间顺序，独立于每秒指令。字段：
  - `模式` — 本镜是 `dialogue` 还是 `silent`（可与项目全局模式不同，如对白片里的静默镜）。
  - `对白` — 台词、说话人、语气、时间范围。**一镜只允许一个说话人。**
  - `口型` — 逐秒记录嘴部开合；说话人 `mouth-open`，同镜其他角色 `mouth-closed`，`silent` 镜全员 `mouth-closed`。
  - `音效` — 关键音效，按时间锚定。
  - `字幕` — 本镜要渲进画面的字幕文本（即台词本身，不加引号/书名号/括号）；`silent` 镜写 `none`。
  - `表演备注` — 每条对白对应的眼神与身体动作变化。

表格全局规则：

- 每镜必须通过 `连续性衔接` 列自然继承上一镜画面状态，并为下一镜铺垫。
- 每秒指令必须具体到可直接生成分镜面板；避免「继续移动」这类缺少身体/镜头/道具细节的模糊描述。
- 表演必须夸张弹性，符合 squash-and-stretch、anticipation、overshoot、follow-through、overlap、弧线、快速姿态变化和清晰喜剧剪影。
- 景别必须在特写 / 大特写与其他景别间交替；避免重复景别。
- 荷兰角构图为追逐、失衡、惊吓或闹剧节拍设计。
- 台词语言仅在用户明确要求时使用；否则用最小化非语言反应或把台词标记为待确认。
- 已离屏角色在 `退场人物状态` 至少记录 1 镜，连续 2 镜明确不在场后再移除。
- 对白句长与镜头规划绑定：**句长容量与拆镜阈值按 `h3-prompt-writing`「字幕与画面内文案」§3 执行**（超限就拆成相邻两镜、每镜一句短对白）。拆镜 = 本表改行/拆行 + Step 5.5 自检重跑。

选项卡：批准表格并进入自检（推荐）/ 调整镜头连续性 / 让动画更夸张 / 调整特写节奏 / 调整荷兰角设计。

## STEP 5.5：镜头表自检门（强制）

进入分镜前必须对已批准的镜头表跑硬性自检。任何一项不通过必须先修订表格再重跑。

九项必检：

1. **Hook 密度**：每镜都有 `Hook 类型`；每连续 3 镜至少 1 镜使用 `reveal` / `reversal` / `callback`；开场镜和收尾镜各带强 hook。
2. **单镜时长**：任何镜头不超过 15 秒（视频工作流单次生成上限）。节拍需要更长就拆镜。
3. **单镜角色数**：任何镜头不超过 3 个重要角色（有画面动作或对白的角色）。
4. **空间锚点继承**：含 2 镜以上的同场景，下一镜的 `固定地标` 与 `光位基线` 必须与上一镜一致，或含明确连续性备注（如 `door-frame 随镜头左环绕由右侧 1/3 移至中央`）。
5. **每秒指令覆盖**：从 `0s` 到镜尾每秒都有指令，每条含 5 个必填要素；允许亚秒节拍但不能留时间空隙。
6. **跨镜连续性**：逐行读 `连续性衔接` 列必须形成连续链——任何一镜都不能从与上一镜结束矛盾的状态起步。翻转眼神、人物位置、道具状态或光位的镜头必须明确标记（如 `HARD CUT — 时间跳 2h`）。
7. **音频模式与口型安全**：每镜 `模式` 与项目全局模式兼容；`dialogue` 镜有且只有一个说话人，同镜其他角色全程 `mouth-closed`；`silent` 镜无对白无字幕、全员 `mouth-closed`；字幕文本与对白文本逐字一致。
8. **转场帧洁净**：每个跨场景边界的**前一镜最后 0.5s 必须无对白无字幕**（否则它的末帧带烧录字幕，会被 Step 7 的转场镜继承）。不满足就把该镜的对白往前挪，或在镜尾补一个无声反应节拍。
9. **first-frame 资格**：每个标 `first-frame`（i2v 首帧串联）的镜，按上一镜 `人物位置` / `连续性衔接` 推断，**上一镜末帧画面必须已包含本镜全部在屏角色**。本镜若有任何角色不在上一镜末帧里（新登场 / 从画外进入）→ 该镜**禁止用 i2v**，必须改标 `ref`（参考绑定角色卡 + 场景卡）后重跑自检；角色入场镜不得计划为 `first-frame`。

九项全过后，在画布表格节点顶部加 `shot-table self-check: passed at <时间戳>` 戳，并出选项卡：批准自检并进入分镜（推荐）/ 查看自检详情 / 修订失败项 / 重新跑自检。

任何一项不通过就不进入 Step 6：返回 Step 5，列出失败行，修好并重跑自检通过后才能再次展示分镜批准选项卡。

## STEP 6：单文本分镜文档（默认）+ 铅笔分镜图（opt-in）

自检通过后先出分镜模式选项卡，再生成任何分镜产物：

- **单文本分镜文档（默认，推荐）** — 整片一份画布文本节点，所有分镜作为文档内章节。承载完整质控载荷，成本几乎为零，是 Step 7 的权威渲染参考。
- **单文本分镜文档 + 多宫格铅笔图（可视化模式，opt-in）** — 文本文档仍是权威产物，额外为每镜生成一张多宫格铅笔图供人眼审稿。成本更高，适合想在付视频成本前做一次视觉预演，或弹性表演 / 姿态剪影是高风险项的情况。

把选中的分镜模式记入项目简报，并在 Step 7 与重生成纪律里复用。

### 默认路径：单文本分镜文档

生成一个画布文本节点，命名 `<标题> text storyboards`（group `text storyboards`），一个文档包含所有分镜。

**文档头部块**：项目标题、画面比例、生成档位、音频模式、分镜模式、自检状态戳；一段目录列出每镜的 hook 与章节锚点（`S01`、`S02`…）。

**每镜章节结构**（每个 `##` 标题对应一镜，按镜头顺序，字段顺序固定）：

1. **镜头标题 & 时长** — 简短可读的标题 + `S<N> / <duration>s`。
2. **Hook 类型** — 受控词。
3. **场景 & 角色** — 精确场景卡名、精确在屏角色名（绑定到角色卡）。
4. **空间锚点卡**（强制，四子字段）：`固定地标` / `人物位置（机位视角）` / `退场人物状态` / `光位基线`。
5. **连续性**：`承接 S(N-1)` 一两句交代上一镜结束状态；`交接 S(N+1)` 一句铺好下一镜开场。
6. **双绑定** — `[char:角色名] [scene:场景名] [hook:类型] [audio_mode:dialogue|silent] [speaker:角色名|none]`。这些是分镜专用参考标记，**视频渲染时必须剥离**。
7. **每面板四象限内容**（按时间顺序，就是镜头表里的每秒指令原样保留）：
   - `时间码` — 如 `0–1s`。
   - `姿态 + 表情` — 具体身体姿态、剪影、关键持握、眼神、表情路径；弹性节拍明确写出 squash / stretch / anticipation / overshoot。这是最大块内容，也是视频模型读取的视觉节拍。
   - `镜头` — 景别、镜头运动、荷兰角备注。
   - `音频 + 锚点` — 音频线索（`对白: …` / `SFX: …` / `silent`）+ 空间锚点备注。
   - `表演备注` — 逐秒口型（`mouth-open: <说话人>` / `mouth-closed: all`）、表情路径、眼神与身体动作变化。
8. **布局规则**：3 秒镜 3 面板、4 秒镜 4 面板、5 秒镜 5 面板、6 秒镜 6 面板、7 秒及以上每秒 1 面板；亚秒关键节拍按需加迷你面板（如 `2.0–2.5s`），仅当该节拍是本镜核心 hook。面板必须覆盖整镜时长，首帧到尾帧无空隙。
9. **每面板绑定**：绑定表格行列出的精确角色卡（锁定外观、脸、发型、身材、服装、签名道具、身份）与场景卡（保留环境、道具、地标、运动路径、空间逻辑），角色名与表格一致。
10. **ASCII 布局块（推荐，零成本）**：每镜一张组合草图，让用户秒扫空间布局而不必渲染图。ASCII 仅供人看，视频模型读上面的结构化四象限内容。
11. **分镜专用标记**：关键节拍在时间码后加 `[BEAT]`；需要交接特定状态时加 `[HANDOFF → S04 opening]`。

每镜章节模板（复制粘贴骨架）：

```markdown
## S03 / 5s — 奶奶把苹果筐递给 Mia

- **Hook 类型**：reveal
- **场景 & 角色**：scene:kitchen | char:Mia, char:Grandma
- **空间锚点卡**：
  - 固定地标：door-frame（右侧 1/3）、kitchen-island（底部居中）
  - 人物位置：Mia（左，中景，面朝镜头）| Grandma（右，前景，面朝 Mia）
  - 退场人物状态：—
  - 光位基线：温暖顶光主光 + 右侧冷反光
- **承接 S02**：奶奶弯下腰从中岛拿起苹果筐
- **交接 S04**：Mia 接住筐转身，门铃响起
- **双绑定**：[char:Mia] [char:Grandma] [scene:kitchen] [hook:reveal] [audio_mode:dialogue] [speaker:Grandma]

### 每面板四象限内容

#### 0–1s
- 姿态 + 表情：奶奶弯腰双手持筐；Mia 左侧站姿，眼神好奇
- 镜头：locked medium shot, eye-level
- 音频 + 锚点：silent | Mia: 左中景 | basket: 底部居中
- 表演备注：mouth-closed: all [BEAT]

#### 1–2s
- 姿态 + 表情：奶奶手臂伸向 Mia，筐倾斜；Mia 双手前伸准备接
- 镜头：locked medium shot, eye-level
- 音频 + 锚点：对白（Grandma）:「拿好了。」| SFX: 竹筐窸窣 | anchor: door-frame 右侧 1/3
- 表演备注：mouth-open: Grandma；mouth-closed: Mia [HANDOFF → S04 opening]

### ASCII 布局
[0-1s]  Grandma (R, fg)        door-frame (R, bg)
        ——lifts basket——        Mia (L, mid)
        cam: locked | silent
```

所有章节写完后放到画布，直接进入 Step 7。默认模式下不调用任何图像生成。

### 按镜抽取（重点迭代模式）

单文档形态针对阅读和跨镜连续性优化。当用户标记某镜需要重点迭代（通常是 climax / 追逐 / 闹剧节拍）：

1. 新建画布文本节点 `<标题> S05 text storyboard (extracted)`（同组 `text storyboards`）。
2. 把文档中 `## S05` 章节完整内容移到新节点。
3. 文档中原章节替换为占位行：`> S05 — 已抽取到独立节点（见 <标题> S05 text storyboard (extracted)）`。
4. Step 7 渲染 S05 时从抽取节点读取；其他镜仍从文档读取。
5. **回填**：用户满意后把内容折叠回文档（占位换成最新内容），独立节点归档。

多镜抽取时各自独立成节点，文档里用占位追踪。

### Opt-in 路径：多宫格铅笔分镜图

仅在用户选了可视化模式时，额外为每镜用 `comfy_generate_image` 生成一张多宫格铅笔图（group `text storyboards`）。铅笔图仅供人眼审稿，**不作为视频渲染参考，不进 `ref_nodes`**（图内含文字与多个身体，违反参考图硬规则）。

每张铅笔图：

- 面板物理排版：3 秒镜 1×3 条；4 秒镜 2×2；5 秒镜 上 3 下 2；6 秒镜 2×3；7 秒以上 3 排均衡。每面板占相同画布面积。
- 每面板四象限：左上时间码；右上姿态 + 表情草图（最大区域）；左下镜头图标 + 运动箭头 + 荷兰角备注；右下音频线索与锚点备注。
- 面板按阅读顺序排布，不同镜头不合并到同一图。
- 纯黑白铅笔线稿：不上色、不带最终渲染光、不带精致 3D 渲染。
- 可含分镜专用标记：铅笔结构线、动作箭头、镜头路径图标、时间标记、镜头号与双绑定标签。

铅笔图失败回退阶梯（布局塌陷 / 标签糊掉 / 面板合并 / 角色走样）：
1. 第一次重试：更紧的提示重画同一镜，明确写上四象限布局与每面板内容规则。
2. 第二次重试：去掉右下象限文字（保留空白格），减少文字负载。
3. 第三次重试：面板数减 1（合并动作最弱的两秒），镜头图标简化为单箭头。
4. 同一镜连续 3 次失败：选项卡问用户——切色块分镜（灰块占位姿态）/ 放弃该镜铅笔图仅靠文本分镜推进 / 回 Step 5 把该镜拆成两段更短的镜头并重跑自检 / 手动提供参考图。

默认文本模式没有这套回退——文本分镜失败就直接回 Step 5 修订该行表格。

### 分镜批准

选项卡：批准分镜并渲染镜头视频（推荐）/ 抽取或回填某镜 / 重画选定铅笔分镜（仅可视化模式）/ 修复角色一致性 / 修复场景逻辑 / 修复镜头标记 / 修复音频与口型标记。

## STEP 7：逐镜视频生成

### 渲染前的门

分镜批准后，先确认渲染参数选项卡：

**生成档位**：沿用 Step 0 选择（推荐）/ 切 `fast` 先走通全片 / 升到 `balanced` 或 `quality` 出成片 / 本镜临时改档。**逐镜调用必须显式传 `tier=`**（`fast` / `balanced` / `quality`），不要依赖缺省——缺省是 `quality`，成本最高。分辨率由画布 `aspectRatio` + 档位自动推导（`fast` 长边 832、`balanced`/`quality` 长边 1344），不需要单独选分辨率；用户要单镜 hero 画质时才显式传 `width`/`height`。

**档位与能力可用性**：一个能力支持多档，**具体有哪些档、每档什么代价，以 `comfy_list_workflows` 为准**（不同能力可以不同，用户增删工作流后也会变）——不要假设档位数量或名称。请求了该能力没有的档会**显式报错并列出可用档位**（工具不会静默换档）。遇到这类报错就改请求可用档位，**不要原样重试同一请求**。

**档位与分辨率/耗时同源**：工具返回会带 `tier` / `implementation` / `resolution`，回复与交付清单里如实回报**实际用到的实现 id**（透明化；换工作流后不复述旧档位描述）。实测参考（16:9 · 124 帧 ≈ 5.17s，随硬件/驱动/模型版本浮动，只作量级参考）：ref2v `fast`(832×480) 24.6s ｜ `balanced`(1344×768) 166.3s ｜ `balanced` 带加速 136.3s ｜ `quality`(1344×768) 396.6s ｜ `quality` 带加速 311.2s；i2v `fast` 26.1s ｜ `balanced`(1344×768) 177.3s ｜ `balanced` 带加速 130.5s ｜ `quality` 394.8s ｜ `quality` 带加速 314.7s。画质：`balanced`(8 步) 帧锐度比 `quality`(20 步) 高约 13%；`fast` 档细节最弱、适合调构图 / 走位。

**工作流**：默认由能力注册表 `preferred` 决定，不出选项卡。仅当用户主动要求换模型时，先 `comfy_list_workflows` 核对能力，再出工作流选项卡，选定后用 `comfy_render` 显式传 `workflow`，并把选择记入项目简报。

### 参考绑定策略（逐镜按镜头表 `绑定` 字段执行）

> 以下所有逐镜调用都要显式带 `tier=`（Step 7 渲染前的门选定），不要依赖缺省。

- **起点镜 / 换场景镜**：`comfy_generate_video(tier=档位, ref_nodes=[说话人角色卡, 场景卡])` —— 走参考绑定路径（r2v）。r2v 只传 `ref_nodes`，**绝不带任何首/末帧**。
- **同场景续接镜**（如 S03→S04、S05→S06）—— i2v 首帧串联，两条硬规则：
  - **资格（不满足就禁止 i2v，必须改用 r2v）**：上一镜的**末帧画面必须已包含本镜全部在屏角色**。只要本镜有任何一个角色不在上一镜末帧里（新角色登场、角色从画外进入、角色此前已离屏），该镜**禁止用 i2v 首帧串联**，改为 `comfy_generate_video(tier=档位, ref_nodes=[本镜全部角色卡, 场景卡])` 走参考绑定（镜头表 `绑定` 列相应标 `ref`）。
  - **执行时不传 `ref_nodes`**：`comfy_generate_video(tier=档位, first_frame_node=刚抽出的末帧图片节点)` —— i2v 工作流（`video.image2video`）**没有参考图注入点**，传 `ref_nodes` 会被静默忽略（仅上传不接线，徒增误导）；身份与环境完全由末帧真实画面继承。操作顺序：先 `extract_frame(video_node=上一镜片段节点)` 抽末帧（默认 `frame_index=-1`），再以上面形式调用。
- **跨场景镜绝不带上一镜末帧**（跨场景的过渡交给下面的转场镜）。
- 角色卡可以传画布节点 id，也可以直接传资产 id（如 `character:luna`）复用跨会话锚点。
- 同一角色有多个着装状态卡时，按本镜状态选正确的那张。

### prompt 组装（逐镜）

按以下顺序组装：

1. **H3 结构化重写（委托 `h3-prompt-writing` skill，主路径）**：调用 skill 工具加载 `h3-prompt-writing`，按它的规范（官方 `base-en.txt` / `ref-en.txt` + `references/studio-mapping.md` 映射表）把本镜「分镜章节 + 镜头表 `参考锚点` / `音频与对白轨` 行」重写为 H3 结构化 prompt：
   - **参考绑定镜**（`ref_nodes`，无首末帧）→ **Ref2VA 六段式**：`subject_definitions` → `summary` → `retention_analysis` → `detailed_description` → `overall_soundscape` → `non_diegetic_music`；
   - **首末帧串联镜 / 转场镜**（`first_frame_node` / `last_frame_node`）→ **I2VA / FL2VA 三段式**：对齐指令（首行）+ `integrated_multimodal_description` + `overall_soundscape` + `non_diegetic_music`；
   - **条件启用**：仅当解析到的工作流 id 前缀为 `minimax-h3-` 时走本路径；其他工作流跳过，直接走 2 的自由格式组装（模型无关，不写死模型名）。
   - 交给重写前先剥离分镜专用标记：**双绑定标签**（`[char:…] [scene:…] [hook:…] [audio_mode:…] [speaker:…]`）与 `[BEAT]` / `[HANDOFF …]`——不能出现在渲染 prompt 里。
2. **自由格式兜底（仅非 H3 工作流）**：从单文本分镜文档对应章节（已抽取的镜从独立节点）取每面板四象限内容，逐秒展开成自然语言镜头描述。
3. **角色形态描述（铁律一，两条路径共用）**：凡在屏角色含非人形 / 非常规解剖形态，其形态描述一律按铁律一正向构造清单（整体形状词 → 比喻锚点 → 部位关系 → 唯一附肢 → 解剖总括句）写入重写素材或自由格式正文——角色卡节点描述里已有合规解剖清单时直接引用，正文禁否定堆叠与"可能长四肢"暗示。
4. **风格锁后缀**：全局视觉风格锁的关键词串（两条路径都追加）。
5. **字幕（dialogue 镜）——写法一律委托 `h3-prompt-writing`**：把镜头表 `字幕` 字段与对白原文交给它的「字幕与画面内文案（唯一权威版）」处理（H3 路径内嵌正文对白处、自由格式路径紧随对白句），片型侧**不追加任何末尾字幕指令、不复述四条限定词、不定档位 / 实现策略**。
   - 片型侧只落数据：`silent` 镜不加字幕、不写任何 `<d>`，负向尾句加 `no subtitle, no text anywhere`；`dialogue` 镜字幕文本与镜头表 `字幕` 字段逐字一致。
6. **负向意图**：不要分镜线稿、不要手绘草图质感、不要面板边框、不要标签水印、不要真人写实。

`length` 为 24fps 帧数（124 ≈ 5s），按镜头表时长换算。片段写入 group `shot clips`，标题带镜头号。

### 逐镜失败回退阶梯

0. **（仅 H3 结构化路径）先检查重写本身**：若本镜走了 `h3-prompt-writing` 结构化重写且质量倒退（字幕 / 口型 / 一致性 / 音频任一指标），先回退该镜为自由格式 prompt 重渲（见 h3-prompt-writing 适配节「失败回退」），再走下面的重试阶梯。**回退时 prompt 首行加 `[PROMPT_FALLBACK]` 标记**（质检门据此放行，否则会被 H3 结构化校验拦截）。
0.5 **prompt 方法论合规自检（任何路径重试前必做）**：本镜含非人形角色时，先自查 prompt 是否违反「铁律一」（否定堆叠 / 暗示可能长四肢）；含对白字幕时，字幕写法的合规性**按 `h3-prompt-writing`「字幕与画面内文案（唯一权威版）」核对**（本节不复述其条目）。不合规就先修 prompt 再渲，**禁止不改 prompt 直接重试同请求**。
1. **第一次重试**：强化 prompt——直接引用镜头表 `参考锚点` 块的地标与人物位置，缩短冗余措辞。
2. **第二次重试**：缩到 ≤6s，砍掉的秒拆成 Step 5 的新相邻行，重跑 Step 5.5 自检再重渲。
3. **第三次重试**：改档验证是 prompt 问题还是采样问题——字幕字准 / 漏烧类问题**升档**（`fast`/`balanced` → `quality`），**只是想省成本或排查链路才降档**（`quality` → `balanced`/`fast`，注意 i2v 无 `balanced`，会报错）；或简化动作、去掉一个道具、降低 hook 强度。（同档换实现的可行性按 `h3-prompt-writing`「字幕与画面内文案」§4 的口径取证后再说。）
4. **同一镜连续 3 次失败**：选项卡问用户——换工作流（先 `comfy_list_workflows` 核对能力）/ 放宽要求 / 跳过该镜并在下游标记 `placeholder: missing clip` / 手动提供参考视频。

不要重复提交未改动的同一请求。

### 逐镜门控（门 3：每镜一确认，禁止批量出镜）

正片**逐镜生成、逐镜确认**，不做「全部渲完再批量批准」：每渲完一个镜头，AI 先自检，再把该片段交人工确认；确认通过才进入下一镜生成。上一镜未批准，不推进下一镜。转场镜同样逐个走本门。

每镜渲染后的 **AI 自检**（渲染完立即执行，任一不过不弹确认卡）：

1. **与计划一致**：对照镜头表该行 + 分镜章节，核对景别、动作节拍、空间锚点（地标落位 / 人物位置 / 离屏方向）、光位。**关键帧抽样，不只看末帧**——按下面采样表用 `extract_frame` 抽取后用当前模型自身视觉逐帧核对（当前模型不支持图片输入时回退 `describe_image`）：
   - 每镜必抽 **首帧 / 中段帧（约 1/2 处）/ 末帧** 三帧；镜长 ≥5s 或动作密集镜按 ~1.5–2s 间距加抽，单镜上限 5–6 帧；
   - `dialogue` 镜在说话时间窗内加抽 1–2 帧查口型；带字幕镜抽说话窗帧核对字幕文字；
   - 转场镜**必抽中段帧**（实测：短 length + fast 档中段易糊 / 建筑形变）；
   - 末帧必抽，且同时充当下一镜 i2v 首帧素材（一帧两用）。抽出的检查帧归 `shot clips` 组作中间产物，终检不计入镜头数。
2. **人物一致性（对照角色卡）**：用第 1 项抽出的关键帧，把画面中每个角色对照**本镜绑定**的角色卡（画布节点 id / 资产 id）逐项核对——脸型、发型、身材、服装、签名道具、不可改特征无漂移；同一角色多状态卡时确认用的是**本镜正确状态卡**（如「穿宇航服」状态）；同镜多角色各自对照各自的卡；疑似帧单独加抽复核。不过 → 强化 prompt 直引角色卡外观锚点重渲（或先检查 ref / 首帧绑定是否绑错卡），重跑自检。
3. **口型与字幕（有对白的镜必查）**：`dialogue` 镜只有说话人动嘴、同镜他人闭嘴；**字幕文本与镜头表 `字幕` 字段逐字一致**、无引号书名号括号、无错字，且**无整段缺失**；`silent` 镜无字幕、全员闭嘴（用第 1 项关键帧抽样的说话窗 / 字幕帧核对）。**不过关 → 不弹批准卡**，弹处置选项让用户选：**重新生成本镜 / 升档重渲**（`fast`/`balanced` → `quality`，i2v 直接到 `quality`）。写法侧的问题按 `h3-prompt-writing`「字幕与画面内文案（唯一权威版）」核对，本门不复述其条目。
4. **无污染**：无分镜痕迹（面板边框 / 箭头 / 标签 / 时间标记 / 双绑定标签）、无参考图带出的文字水印与角色副本。
5. **音频**：AI 不能听音——把「对白清晰 / 音效与画面同步 / 无杂音幻听」列入确认卡，由人工听核；转场镜重点核对有无幻听人声。

失败处置：任一不过 → 走「逐镜失败回退阶梯」重渲本镜（强化 prompt / 缩时长 / 降档 / 简化动作）后重跑自检；**未过自检的片段不弹确认卡**。若片段与已批准的 `参考锚点` 漂移（门框落到错边、人物从错边离屏、光位翻转），用直接引用 `参考锚点` 块的强化提示重渲。

确认卡（每镜一次 `ask_user_question`）：批准本镜并生成下一镜（推荐）/ 重渲染本镜 / 升档重渲本镜（字幕字准类问题）/ 修复角色不一致 / 修复场景不一致 / 修复跨镜空间锚点漂移 / 查看自检详情。

### 用户修改与计划冲突的处理（权威链：镜头表 → 分镜 → 片段）

已批准镜头表 + 分镜文档是**计划权威**（分镜是 Step 7 渲染的权威参考）。用户在任何关口提出修改时，先归类再执行，**禁止静默改渲让片段与计划漂移**：

1. **计划内微调（行内重渲）**：修改不改变镜头表该行的景别 / 时长 / 动作节拍 / 锚点 / 音频与字幕（如「动作再夸张点」「这句演得更委屈」「门框别挡脸」）→ 直接强化 prompt 重渲本镜，走门 3 自检 + 确认，无需改表。
2. **偏离镜头表行（必须先落表）**：用户要求改变景别 / 时长 / hook / 台词字幕 / 说话人 / 锚点等本行计划内容、与已批准表格不一致 → **不得直接按口头要求重渲**；先把修改写进镜头表对应行（或拆行 / 新增行）→ 跑 **STEP 5.5 九项自检**（不过就继续改表）→ 同步更新分镜文档对应章节（已抽取的镜同步其独立节点）→ 再重渲受影响镜。
3. **改动连续性 / 交接的修改**：涉及角色离场、道具状态、光位、为下一镜铺的开场状态 → 除本行外沿 `连续性衔接` 链检查后续行（锚点继承 / 第 9 项 first-frame 资格 / 第 8 项转场帧洁净），必要时按「i2v 帧链连锁 / 锚点式重渲」处理下游。
4. **意图冲突时先澄清**：用户口头修改与已批准计划冲突且未明说改表 → 先出选项卡澄清（改表走自检 / 行内微调重渲 / 维持原计划），按用户选择执行；AI 不自行猜测吞掉冲突。
5. **修改全部落画布**：更新后的镜头表 / 分镜 / 片段为当前批准版本，旧版标记废弃，重跑 `video_concat` 与终检（遵守「重生成与最新资产纪律」）。

### 跨场景转场镜

所有正片片段**逐镜批准**完成后，为每一个**跨场景边界**生成一个转场镜。3D 动画短片不用交叉溶解（有 PPT 感），而是让镜头真的运动过去：

1. `extract_frame(video_node=前一镜片段, frame_index=-1)` → 前一镜末帧。
2. `extract_frame(video_node=后一镜片段, frame_index=0)` → 后一镜首帧。
3. `comfy_generate_video(tier=档位, first_frame_node=末帧节点, last_frame_node=首帧节点, length=…, prompt=过渡意图, group="shot clips", title="S03→S04 转场")` —— 首末帧串联，模型自己补出中间的运动，收尾精确落回后一镜首帧。
4. 转场镜作为**普通片段**参与 Step 8 的拼接顺序，插在两镜之间。

转场镜**逐个生成、逐个确认**（同门 3：渲染后 AI 自检抽**首 / 中 / 末**帧核对运镜与光变——中段必查防形变，确认无杂音幻听 → 人工确认 → 再生成下一条），不做批量。

转场 prompt 只写镜头运动与光线变化（如「镜头快速上摇掠过屋顶冲向天空，暖色黄昏光渐变为高空冷蓝光」），**不写角色动作、不写对白**，音频模式按 `silent` 处理。

三条实测约束，必须遵守：

- **避开带字幕的帧**（实测硬规则）。`dialogue` 镜的末帧上有烧录字幕，直接拿去当转场首帧，字幕会被原样带进转场镜开头。两个办法：① 镜头表把跨场景边界的前一镜设计成**最后 0.5s 无对白**，末帧天然干净；② 抽帧时往前挪，用 `frame_index=-12` 之类取字幕消失后的帧。首选 ①，它在流程层就把问题消掉了。
- **`length` 走 17k+5 网格**（5 / 22 / 39 / 56 / 73 / 90 / 107 / 124…），且模型训练区间是 **124–362 帧**。短于 124 属未测区，实测 `length=39` + fast 档的中段会糊、建筑有形变。转场镜建议至少 `length=56`，**成片一律用 `quality` 档重出**，fast 只用于验证链路。
- **分辨率必须与前后镜一致，否则拼接会失败**。转场镜显式传与正片相同的 `width`/`height`，并**与正片用同一档位**——`fast`（长边 832）与 `balanced`/`quality`（长边 1344）出的片段混在同一条成片里会因分辨率不一致而拼接失败。**跨档升档必须在生成前决定**（全片同一档），不要到拼接时才发现混档；已经混档的片段要先统一档位重出再拼。

同场景续接镜不需要转场镜——首帧串联本身已经连续，插转场反而暴露剪辑点。

抽出的末帧/首帧图片节点也归 `shot clips` 组，它们是中间产物，终检时不计入镜头数。转场镜自带模型生成的音频，终检时必须逐条听过，有杂音或幻听人声就重出。

### 片段收集（逐镜确认已在门 3 完成）

正片与转场镜全部**逐镜批准**后，按镜头表顺序放到画布（group `shot clips`）。不再设批量「批准片段」选项卡——每镜的人工确认已在生成当下（门 3）完成；整体复查需求留给 STEP 8 交付批准卡的「补做终检某一项 / 重渲染选定片段」选项。严禁在交付时静默混合修正版与未修正版片段。

## STEP 8：拼接、交付与终检

### 拼接全片

全部片段**逐镜批准（门 3）**后，用 `video_concat(nodes=[按镜头表顺序的片段节点 id，含转场镜], title="拼接成片", group="final delivery")` 拼成完整成片（含音轨）。后端由插件自动选择——本机有 ffmpeg 走 ffmpeg，没有就走 ComfyUI 纯节点链路，两者对本 Skill 透明。

拼接的三条限制，必须提前告知用户：

- **拼接本身只做硬切，没有溶解**。跨场景过渡由 Step 7 生成的转场镜承担——把转场镜按顺序放进 `nodes` 即可。如果没做转场镜，成片就是直切。
- **所有片段必须同分辨率**（同一档位出的片段天然满足）。`fast` 长边 832 与 `balanced`/`quality` 长边 1344 **不能混在同一条成片里**——混了就先统一档位重出。**跨档升档要在生成前决定**（全片同档），不要到拼接时才处理：`balanced` 与 `quality` 长边相同（1344），拼接不会失败，但**同一条片子里混不同实现会导致观感/像素漂移**，非必要不混。
- **无 BGM**：注册表当前没有 `audio.music` 工作流，插件不能生成配乐。片段自带的对白与音效会保留。

### 交付清单

在 group `final delivery` 写一个交付清单文本节点，包含：

- 拼接成片的节点 id 与媒体路径、总时长。
- 按镜头表顺序的片段清单（镜头号 → 画布节点 id → 媒体路径 → 时长）。
- 未落地项：需要人工补的溶解转场位置、BGM 建议（情绪弧、节奏、在对白与重要音效下 duck 的时间点）。

**终检清单**（逐条核对并写进交付节点）：

- 角色一致性：跨镜同一角色的脸、发型、身材、服装、签名道具无漂移；换装镜用的是正确状态卡。
- 场景连续性：对照 `参考锚点` 列逐镜验证每个地标是否落在表格说的位置；光位无意外翻转。
- 情绪锚点回收。
- 镜头意图清晰度；景别有交替，无重复景别堆叠。
- **口型硬卡**：每个 `dialogue` 镜只有一个说话人在动嘴，其他角色全程闭嘴；`silent` 镜全员闭嘴。
- **字幕正确**：字幕文本与镜头表 `字幕` 字段逐字一致，无错字、无引号书名号括号；`silent` 镜无字幕。
- 音频可听：对白清晰，音效与画面同步。
- **无分镜痕迹**：没有面板边框、铅笔线、箭头、标签、手写备注、时间标记、姿态残影，**也没有双绑定标签**（`[char:…] [scene:…] [shot:…] [dur:…] [hook:…]`）。
- **无参考图污染**：成片里没有从参考图带进来的文字/水印，也没有同一角色的多个副本（若出现，检查该镜用的参考图是否为单视图零文字）。
- 缺失或薄弱片段；任何可能需要重做的资产。

### 渠道交付（飞书 / TUI）

「画布」tab 只在 Web 可见；跑在 TUI / 飞书时用户看不到画布，交付阶段要把产物送达用户，而不是只写交付清单：

1. **ask 前自动送达**：飞书渠道下，插件会在每次 `ask_user_question` 执行前自动把画布中未送达的产物经 `send_file` 送达——角色卡/场景卡/逐镜片段/拼接成片等媒体直接发原文件；简报/大纲/镜头表/分镜等文本节点自动导出为 .pdf 一并送达（飞书可直接预览；本机无 PDF 工具时兜底 .html）。**发送的文件名取自节点标题**（如 主角卡.png、简报.pdf），所以给节点起有意义的标题（「S01 片段」而非「视频1」）。**不要手动调 `send_file`**，避免重复。群聊会先弹审批卡、再出选项卡，照常调用、由用户在飞书确认。
2. **文本同时进回复**：文本产物除 .pdf 文件外，把要点写进 ask 前的回复正文，飞书回复本身即可读。
3. 没有 `send_file`（Web / TUI）则产物已在画布/工作区，无需推送；TUI 用户按工具返回的 `absPath`（绝对路径）自行打开。
4. `send_file` 单文件默认上限 20 MiB：成片或长片段超限导致自动送达失败时改用 fast 档 / 更短镜头 / 分镜分开发，或提示用户到画布取。

选项卡：批准交付（推荐）/ 重渲染选定片段 / 升档重出全片（`balanced` / `quality`，全片同档）/ 补做终检某一项。

## 画布归组纪律

每生成一个耐用产物立刻上画布并归组（生成工具自动上画布的不重复写）。本 Skill 的分组词汇（已在 Step 0 通过 `groupOrder` 声明）：

`story planning`（简报 + 大纲）· `character cards` · `scene cards` · `shot table` · `text storyboards`（分镜文档 + 抽取节点 + 铅笔图）· `shot clips` · `final delivery`（交付清单 + 终检）

一轮生成产出 2 个或更多产物时立刻 `canvas_group_nodes` 归组并起清晰标题。顺序错乱时用 `canvas_reorder` 修正。

## 用户选项卡纪律

每个需要用户确认的地方都用 `ask_user_question` 选项卡，不允许用纯对话问题或散文代替。强制门：

- 查库后（库非空）：复用范围
- 任何产物之前：画面比例 / 总时长 / 音频模式 / 生成档位
- 项目简报后 · 故事大纲后 · 角色卡后 · 场景卡后
- 镜头表后（门 1：批准表格进入自检）
- 自检通过后（门 2：批准自检，并立即选分镜模式）
- 分镜后 · 渲染档位确认 · **每镜渲染后（门 3：AI 自检 + 人工确认，逐镜推进，不批量）** · 交付后
- 任何「同一镜连续 3 次失败」的求助点

默认推荐项放最前，始终允许用户自定义输入。用户说「继续」时按选了推荐项处理。

## 重生成与最新资产纪律

用户重做或修订任何产物时，下游步骤必须用最新批准的产物：

- 角色卡重做后，后续镜头表、分镜、片段必须按精确角色名引用新卡；旧卡节点在画布上明确标记为废弃。
- 场景卡重做后同理，并重新核对所有引用该场景的 `固定地标` 与 `光位基线`。
- 镜头表修订后，分镜（文档 + 抽取节点）与片段必须用新表，**Step 5.5 自检必须重跑**才能恢复分镜。
- 分镜某章节修订后，对应片段必须用新章节内容；已抽取的镜以独立节点为权威。
- 铅笔图重画不强制重渲视频（它不是渲染参考）。
- **片段重渲的 i2v 帧链连锁（铁律）**：任何镜重渲都会产生**新末帧**；所有以该镜旧末帧为 `first_frame_node` 的下游 i2v 镜（同场景续接镜 / 转场镜）链输入随之失效，**默认必须顺次重渲**——抽新镜末帧 → 换作下游镜 first_frame → 下游重渲 → 门 3 自检确认，逐级推进到链尾。r2v 镜不继承帧、**不参与连锁**（仅按 `连续性衔接` 做叙事核对，新结尾与下一镜开场矛盾才重渲）。示例：S1 r2v → S2 i2v → S3 i2v → S4 r2v，重渲 S2 ⇒ 必顺次重渲 S3（first_frame 换新 S2 末帧）；S1 末帧未变直接复用；S4 不重渲；S3→S4 若有转场镜（串联 S3 末 + S4 首）随新 S3 重渲。**禁止只重渲单镜而保留旧下游 i2v**（拼接处首帧对不上）。
- **锚点式重渲（例外，可免下游重渲）**：当重渲动机只在**中段**、结尾交接状态不变（下游镜开场仍与计划一致）时，不要把本镜作自由尾 i2v 重渲，而是双端锚定：`comfy_generate_video(tier=档位, first_frame_node=上游末帧, last_frame_node=下游镜真实首帧)`（下游首帧取 `extract_frame(下游镜, 0)` 或原链输入节点）——FL2VA 双端生成，本镜新末帧精确落回下游首帧，**下游 i2v 镜无需重渲**。仅当重渲要改变交接状态（新结尾与旧结尾不同）时才必须走顺次重渲。
- 片段重渲（含连锁）后，必须用新片段重跑 `video_concat`，交付清单与终检也随之更新。
- 换工作流重渲时，在项目简报记入新工作流，并重检该镜的参考绑定策略。

任何重做后：在下一条回复中标明重做产物为当前批准版本；后续调用一律用新节点 id；画布上同时存在多版本时先指明当前选用版本再继续；被替换的旧末帧 / 旧链输入节点一并标记过期，不再用作任何镜的 `first_frame_node`；不要在交付清单里静默混合新旧资产。

## 边界

单张图、简单修图、单段独立镜头、logo 设计、纯提示咨询不用本 Skill。音频模式只支持 `silent` 与 `dialogue-led`，**旁白主导不在范围**。不用于真人写实。
